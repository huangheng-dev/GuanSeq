# GuanSeq 0.1.0-alpha.1 预览版说明

> 发布日期：2026-08-28  
> 发布级别：开源 Alpha 预览  
> 许可证：Apache License 2.0

## 发布定位

这是 GuanSeq（贯序）的首个公开预览版本，用于开源评审、二次开发和受控试点准备。它证明当前源码可以通过统一门禁、从空 PostgreSQL 数据库启动，并完成已标记为“正式后端”的制造主闭环；它不是稳定生产版，也不证明任何工厂实例已经完成 OIDC、TLS、备份、观测、设备和业务验收。

## 已交付范围

- Next.js 工作台、Spring Boot Modulith 模块化单体、PostgreSQL 18 与 Flyway V1—V56。
- 236 条产品路径的统一成熟度标识：50 条正式后端、174 条 Mock、12 条规划。
- 销售订单、计划/MRP、采购与收货、生产执行、质量检验、库存、发货、基础收付款与成本利润的第一条纵向闭环。
- 销售退货、采购退货、移动扫码、受控标签、上架、库内调拨和盘点等反向物流与现场切片。
- 可替换的 Modbus TCP 和 MQTT 只读设备采集适配；不内置或强制指定 Broker。
- 非 root OCI 镜像、最小生产 Compose、配置预检、健康检查、备份与隔离恢复演练脚本。
- 前端、后端、源码/依赖/配置/密钥、镜像、SBOM 与浏览器主闭环发行门禁。
- PostgreSQL JDBC 42.7.13，包含 CVE-2026-54291 的 SCRAM 通道绑定降级修复。
- Netty 4.2.16.Final，包含 CVE-2026-59901 的压缩解码无限循环修复。
- Web 运行时镜像不携带构建阶段使用的 npm/npx 工具链，减少无关软件包和公开攻击面。

## 快速验证

发行工作流发布两个同版本 OCI 镜像：

- `ghcr.io/huangheng-dev/guanseq-web:0.1.0-alpha.1`
- `ghcr.io/huangheng-dev/guanseq-server:0.1.0-alpha.1`

每个 GitHub Release 同时附带两个 SPDX JSON SBOM 和包含镜像不可变摘要、源提交及文件校验和的发行清单。生产部署应优先固定清单中的镜像摘要，不使用 `latest`。

开发环境需要 Node.js 24.18、pnpm 11.16、Java 25 与 Docker：

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
cd guanseq-server
./mvnw verify
cd ..
pnpm e2e:install
pnpm e2e
```

生产式部署必须从仓库外注入受控环境文件，并使用真实 OIDC 与外部 HTTPS 入口：

```bash
pnpm production:preflight -- --env-file /etc/guanseq/production.env
docker compose --env-file /etc/guanseq/production.env -f compose.production.yaml build --pull
docker compose --env-file /etc/guanseq/production.env -f compose.production.yaml up -d --wait
```

完整步骤、回退和恢复边界见[生产部署与恢复运行手册](../生产部署与恢复运行手册.md)。

## 已知限制

- 174 条 Mock 路径只用于产品评审，不能保存正式业务事实；12 条规划路径尚未实现。
- 默认没有完整指标、分布式追踪、集中日志或高可用编排；安装者可接入现有平台。
- 生产 OIDC、TLS、异机备份、RPO/RTO、最小权限和真实业务验收必须由每个安装实例独立完成。
- Modbus/MQTT 仿真只证明软件适配器，不能替代真实设备、网络、安全、映射和容量验收。
- `0.x` 期间允许不兼容调整，不承诺长期支持窗口。

## 升级与反馈

数据库迁移只向前执行，不提供自动降级。升级前必须完成可恢复备份和隔离恢复演练；发生问题时按运行手册判断应用回退或前向修复，不得用旧备份覆盖已经产生的新业务写入。

缺陷、安全问题和功能建议分别通过仓库 Issue、[安全策略](../../SECURITY.md)和[贡献指南](../../CONTRIBUTING.md)反馈。
