# 业务切片：采购收货移动扫码闭环

> 适用阶段：阶段 C 现场移动作业增强  
> 工程状态：已闭环  
> 前置事实：已下达采购订单、采购收货、仓库/库位、来料检验与库存流水

## 目标与边界

```text
仓库收货员扫描采购单号
→ 扫描物料编码
→ 系统匹配当前租户已下达订单和唯一未收行
→ 录入数量、批号、仓库与库位
→ 后端重新校验权限、订单状态、订单行和未收数量
→ 复用正式采购收货用例过账
→ 免检物料进入合格库存；需检物料进入待检库存并生成 IQC
```

扫码是输入方式，不产生第二套采购、库存或质量事实。普通 USB/蓝牙扫码枪按键盘输入工作；首版也允许人工输入同一编码，便于开源用户在没有专用设备时开发和验收。

## 业务对象与所有权

| 对象 | 所有模块 | 核心事实 |
| --- | --- | --- |
| 采购订单及未收数量 | procurement | 扫描采购单号和物料编码只能匹配当前租户 `RELEASED` 订单的唯一未收行 |
| 采购收货单及来源 | procurement | 正式收货事实；`DESKTOP_FORM` 与 `MOBILE_SCAN` 区分操作入口 |
| 合格/待检库存和流水 | warehouse | 仍由既有采购收货公开服务过账，移动页面不得直接写库存 |
| 来料检验 | quality | 需检物料继续由既有收货用例生成 IQC，不在移动端伪造判定 |
| 弱网草稿 | 浏览器本机 | 只保存待提交输入和稳定请求编号，不是服务端业务事实 |

## 权限、不变量与恢复

- `WAREHOUSE_MANAGER`、`INVENTORY_CONTROLLER`、`PROCUREMENT_MANAGER`、`ADMIN` 可以提交收货；其他角色只能看到无权限状态，后端继续拒绝写入。
- 采购单号和物料编码去首尾空格并按大小写不敏感精确匹配，不做模糊猜测；找不到、已收完或不唯一时不得进入过账步骤。
- 收货数量必须大于零且不超过后端实时未收数量；仓库和库位必须启用且属于当前租户，库位必须属于所选仓库。
- 每次移动草稿生成稳定 `X-Request-Id`。网络中断、页面刷新或重复点击后使用同一请求编号重试，后端只形成一张收货单。
- 离线时仅在本机保存草稿并明确显示“未过账”；恢复网络后由用户重新确认提交。首版不做后台静默同步。
- 收货事件保留操作者、时间、请求编号、来源和行数；移动来源进入收货单快照，便于审计与统计。

## API 与完成定义

- 复用 `GET /api/v1/procurement/receipt-reference-data` 获取当前租户已下达订单、仓库、库位及后端写权限。
- 复用 `POST /api/v1/procurement/receipts` 完成正式过账；请求新增可选 `source`，只接受 `DESKTOP_FORM` 或 `MOBILE_SCAN`。
- Flyway `V50` 为收货来源字段事实来源；V51 统一采购退货后的补收数量约束，按“累计毛收货 - 累计已退货 ≤ 订购量”控制；OpenAPI 为 HTTP 契约事实来源。
- `/procurement/mobile-receiving` 通过 `src/services` 与同源 BFF 接入正式 API，覆盖空数据、无权限、扫码不匹配、校验失败、离线草稿、提交中、接口失败和幂等重试。
- PostgreSQL 集成测试、契约测试、前端测试、lint、类型检查、生产构建以及桌面/390px 浏览器闭环全部通过后，状态才能改为“已闭环”。

## 非目标

- 不接入专用 PDA SDK、摄像头识别库、打印机驱动、RFID、电子秤或供应商 ASN。
- 不实现离线数据库、后台自动同步、冲突自动合并或跨设备草稿共享。
- 不新建移动端专用采购单、库存表或质量表。
- 不把扫描成功等同于库存已过账；只有后端返回正式收货单才算完成。

## 交付证据

- 普通键盘式扫码枪或人工输入均可完成“采购单 → 物料 → 数量/批号/库位 → 正式收货”，未引入专用硬件 SDK。
- 刷新后草稿与稳定请求编号保持不变；离线状态只允许保留本机草稿，提交按钮明确锁定，不产生服务端收货事实。
- 浏览器通过真实 BFF/API/PostgreSQL 生成 `PR-20260827-000003`，数据库来源为 `MOBILE_SCAN`，同一请求编号仅形成一张收货单；到货台账可见该正式事实。
- 真实验收发现并修复退货后补收的旧数据库约束冲突；新增回归证明毛收货 7、已退货 2、净收货 5 的业务和数据库口径一致。
- 前端 lint、TypeScript、36 个测试文件/106 项测试和生产构建通过；后端 133/133 项测试通过、0 跳过，PostgreSQL 18.4 完整执行 V1—V51，Maven 生产打包通过。
- 390px 视口无横向溢出；干净浏览器会话在扫码页与到货台账均为 0 错误、0 警告。
