# 业务切片：设备点检、保养与维修闭环

> 文档状态：已完成
> 适用阶段：设备与智能能力（阶段 D 第二个纵向切片）
> 模块归属：equipment
> 迁移：V38
> 前置切片：设备台账与人工受控运行状态

## 0. 业务目标与非目标

本切片解决设备经理无法把计划作业、现场执行、异常转维修和维修验收串成同一证据链的问题。交付对象是当前工作区内的一次性点检任务、预防性保养任务和维修工单；每个动作都记录责任人、时间、原因、请求编号、前后状态和关联设备。

本切片不实现周期模板自动生成、备件库存领用、维修成本、外协维修、移动离线执行、图片附件、IoT 自动触发、点位采集、报警、OEE 或远程控制。周期规则和自动任务只有在一次性任务运行数据证明需要后再建设。

## 1. 业务对象与所有权

| 对象 | 所有者 | 说明 |
|---|---|---|
| 设备运维工单 | equipment | `INSPECTION`、`PREVENTIVE_MAINTENANCE`、`REPAIR` 三类计划与执行事实 |
| 运维工单事件 | equipment | 创建、开工、执行完成、送验、验收、驳回和取消的不可变证据 |
| 设备台账与当前状态 | equipment | 工单只关联同租户、同工作区设备，并在适用动作中原子更新设备状态 |
| 工作区与角色 | identity | equipment 只使用公开的当前工作区访问上下文 |

工单编号在租户内唯一，创建后不可修改。工单保存设备编码、名称和位置快照，避免台账后续变更破坏历史证据。

## 2. 状态机

### 2.1 点检与预防性保养

```text
PLANNED（已计划） -> IN_PROGRESS（执行中） -> COMPLETED（已完成）
PLANNED（已计划） -> CANCELLED（已取消）
```

- 点检完成必须提交 `PASS` 或 `FAIL` 结论和执行记录。
- 点检 `FAIL`：设备从 `IDLE/RUNNING` 转为 `DOWN`；若不存在未关闭维修工单，自动创建一张 `REPAIR` 工单。
- 保养开工：设备必须为 `IDLE` 或 `DOWN`，原子转为 `MAINTENANCE`。
- 保养 `PASS`：设备回到 `IDLE`；保养 `FAIL`：设备转为 `DOWN` 并自动创建维修工单。

### 2.2 维修工单

```text
PLANNED -> IN_PROGRESS -> WAITING_ACCEPTANCE -> COMPLETED
   |              ^               |
   └-> CANCELLED  └--- REJECT ----┘
```

- 维修开工要求设备处于 `DOWN`，并原子转为 `MAINTENANCE`。
- 维修人员提交完工记录后进入 `WAITING_ACCEPTANCE`，设备仍为 `MAINTENANCE`。
- 验收通过后设备回到 `IDLE`；验收驳回后工单回到 `IN_PROGRESS`，设备继续为 `MAINTENANCE`。
- 只有 `PLANNED` 工单可以取消；取消维修工单不会自动恢复故障设备，必须重新建单或保留人工处置证据。

## 3. 入口与关联规则

1. 从点检、保养或维修页面可以为当前工作区设备创建对应任务。
2. `REPORT_BREAKDOWN` 从设备台账提交时，设备转为 `DOWN` 并在同一事务自动创建维修工单。
3. 原设备台账的 `START_MAINTENANCE`、`COMPLETE_MAINTENANCE` 公共动作保留兼容入口但不再执行，返回 409 并提示从运维工单推进，防止绕过验收。
4. 同一设备同一时刻只能有一张执行中或待验收的保养/维修工单。
5. 已停用设备不能创建或执行运维工单；运行中设备只能执行点检，不能开始保养或维修。

## 4. 权限与数据范围

| 操作 | 允许角色 |
|---|---|
| 查询列表与详情 | 当前工作区已认证用户 |
| 创建、开工、执行、送验、验收、驳回、取消 | `MAINTENANCE_MANAGER`、`PRODUCTION_MANAGER`、`ADMIN` |

前端隐藏按钮只用于交互提示。后端按当前租户和工作区限定设备与工单，跨工作区、跨租户对象按不存在处理。

## 5. 并发、审计与恢复

- 工单和设备分别使用 `@Version` 乐观锁；涉及设备状态的动作同时校验工单期望版本和设备期望版本。
- 工单事件记录 actor、action、from/to status、reason、request_id、outcome、details 和 occurred_at。
- 自动创建维修工单、设备状态变更和来源工单完成在同一事务提交，任何一步失败整体回滚。
- 并发修改、重复活动干预、非法流转返回 409；业务前置条件不满足返回 422。
- 失败点检或保养已经生成未关闭维修工单时复用该工单，不重复建单。

## 6. API 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/equipment/work-orders` | 当前工作区分页查询，支持类型、状态和关键字筛选 |
| GET | `/api/v1/equipment/work-orders/{id}` | 工单、设备快照、当前设备版本和事件详情 |
| POST | `/api/v1/equipment/work-orders` | 创建一次性点检、保养或维修工单 |
| POST | `/api/v1/equipment/work-orders/{id}/actions` | 开工、完成、送验、验收、驳回或取消 |

## 7. 前端入口

- `/equipment/inspections`：点检计划与执行。
- `/equipment/maintenance`：预防性保养计划与执行。
- `/equipment/work-orders`：故障报修、维修过程与验收。
- 数据统一经 `src/services` 和同源 BFF；页面覆盖加载、空数据、无权限、校验失败、接口失败、提交中和并发冲突。
- 页面明确标注“人工执行记录 / 自动采集未接入”，不展示伪实时数据。

## 8. 验收条件

1. 未认证请求返回 401，跨工作区或跨租户详情返回 404。
2. 无维护权限用户可查询但写操作返回 403。
3. 创建校验设备范围、停用状态、计划时间和必填责任信息。
4. 工单过期版本或设备过期版本返回 409，不发生部分状态更新。
5. 点检失败和保养失败会原子生成维修工单并把设备置为 `DOWN`。
6. 维修工单必须经过开工、提交验收和验收通过才能使设备回到 `IDLE`。
7. 验收驳回恢复到执行中，保留原因且设备继续处于 `MAINTENANCE`。
8. 设备台账直接开始/完成维修被拒绝，不能绕过工单证据链。
9. 每个动作在详情中可追溯操作者、原因、请求编号、时间、结论与关联来源。
10. V38、OpenAPI、后端测试、前端契约测试、lint、类型检查、生产构建和关键浏览器流程全部通过。
