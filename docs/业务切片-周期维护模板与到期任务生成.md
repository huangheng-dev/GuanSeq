# 业务切片：周期维护模板、到期任务生成与逾期证据

> 状态：已实现
> 适用阶段：设备与智能能力（阶段 D 第四个纵向切片）
> 完成日期：2026-08-25
> 前置切片：设备台账与运行状态、设备点检保养与维修闭环

## 1. 业务目标

本切片把重复发生的点检和预防性保养从一次性人工建单，推进为受控周期模板。设备经理先定义适用设备、周期、提前生成天数、责任人和作业窗口，再由有权限人员确认业务截止日并触发生成。生成结果、复用结果和跳过原因全部留痕。

首版不引入独立调度服务，也不把人工触发描述成后台自动生成。真实定时调度只有在运行频率、补偿策略、通知要求和运维责任明确后才进入后续切片。

## 2. 事实所有权

| 事实 | 所属模块 | 说明 |
|---|---|---|
| 周期维护模板 | equipment | 点检/保养类型、设备快照、周期、提前期、责任人与下次到期日 |
| 模板不可变事件 | equipment | 创建、启用、停用的操作者、原因、请求编号、前后状态与时间 |
| 生成批次与明细 | equipment | 截止日期、生成/已存在/跳过结果及关联工单 |
| 运维工单 | equipment | 生成后的执行、结论和验收事实，继续沿用 V38 工单状态机 |
| 设备当前状态 | equipment | 停用设备跳过生成，其他设备状态不阻止建立未来任务 |

模板保存设备编码、名称和位置快照，避免后续台账修改破坏历史责任证据。其他模块不得直接修改 equipment 表。

## 3. 业务规则

### 3.1 模板

- 只支持 `INSPECTION` 与 `PREVENTIVE_MAINTENANCE`，不把故障维修定义为周期任务。
- 模板编码在租户内唯一；创建请求按租户与请求编号幂等。
- 周期为 1–3650 天，提前期为 0–365 天；计划开始时间不得晚于要求完成时间。
- 已停用设备不能建立模板；创建时校验设备期望版本和当前工作区归属。
- 周期、提前期、首次到期日等节拍事实创建后不静默改写。需要调整节拍时，停用旧模板并创建新模板。
- 模板仅支持 `ACTIVE ↔ INACTIVE`，动作携带期望版本、原因和请求编号。停用后不再生成新工单，已经生成的工单与逾期责任不受影响。

### 3.2 到期生成

- 生成条件为 `nextDueDate - leadDays <= asOfDate`，业务日期按 `Asia/Shanghai` 解释。
- 每次生成锁定当前工作区活动模板，单批最多处理 500 个到期实例；剩余到期数继续在页面暴露，不会被误报为全部完成。
- 同一请求编号返回同一生成批次；数据库同时以“租户 + 模板 + 到期日”约束工单唯一，跨请求重试也不会重复建单。
- 成功生成后，模板的 `nextDueDate` 按周期推进；生成工单保存 `sourceType=MAINTENANCE_PLAN`、模板 ID 和来源到期日。
- 设备已停用时记录 `SKIPPED_INACTIVE_ASSET`，不推进模板到期日；已经存在时记录 `ALREADY_EXISTS`；新建时记录 `GENERATED`。
- 批次保存截止日期、原因、操作人、请求编号、开始/完成时间和三类数量，明细保存每个模板到期日的结果与工单关联。

### 3.3 逾期证据

- 周期工单要求完成时间早于当前时间，且状态不是 `COMPLETED` 或 `CANCELLED` 时计为逾期。
- 模板详情返回逾期工单号；页面总风险统计包含活动和已停用模板留下的未关闭逾期工单。
- 逾期仅作为可核验风险证据，不在本切片自动催办、升级或修改工单状态。

## 4. 权限与并发

- 当前工作区已认证成员可读。
- `MAINTENANCE_MANAGER`、`PRODUCTION_MANAGER`、`ADMIN` 可以创建、启停和生成；后端授权是唯一可信边界。
- 跨租户或跨工作区对象按不存在处理。
- 模板启停使用乐观锁；生成用例使用悲观写锁串行推进活动模板，并由数据库唯一约束承担最终幂等边界。
- 所有关键动作具备操作人、时间、原因、来源与请求编号。

## 5. API 与数据库

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/equipment/maintenance-plans` | 分页查询模板、活动/应生成/逾期指标和最近批次 |
| GET | `/api/v1/equipment/maintenance-plans/{id}` | 查询模板、逾期工单与不可变事件 |
| POST | `/api/v1/equipment/maintenance-plans` | 建立并启用周期模板 |
| POST | `/api/v1/equipment/maintenance-plans/{id}/actions` | 启用或停用模板 |
| POST | `/api/v1/equipment/maintenance-plans/generate` | 按业务截止日人工触发幂等生成 |

V40 新增 `equipment.maintenance_plans`、`maintenance_plan_events`、`maintenance_generation_runs` 和 `maintenance_generation_items`，并为运维工单增加来源模板与到期日。Flyway 迁移和 OpenAPI 契约是事实来源。

## 6. 前端交付

- `/equipment/maintenance` 在一次性保养工单之上增加“到期任务生成控制”。
- 提供活动模板、当前应生成、逾期未关闭、最近批次四项指标。
- 支持模板搜索、新建、详情、启停、人工截止日生成和批次反馈。
- 工单列表明确显示“周期模板 · 到期 YYYY-MM-DD”来源；页面持续标注“后台调度未接入”。
- 覆盖加载、空数据、无权限、校验失败、接口失败、并发冲突和幂等重试等适用状态。

## 7. 验收条件

1. 合法模板可以创建，非法设备、时间、节拍、角色和跨工作区访问被拒绝。
2. 到期模板生成真实点检或保养工单，并推进下次到期日。
3. 同一请求重试返回原批次，不同请求重复覆盖同一模板到期日也不新增工单。
4. 停用设备被跳过且不推进到期日；停用模板不再生成新实例。
5. 已生成工单保留模板与到期来源，未关闭逾期在模板详情和总指标中可追溯。
6. 模板启停校验期望版本并记录不可变事件。
7. Flyway、OpenAPI、模块边界、集成测试、前端契约测试、lint、类型检查、生产构建和真实浏览器流程全部通过。
