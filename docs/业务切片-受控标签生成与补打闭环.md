# 业务切片：受控标签生成与补打闭环

> 状态：已完成（2026-08-27）

## 目标

为既有工序任务、当前认证人员和库存余额生成稳定、可扫描的标签，并保留首次生成与补打的不可变责任证据。标签只投影原业务对象，不成为第二套工序、人员或库存主数据。

## 对象与所有权

| 对象 | 事实所有者 | 标签模块使用方式 |
|---|---|---|
| 工序任务 | production | 读取任务号、工序、生产订单与版本，生成 `OT:<任务号>` |
| 当前人员 | identity | 只允许当前认证人生成本人标签，生成 `EMP:<username>` |
| 库存余额 | warehouse | 读取余额、物料、仓库、库位、批次、质量与版本，生成 `STOCK:<余额 UUID>` |
| 打印准备请求 | labeling | 保存对象快照、模板版本、份数、模式、原因、责任人、请求编号和时间 |

## 状态与不变量

```text
尚无打印记录 → INITIAL → PREPARED
已有打印记录 → REPRINT（原因必填）→ PREPARED
```

- `PREPARED` 只表示已生成浏览器可打印凭证，不表示打印机已经成功出纸。
- 同一请求编号只形成一条打印准备事实；重复请求返回原结果。
- 首次生成后再次使用 `INITIAL` 必须被拒绝；从未生成的对象不能直接补打。
- 提交时校验原对象版本，防止用过期页面生成错误标签。
- 工序标签由生产角色准备，库存标签由仓储角色准备；人员标签只允许受控现场角色生成本人标签。
- 内置模板首版固定为 `OT-V1`、`EMP-V1`、`STOCK-V1`，不在本切片开放任意模板脚本。

## 非目标

- 不接入打印机厂商 SDK、云打印服务、后台打印队列或专用 PDA。
- 不声称浏览器打印动作等于物理打印成功，不采集打印机硬件回执。
- 不允许输入任意条码内容，不允许替他人生成身份标签，不允许标签反向修改主数据。

## 验收条件

- 覆盖首次生成、重复首次冲突、补打原因、请求幂等、对象版本冲突、越权和跨租户。
- OpenAPI、Flyway、后端、BFF、前端契约一致。
- 页面覆盖加载、空数据、无权限、失败、提交中、冲突和打印凭证状态。
- 通过 lint、类型检查、前后端测试、生产构建、真实 PostgreSQL 迁移及桌面/390px 浏览器闭环。

## 实现结果

- V54 新增 `labeling.print_requests` 不可变打印准备事实和租户内请求编号幂等约束；标签模块只保存原对象快照，不拥有或修改生产、身份和库存主数据。
- OpenAPI 已提供参考对象、打印准备分页和首次生成/补打接口；后端按对象类型调用 production、identity、warehouse 的公开读取接口，不跨模块访问表或基础设施实现。
- `/production/mobile-operations/label-reprint` 已从 Mock 替换为正式服务，支持工序任务、本人身份和库存余额三类受控对象、Code 128B 条码、模板版本、1—10 份打印凭证、浏览器打印及不可变历史证据。
- 服务端校验标签对象版本、角色、租户、本人身份、首次唯一性、补打前置记录、至少 4 字符原因、1—10 份范围和 Code 128B 字符边界；稳定 `X-Request-Id` 重试只返回原事实。
- 页面明确区分 `PREPARED` 与物理出纸成功；打印机厂商 SDK、后台队列和硬件回执仍为未接入，不影响用户未来自行选择浏览器、驱动或打印集成适配器。
