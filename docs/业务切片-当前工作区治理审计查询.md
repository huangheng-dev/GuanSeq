# 业务切片：当前工作区治理审计查询

> 状态：已完成  
> 日期：2026-08-28  
> 正式路径：`/settings/audit`

## 1. 目标与事实边界

本切片让当前工作区管理员能够追溯身份、成员、角色、组织与工作区治理操作。唯一事实来源是 `identity.audit_events`；页面不读取 Mock，也不让浏览器直连数据库。

本页不是跨模块日志中心。销售、采购、生产、质量、库存和财务事件继续由各自模块拥有，并在对应业务单据详情中形成责任链。identity 模块不得为了“统一入口”直接读取其他模块的事件表；以后若真实审计需求证明需要跨模块查询，应通过各模块公开的只读投影或经 ADR 批准的审计投影实现。

## 2. 权限、范围与数据所有权

- 后端权限：`IDENTITY_AUDIT_READ`，当前仅 `ADMIN` 具备。
- 数据范围：只允许当前认证用户当前工作区的 `workspace_id`，客户端不能指定工作区。
- 查询窗口：默认最近 30 天，单次最长 90 天；开始时间晚于结束时间或超过窗口返回 `422`。
- 查询操作只读，不新增审计事件，避免“查询审计又生成审计”的递归噪声。
- 操作人通过当前租户用户表批量解析；没有登录主体的系统事件明确显示为“系统”。
- 本切片没有状态机、乐观锁或幂等写入，因为没有业务事实写操作。

## 3. 正式契约

`GET /api/v1/identity/audit-events` 支持：

- `page`、`size` 服务端分页，单页最多 100 条；
- `eventType`、`objectType`、`actorId` 精确筛选；
- `query` 按请求编号或对象编号模糊查询；
- `occurredFrom`、`occurredTo` 按 ISO-8601 时间筛选；
- 返回当前工作区信息、范围说明、分页事件、事件/对象/操作人筛选选项。

响应按 `occurredAt DESC, id DESC` 稳定排序。OpenAPI 是接口事实来源；V58 只为既有 `identity.audit_events` 增加当前工作区、时间、事件、对象和请求编号查询索引，没有引入新表或新基础设施。

## 4. 页面行为

- 首屏由服务端读取正式 API，后端不可用或无权限时失败关闭，不回退为 Mock。
- 支持事件、对象、操作人、请求/对象编号和日期范围组合查询、刷新、重置及服务端分页。
- 行详情抽屉展示审计编号、动作、对象、责任人、请求编号、时间和结构化附加证据。
- 覆盖加载、空结果、无权限、参数校验失败、接口失败和恢复重试。
- 不提供伪导出、删除、编辑或归档按钮；导出与归档只有在真实合规需求、权限和保留策略确定后再建设。
