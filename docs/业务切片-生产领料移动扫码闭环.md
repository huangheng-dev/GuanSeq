# 业务切片：生产领料移动扫码闭环

> 适用阶段：阶段 C 现场移动作业增强  
> 工程状态：已闭环（2026-08-27）  
> 前置事实：已生成且处于 `DRAFT`/`PARTIAL` 的生产领料单、BOM 组件需求、合格库存余额与不可变库存流水

## 目标与边界

```text
仓库发料员扫描生产领料单号
→ 扫描组件物料编码
→ 扫描库存余额标签或批号
→ 系统匹配同租户、同仓库、同组件的唯一可用批次
→ 录入本次发料数量
→ 后端重新校验角色、领料单状态、BOM 行、剩余需求、库存质量/批次/版本和可用量
→ 复用正式生产领料与仓库发料用例过账
→ 返回领料单状态、库存流水、库位、批号、来源和请求编号
```

扫码只是输入和定位方式，不创建移动端专用领料单、库存账或成本事实。普通 USB/蓝牙扫码枪按键盘输入工作；没有专用设备时允许人工输入同一编码完成开发和验收。

## 业务对象与所有权

| 对象 | 所有模块 | 核心事实 |
| --- | --- | --- |
| 生产领料单及组件需求 | production | 只有 `DRAFT`/`PARTIAL` 且仍有可领数量的行可以进入扫码发料 |
| 合格库存余额、库位、批号和版本 | warehouse | 扫描结果必须精确指向当前租户、领料仓库和组件物料的可用余额 |
| 发料库存流水 | warehouse | 仍由仓库公开服务原子扣减并生成不可变 `ISSUE` 流水 |
| 领料动作与来源证据 | production | 记录操作者、时间、请求编号、`DESKTOP_FORM`/`MOBILE_SCAN` 来源及逐笔库存流水 |
| 弱网草稿 | 浏览器本机 | 只保存扫描输入、数量、备注和稳定请求编号，不是服务端发料事实 |

## 状态、权限与不变量

- `PRODUCTION_MANAGER`、`WAREHOUSE_MANAGER`、`INVENTORY_CONTROLLER`、`ADMIN` 可以正式发料；其他角色看到无权限状态，后端写入继续返回 403。
- 领料单号和组件编码去首尾空格、大小写不敏感精确匹配；库存标签支持 `STOCK:<余额 UUID>`，批号支持 `LOT:<批号>`。仅扫描批号时必须在当前仓库和组件下唯一，否则要求扫描余额标签，不做模糊猜测。
- 扫描库存必须为 `AVAILABLE`、属于领料单仓库和组件物料，且可用数量大于零；库存余额版本变化、冻结、占用、批次耗尽或跨仓/跨物料均拒绝过账。
- 发料数量必须大于零，同时不超过领料行实时可领数量和扫描余额实时可用数量；整笔动作成功或整体回滚。
- 每个移动草稿生成稳定 `X-Request-Id`。网络中断、刷新或重复点击使用同一请求编号重试，后端只形成一次领料动作和对应库存流水。
- 离线只保存本机草稿并明确标记“未过账”；恢复网络后由用户重新确认，不后台静默同步。

## 数据、API 与完成定义

- 复用 `GET /api/v1/production/material-issues` 和 `GET /api/v1/production/material-issue-reference-data` 获取开放领料单、写权限与可扫描库存余额。
- 复用 `POST /api/v1/production/material-issues/{id}/actions` 正式发料；请求行可选指定 `stockBalanceId` 与 `expectedStockVersion`，旧桌面表单不指定时继续使用既有自动拣取规则。
- Flyway 新迁移记录领料动作和库存关联证据的操作来源及批号；OpenAPI 是 HTTP 契约事实来源。
- `/production/mobile-operations/material-scan` 通过 `src/services` 和同源 BFF 接入正式 API，覆盖加载、空数据、无权限、扫码不匹配、批号歧义、校验失败、库存版本冲突、接口失败、离线草稿、提交中和幂等重试。
- PostgreSQL 集成测试、契约测试、前端测试、lint、类型检查、生产构建以及桌面/390px 浏览器和数据库证据全部通过后，状态才改为“已闭环”。

## 非目标

- 不接入专用 PDA SDK、摄像头识别库、RFID、电子秤、标签打印机或自动输送设备。
- 不实现离线数据库、后台自动同步、跨设备草稿、冲突自动合并、替代料或超领审批。
- 不改变桌面端现有自动批次拣取；只有移动扫码请求显式指定库存余额时才执行精确批次发料。
- 不把扫描成功或本机草稿显示成已发料；只有后端返回正式领料单和库存流水才算完成。
