# 业务切片：采购订单、提前期与计划接收

## 目标

把采购订单从通用前端占位页推进为受控业务事实，并让 MRP 通过采购模块公开接口读取“已下达且未收齐”的计划接收。该切片同时落地物料级提前期，仍不生成净需求建议，也不冒充生产订单或到货收货已经完成。

## 业务对象与所有权

| 对象 | 所有模块 | 说明 |
|---|---|---|
| 供应商 | 采购 | 当前切片提供启用供应商引用事实，后续供应商维护独立推进 |
| 采购订单与明细 | 采购 | 保存供应商、物料、数量、价格、到货承诺、收货进度和状态 |
| 物料提前期 | 计划 | 当前只维护自然日提前期，不预置未经业务证明的其他参数 |
| MRP 计划接收快照 | 计划 | 从采购公开接口冻结，来源订单后续变化不改写历史记录 |

采购模块不得读取计划内部表；计划模块不得直接读取采购表。跨模块只使用 `ScheduledReceiptProvider`。

## 状态与规则

采购订单状态：`DRAFT → PENDING_APPROVAL → APPROVED → RELEASED`，待审核订单可 `REJECTED`，已驳回订单编辑后回到草稿。

- 草稿或已驳回订单允许编辑；审核后禁止改写业务内容。
- 只有采购、计划负责人或管理员可以审核、驳回和下达。
- 驳回必须填写原因；下达前必须存在供应商承诺到货日期。
- 当前订单只允许采购或委外物料，自制物料不得直接采购。
- 同一物料在同一订单中不得重复。
- 计划接收只包含 `RELEASED`、承诺日期不晚于本次 MRP 期间结束、且 `ordered_quantity > received_quantity` 的明细。
- 零在途是采购物料的合法事实，不产生“计划接收缺失”异常。
- 自制物料在生产订单接收未接入前，继续产生物料级 `SCHEDULED_RECEIPTS_UNAVAILABLE` 阻断。
- 未配置提前期的物料产生 `LEAD_TIME_UNAVAILABLE`；已配置物料不再产生该阻断。

## 数据与 API

Flyway：

- `V13__create_procurement_order_model.sql`
- `V14__create_material_planning_parameters.sql`

主要接口：

- `GET/POST /api/v1/procurement/orders`
- `GET/PUT /api/v1/procurement/orders/{id}`
- `POST /api/v1/procurement/orders/{id}/actions`
- `GET /api/v1/procurement/order-reference-data`
- `GET /api/v1/planning/material-parameters`
- `PUT /api/v1/planning/material-parameters/{materialId}`

所有写入使用后端权限校验、乐观锁、请求编号和审计事件。OpenAPI 是外部契约事实来源。

## 前端验收

- `/procurement/orders` 展示真实采购订单、供应商、到货承诺、明细和收货/在途数量，支持创建、编辑、提交、审核、驳回和下达。
- `/planning/parameters` 展示当前租户启用物料及提前期，允许受权用户修改并处理并发冲突。
- `/planning/mrp/runs` 展示采购计划接收快照，并继续如实展示尚未接入的生产计划接收阻断。
- 页面数据只通过 `src/services` 和 BFF Route Handler 访问后端，不直接读取静态 JSON。
