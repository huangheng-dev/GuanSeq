# 业务切片：车间工序执行

> 状态：已实现并通过自动化验证  
> 领域归属：生产执行（`production` 模块）  
> 对应页面：`/production/work-orders/operations`

## 目标

把已下达生产订单的工艺路线固定为车间可执行的工序任务，支持班组长和操作人按工序开工、记录完工数量和责任证据；所有工序完成后，生产订单才允许提交现有订单级完工报工，从而把“计划订单”推进到“车间执行 → 报工检验 → 成品入库”的真实闭环。

本切片先支持订单级工序快照、逐序开工/完工和审计追溯，不做设备派工、班组产能、扫码报工、工序质检独立判定、工序外协、返工返修分支或工艺版本变更后的在制迁移。

## 业务对象与所有权

| 对象 | 所有模块 | 说明 |
|---|---|---|
| 工序任务 | production | 生产订单下达时从产品模块已发布工艺路线复制的不可变执行快照 |
| 工序事件 | production | 开工、完工动作的操作者、时间、请求号和数量证据 |
| 工艺路线引用 | product | 产品模块只提供计划开工日有效的已发布路线，生产模块保存快照，不直接依赖可变路线 |

## 状态与规则

工序任务状态：`PENDING → IN_PROGRESS → COMPLETED`。

- 只有 `RELEASED` 或 `IN_PROGRESS` 生产订单下的工序任务可以操作；首道工序开工时自动把生产订单从 `RELEASED` 转入 `IN_PROGRESS`。
- 生产订单下达时必须存在计划开工日已生效工艺路线，并逐道工序生成任务；同一订单只能生成一组工序任务。
- 工序按路线顺序号执行，但本切片不强制上道工序完成后才能开始下一道，避免把串行工艺假设写死到数据层。
- 开工要求任务为 `PENDING`，记录班次、操作人和开始时间。
- 完工要求任务为 `IN_PROGRESS`，完工数量必须大于 0 且不能超过生产订单计划数量，记录班次、操作人、数量和备注。
- 开工和完工按 `X-Request-Id` 幂等，重复请求稳定返回已保存结果。
- 生产报工前，该订单所有工序任务必须为 `COMPLETED`；否则拒绝创建完工报工。
- 取消生产订单时，本切片不新增级联取消逻辑；当前只允许草稿或未开工订单取消，因此尚未生成在制工序任务。

## 数据与 API

Flyway：

- `V20__create_production_operation_tasks.sql`

主要接口：

- `GET /api/v1/production/operation-tasks`
- `GET /api/v1/production/operation-tasks/{id}`
- `POST /api/v1/production/operation-tasks/{id}/actions`
- `GET /api/v1/production/orders/{id}/operation-tasks`（详情页按单查询）

产品模块新增公开引用：

- `RoutingReferenceProvider.findEffectiveRouting(...)`：返回路线编号、版本、工序顺序、工作中心、标准工时和检验标记。

## 前端验收

- `/production/work-orders/operations` 展示真实工序任务，支持按状态筛选和关键字搜索。
- 可查看任务所属生产订单、产品、工序顺序、工作中心、计划数量、标准工时和作业摘要。
- 待开工任务可“开始工序”，执行中任务可“完工登记”。
- 成功后更新状态、完工数量、操作者、时间和请求号证据。
- 后端不可用、空数据、无权限、校验失败、并发冲突和重复提交都有明确提示。
- 生产报工页面仍保留现有功能；若订单工序未全部完成，后端返回冲突信息。

## 未完成边界

- 不做工作中心主数据、设备采集、OEE、派工优先级和甘特排程。
- 不做工序级独立检验单；路线中的检验标记先作为作业提示，质量结果仍在完工检验阶段记录。
- 不支持工序跳过、返工、报废、外协工序和跨订单工序移动。
- 不支持工艺路线升版后自动重建已生成的工序任务；在制订单继续使用下达时的快照。
