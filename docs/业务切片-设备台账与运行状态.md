# 业务切片：设备台账与运行状态

> 文档状态：已实现并通过验收（2026-08-25）
> 适用阶段：设备与智能能力（阶段 D 首个纵向切片）
> 模块归属：equipment
> 迁移：V37
> 前置切片：工作区与角色治理

## 0. 设计立场

本切片先建立设备事实、责任与受控状态，不把人工填报包装成自动采集。设备状态由有权限的人员明确提交，必须携带原因、期望版本和请求编号，并形成不可变事件。

MQTT / OPC UA、边缘网关、点位模型、时序数据、自动报警、OEE、远程控制、点检与维修工单均未接入。浏览器不直连设备或 Broker，高频原始点位未来也不进入核心 PostgreSQL 业务表。

## 1. 业务对象与事实所有权

| 对象 | 所有者模块 | 说明 |
|---|---|---|
| 设备台账 | equipment | 编码、名称、类别、位置、责任人和当前人工状态 |
| 设备状态事件 | equipment | 每次状态流转的操作者、原因、请求编号与时间 |
| 租户、工作区、角色 | identity | equipment 只引用当前访问上下文 |
| 工作中心 | production / product | 本切片保存可选的编码与名称快照，不反向修改其事实 |

设备编码在租户内唯一；设备只在所属工作区可见。编码创建后不可修改。

## 2. 状态机

```text
新建 -> IDLE（闲置）

IDLE -> RUNNING       START（开机）
RUNNING -> IDLE       STOP（停机）
IDLE/RUNNING -> DOWN  REPORT_BREAKDOWN（报故障）
IDLE/DOWN -> MAINTENANCE START_MAINTENANCE（开始维修）
MAINTENANCE -> IDLE   COMPLETE_MAINTENANCE（维修完成）
IDLE -> INACTIVE      INACTIVATE（停用）
```

- `INACTIVE` 在本切片中是终态，恢复设备需进入后续受控变更能力。
- 运行中和已停用设备不能编辑台账；设备编码始终不可编辑。
- 非法流转返回 409，不静默改写状态。

## 3. 业务流程

### 3.1 新建设备

1. 录入设备编码、名称、类别、位置和责任人，可补充制造商、型号、序列号、工作中心与投产日期。
2. 必须填写至少 4 个字符的建档原因。
3. 初始状态固定为 `IDLE`。
4. 编码重复返回 409；成功创建写入 `CREATED` 事件。

### 3.2 编辑台账

1. 仅 `IDLE`、`DOWN`、`MAINTENANCE` 状态可编辑。
2. 必须传 `expectedVersion`，过期返回 409。
3. 必须填写变更原因，并写入 `UPDATED` 事件。

### 3.3 状态动作

1. 按状态机校验动作和来源状态。
2. 每个动作必须传 `expectedVersion` 和至少 4 个字符的原因。
3. 保存当前状态、状态变更时间和版本，同时写入不可变状态事件。

### 3.4 查询

- 列表支持设备编码、名称、位置、责任人和工作中心模糊查询。
- 支持状态和类别筛选以及服务端分页。
- 详情返回完整事件时间线。
- 只返回当前租户、当前工作区设备；跨工作区和跨租户访问均按不存在处理。

## 4. 权限

| 操作 | 允许角色 |
|---|---|
| 查询列表与详情 | 当前工作区已认证用户 |
| 新建、编辑和状态动作 | MAINTENANCE_MANAGER、PRODUCTION_MANAGER、ADMIN |

`MAINTENANCE_MANAGER`（设备经理）加入当前受控角色目录。前端按钮仅用于交互提示，后端权限校验是唯一可信边界。

## 5. 数据所有权、并发与审计

- `equipment.assets` 是当前台账和状态事实，使用 `@Version` 乐观锁。
- `equipment.asset_events` 是不可变业务证据，记录 actor、action、from/to status、reason、request_id 和 occurred_at。
- 写操作在同一应用用例事务内更新台账并追加事件。
- 数据库检查约束限制类别、状态、事件动作和必填字段。

## 6. API 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/equipment/assets` | 当前工作区分页列表 |
| GET | `/api/v1/equipment/assets/{id}` | 台账与事件详情 |
| POST | `/api/v1/equipment/assets` | 新建设备，返回 201 |
| PUT | `/api/v1/equipment/assets/{id}` | 编辑台账 |
| POST | `/api/v1/equipment/assets/{id}/actions` | 执行受控状态动作 |

适用错误语义：400 参数无效、401 未认证、403 无权维护、404 越界或不存在、409 重复/并发/非法状态、422 业务规则不满足。

## 7. 前端接入

- `/equipment/assets`：设备台账视图，支持新建、编辑、筛选、详情和状态动作。
- `/equipment/status`：设备状态视图，突出运行、故障、维修与最近变更，但读取同一设备事实。
- 数据只经 `src/services` 和前端 BFF 访问；后端不可用、403、空数据、校验失败与并发冲突均有明确状态。
- 页面固定提示“人工维护状态 / 真实采集未接入”，不展示伪实时曲线或伪遥测时间。

## 8. 验收条件

1. 未认证请求返回 401。
2. 当前工作区列表可见，跨工作区和跨租户设备不可见。
3. 新建设备固定进入 `IDLE`，重复编码返回 409。
4. 设备经理、生产经理和管理员可以维护；其他角色写操作返回 403。
5. 过期 `expectedVersion` 返回 409。
6. 非法状态动作返回 409，合法动作按状态机流转。
7. 运行中和已停用设备不能编辑；只有闲置设备可以停用。
8. 每次创建、编辑和状态动作都能在详情事件中追溯原因、操作者、请求编号与时间。
9. OpenAPI、数据库迁移、后端测试、前端契约测试、lint、类型检查和生产构建全部通过。
