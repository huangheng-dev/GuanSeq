# 业务切片：设备样本保留自动运行化

> 状态：已实现（2026-08-26 工程闭环）  
> 领域所有者：`equipment`  
> 前置切片：[设备样本历史与保留清理](./业务切片-设备样本历史与保留清理.md)

## 业务目标

设备经理需要在明确知情后，为当前工作区启用原始样本自动清理，查看下一次运行、最近结果和失败责任，并能在故障恢复后立即重试。开源单机和多实例部署必须使用相同业务契约，多个实例不能同时清理同一工作区。

## 业务对象与不变量

- 自动清理是工作区保留策略的可选运行方式，默认关闭；升级到 V43 不会自动删除任何已有样本。
- 管理员或设备经理可以设置 1—720 小时运行间隔。首次启用从“当前时间 + 间隔”开始，不立即产生删除副作用。
- 每个工作区只有一把数据库租约；租约未到期时其他实例或人工“立即运行”不能重复执行。
- 单次自动运行最多删除 10000 条严格早于策略截止时间的原始样本，避免长事务。仍有过期数据时记录 `PARTIAL` 并在短间隔后继续。
- 每次运行持久化触发来源、责任人或实例、请求编号、截止时间、删除数量、剩余数量、开始/完成时间和结果。
- 失败记录为工作区内的待处理责任证据，责任角色固定为 `MAINTENANCE_MANAGER` 或 `ADMIN`；确认失败不会取消自动重试，也不会修改样本事实。
- 失败按 15 分钟起步指数退避，最长 6 小时；成功后恢复配置的正常间隔。
- 错误摘要必须经过受控映射，不写入口令、连接串、SQL 或堆栈。

## 权限、恢复与运行开关

- 当前工作区成员可以查看自动运行状态和最近运行证据。
- 只有 `ADMIN`、`MAINTENANCE_MANAGER` 可以启停自动清理、调整间隔、立即运行和确认失败责任。
- 应用级 `GUANSEQ_TELEMETRY_RETENTION_SCHEDULER_ENABLED` 默认关闭；关闭时后端拒绝启用工作区自动清理，页面明确显示运行器不可用。
- “立即运行”使用请求编号幂等；租约冲突返回 409，禁用状态或运行器不可用返回 422。
- 进程在运行中退出时不提交删除事务；租约到期后其他实例可以恢复。数据库不可用导致无法落失败证据时必须记录结构化应用日志，并在数据库恢复后由下一轮继续扫描。

## 验收条件

1. V43 是自动配置、工作区租约和不可变运行证据的数据库事实来源。
2. OpenAPI 固化自动配置、立即运行、最近运行和失败确认契约。
3. PostgreSQL 集成测试证明默认关闭、显式启用、单工作区互斥、严格截止时间、10000 条批次上限、请求幂等、失败责任确认和权限边界。
4. 调度器只扫描已经显式启用且到期的策略，并由数据库租约决定唯一执行者。
5. 页面覆盖运行器不可用、关闭、等待、运行成功、部分完成、失败待处理、租约冲突和提交中状态。

## 非目标

- 不引入 Quartz、Redis、消息队列、独立调度服务或独立设备服务。
- 不发送邮件、短信、企业微信等外部通知；本切片交付产品内失败责任与确认证据。
- 不实现趋势聚合、长期归档、时序数据库、报警规则、OEE 或远程控制。
- 不改变 Modbus/MQTT 等协议适配边界，也不把仿真验证描述为真实现场上线。

## 实现与验证证据

- V43 已建立策略自动配置、工作区租约与不可变运行记录；自动运行全局开关和工作区策略均默认关闭，升级不会触发清理。
- OpenAPI、后端应用用例、调度扫描、人工立即运行、失败确认和页面运行证据已接入同一业务契约；没有引入新的中间件或独立服务。
- PostgreSQL/Testcontainers 集成测试以 10001 条过期样本证明单批 10000 条上限和 `PARTIAL` 续跑，并覆盖请求幂等、租约冲突、受控失败、责任确认、恢复重试、权限和默认关闭边界。
- 后端完整测试 113/113 通过、0 跳过，Flyway 从空库完整执行 V1—V43；前端 lint、typecheck、29 个测试文件/84 项测试和生产构建通过。
- 真实浏览器已完成“显式启用 → 首次计划不立即删除 → 立即运行 → `SUCCEEDED` 证据回显”，桌面与 390px 布局通过；干净会话完成详情与保留管理交互后控制台 0 错误、0 警告。
- 本切片完成的是样本生命周期运行化，不代表真实设备、现场网络、MQTT、报警、容量或长期归档已经验收。
