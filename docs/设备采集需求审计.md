# 设备采集需求审计

> 审计日期：2026-08-26  
> 状态：现状审计、工程假设与容量评审完成；生产形态 Modbus 代码、仿真、数据库集成和浏览器闭环已实现，真实现场实施准入未完成  
> 适用范围：设备、网关、协议、点位、数据质量、报警、存储与运维责任  
> 前置能力：设备台账、人工状态、维护工单、备件成本、周期维护任务均已接入真实 API

## 1. 审计结论

审计时，代码库只能管理设备业务台账和人工维护证据。根据审计结论与 [ADR-0006](./adr/0006-无真机条件下的可替换设备采集闭环.md)、[ADR-0007](./adr/0007-外部MQTTBroker只读接入.md)，现已增加协议无关的连接/点位/运行状态/样本模型、生产 Modbus TCP 与 MQTT 3.1.1 外部 Broker 只读适配器、标准协议仿真端点、业务 API 和只读工作台。用户授权编制的设备与点位仍是工程假设，不构成现场事实；当前也没有引入内置 EMQX、TimescaleDB 或独立设备接入服务。

2026-08-26 对仓库文档、代码、测试和本地种子数据的复核只发现 `EQ-CNC-001 / 海岳数控 VMC-850` 等开发演示记录，没有对应厂商协议、寄存器/节点表、采样要求或现场网络证据。这些种子记录不能替代真实试点输入。

真实现场启用前，仍需要一台明确的试点设备或用户已有 MQTT Broker 及其接口资料、点位/Topic 清单、网络条件、采样与补传要求。无硬件开发不再被这些现场资料阻塞，但必须使用与生产相同的协议链路并显式标注仿真来源。当前已创建 V41/V44、OpenAPI 和 Modbus/MQTT 协议适配器，而不是静态 JSON 或伪业务 API；设计结论详见[设备采集工程验证假设与最小切片设计](./设备采集工程验证假设与最小切片设计.md)。

## 3. 进入实施必须提供的现场清单

### 3.1 设备与业务目的

每台试点设备必须提供：

- GuanSeq 设备编码，以及厂商、型号、序列号和所在工厂/车间。
- 要解决的具体问题，例如停机识别、关键参数趋势、报警联动或计量抄表。
- 数据使用岗位、查看范围和允许的业务动作。
- 是否只读采集；首个切片默认禁止远程控制。
- 现场负责人、设备厂商联系人和系统运行责任人。

### 3.2 协议与连接

- 协议名称与版本：OPC UA、Modbus TCP/RTU、厂商 API、文件或其他明确协议。
- 服务端/从站地址、端口、站号、命名空间、寄存器或厂商接口文档。
- 鉴权方式、证书生命周期、只读账号和最小权限。
- 采集点位能否由设备直接提供，是否必须使用现场边缘网关。
- 工厂网络分区、防火墙、NAT、代理、出站限制和允许的通讯方向。
- 测试环境、联调窗口以及生产变更审批要求。

密码、证书私钥和令牌不得写入需求文档、代码仓库、截图或日志，只记录其交付与轮换责任。

### 3.3 点位字典

每个点位至少具备：

| 字段 | 说明 |
|---|---|
| 点位编码/地址 | 在设备或协议中的稳定标识 |
| 业务名称 | 用户可理解的简体中文名称 |
| 数据类型 | Boolean、整数、精确小数、字符串或枚举 |
| 工程单位与精度 | 例如 MPa、℃、rpm、kWh，以及小数位 |
| 采样方式 | 周期采样、变化采样或设备事件 |
| 周期/死区 | 秒或毫秒；变化阈值及最小上报间隔 |
| 合法范围 | 最小值、最大值、枚举范围和无效值 |
| 质量规则 | 好、可疑、坏、通讯中断及厂商质量码映射 |
| 时间语义 | 设备时间来源、时区、精度和是否可信 |
| 保留与聚合 | 原始保留期，以及分钟/小时聚合需求 |
| 敏感性 | 是否包含配方、产量或其他受限生产信息 |
| 业务用途 | 趋势、状态、报警、抄表或维护诊断 |

### 3.4 可靠性、报警与运维

- 允许的数据延迟、最大连续断网时长和边缘缓存容量。
- 补传顺序、重复消息去重键、乱序容忍窗口和时钟漂移上限。
- 网关、设备和服务的心跳周期、离线判定和恢复判定。
- 报警阈值、持续时间、去抖、抑制、恢复条件、级别和责任人。
- 哪些报警仅提示，哪些经人工确认后可以创建维修工单。
- 失败重试、死信/隔离、人工补偿、监控、值守和升级责任。
- 数据保留、备份、删除、导出与审计要求。

## 4. 规模与技术准入计算

实施前按以下口径估算，而不是用“以后设备很多”作为技术理由：

```text
日样本数 = 设备数 × 每台点位数 × 86400 ÷ 平均采样间隔（秒）
日原始量 = 日样本数 × 单样本平均字节数 × 编码与索引放大系数
补传峰值 = 离线缓存样本数 ÷ 要求恢复时长
```

评审至少提交平均、峰值和未来 12 个月三组数据，并注明事件型点位和周期型点位比例。

| 候选能力 | 只有满足以下证据才进入决策 | 未满足时的默认 |
|---|---|---|
| 现场边缘网关 | 设备协议不能安全直达中心、需要串口/厂商驱动、断网缓存或现场网络隔离 | 不部署独立网关 |
| MQTT Broker | 多网关长连接、发布订阅、会话/离线交付或明显连接规模证明 REST 不合适 | 不部署 EMQX |
| 时序数据库 | 真实写入量、保留期和趋势查询证明核心 PostgreSQL 成本不可接受 | 不部署 TimescaleDB |
| 独立设备接入服务 | 协议依赖、发布频率、故障隔离或独立扩缩容证明模块化单体不合适 | 保持现有运行单元最少 |
| 事件/消息总线 | 报警或业务联动需要可靠异步传播，且本地事务调用不能满足 | 不引入新消息组件 |

满足任一重大技术引入条件后，必须创建 ADR，记录问题证据、容量数据、成本、退出条件和验证方式。

## 5. 第一个纵向切片的建议边界

现场资料齐全后，首个切片建议只覆盖一类协议和一台真实设备：

```text
设备台账中的试点设备
→ 只读连接与身份验证
→ 3–10 个已评审点位
→ 设备时间、接收时间、质量码和序列号归一化
→ 断连、补传、重复与乱序验证
→ 当前值和最近通讯时间只读展示
→ 操作与故障证据
```

首个切片不包含远程控制、OEE、预测维护、自动生成维修工单、全厂设备批量接入或多协议平台化。报警若进入范围，也只选择一条有明确阈值、恢复条件和责任人的规则。

## 6. 权限与事实所有权

- `equipment` 模块拥有设备、连接配置与业务关联；设备台账继续是设备身份唯一来源。
- 原始采集值不是核心业务状态。业务状态只能经受控用例和权限校验更新。
- 设备经理可查看连接与数据质量；连接凭据只由平台/现场运维管理，前端不返回密钥。
- 生产、质量和维护岗位只能读取其工作区及职责范围内的已授权点位。
- 浏览器只访问 HTTPS 业务 API，不直连 PLC、网关或 Broker。
- AI、报表和报警处理器不得绕过业务 API 修改设备或维修事实。

## 7. 首个切片验收条件

1. 试点设备、业务目的、协议文档、点位字典和现场责任人全部可追溯。
2. 只读连接使用最小权限，密钥不进入仓库、浏览器、日志或截图。
3. 每条样本保留设备 ID、点位、值、质量码、设备时间、接收时间、序列号和消息版本。
4. 正常采集、坏质量、设备断连、网关断网、补传、重复、乱序和时钟漂移均有可重复测试。
5. 页面明确区分设备业务状态、通讯在线状态和数据质量。
6. 采集失败不修改核心业务事实；恢复后不会重复生成报警或业务动作。
7. 跨租户、跨工作区、无权限访问和敏感配置读取被后端拒绝。
8. 真实容量、延迟、补传和保留指标达到现场确认的验收值。
9. 新增技术组件均有已接受 ADR、部署、监控、备份、升级和退出方案。
10. OpenAPI、测试、生产构建、现场联调和浏览器验收全部通过后，页面才能从“规划”改为“已启用”。
