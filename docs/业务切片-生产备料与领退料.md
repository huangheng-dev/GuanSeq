# 业务切片：生产备料与领退料

## 目标

把生产订单的 BOM 组件需求推进为生产模块拥有的备料/领料事实，并让仓库模块以真实库存余额和不可变流水完成发料、退料过账。本切片先支持“按单生成一张领料单、分批领用、剩余数量校验、合格库存退料”，不在本次引入条码/PDA、库位补货、替代料、工序投料、成本归集或审批流。

## 业务对象与所有权

| 对象 | 所有模块 | 说明 |
|---|---|---|
| 生产领料单 | production | 由生产订单和计划开工日已生效 BOM 生成，记录发料仓库、组件需求、已领、已退和审计状态 |
| 生产领料单行 | production | 记录组件物料、BOM 需求数量、本次累计已领数量和累计已退数量 |
| 生产退料单 | production | 对已领组件执行退料过账，记录退料原因、目标库位和逐行退料数量 |
| 库存余额与流水 | warehouse | 只由仓库模块写入；生产模块通过公开 API 请求发料/退料，不直接访问库存表 |

## 状态与规则

生产领料单状态：`DRAFT → PARTIAL → ISSUED`，未发料的草稿可 `CANCELLED`。

- 只有 `RELEASED` 或 `IN_PROGRESS` 的生产订单可以生成领料单。
- 同一生产订单同时只能存在一张未取消领料单，避免重复备料需求。
- 生成时使用计划开工日已生效 BOM，需求数量 = 订单计划数量 × 组件用量 ÷ BOM 基数 × (1 + 损耗率)。
- 发料必须从所选仓库的合格库存余额中扣减；库存不足、库存被冻结/占用或版本冲突时不得部分过账，整笔动作回滚。
- 发料数量必须大于 0，且单行累计已领不得超过需求数量。
- 第一次成功发料后状态为 `PARTIAL`；当所有组件需求均已领足时自动转为 `ISSUED`。
- 退料必须针对已领单行；退料数量必须大于 0，且累计退料不得超过累计已领。
- 退料回到领料单上的发料仓库和用户指定的合格/生产类库位，形成 `RETURN` 库存流水。
- 取消只允许 `DRAFT` 且必须填写原因；创建、发料/取消和退料均按 `X-Request-Id` 幂等，重复请求稳定返回已保存结果。
- 所有动作记录操作者、时间、请求编号和事件；领料单详情返回逐笔库存流水编号、仓库库位、数量和请求号证据。

## 数据与 API

Flyway：

- `V19__create_production_material_issue_model.sql`

主要接口：

- `GET /api/v1/production/material-issues`
- `POST /api/v1/production/material-issues`
- `GET /api/v1/production/material-issues/{id}`
- `GET /api/v1/production/material-issue-reference-data`
- `POST /api/v1/production/material-issues/{id}/actions`
- `POST /api/v1/production/material-issues/{id}/returns`

仓库模块新增公开发料/退料服务，库存流水类型增加 `RETURN`。HTTP 契约以 `guanseq-api-v1.yaml` 为准。

## 前端验收

- `/warehouse/material-issues` 与 `/warehouse/staging` 展示真实生产领料单，支持查询、状态筛选和详情下钻；后端保留分页契约，当前工作台首屏加载前 100 张。
- `/warehouse/staging` 可进入同一备料领退料工作台。
- 可以选择已下达/执行中且已有生效 BOM 的生产订单和仓库生成领料单。
- 可对草稿/部分发料单执行发料，并展示需求、已领、已退、可领数量、库存不足或并发冲突错误。
- 可对已领组件执行退料，成功后展示退料记录、库存 `RETURN` 流水和请求号证据。
- 空数据、加载中、接口失败、无权限、校验失败和并发冲突必须有明确提示。

## 未完成边界

- 本切片不做库位分配建议、批次拣货策略、替代料、工序级投料、超领审批和领料审核；工作台暂不提供超过 100 张后的翻页控件。
- 退料统一回到可用库存；来料/过程质量判定后的不合格退回、冻结或报废由后续质量切片处理。
- 材料成本和订单利润下钻尚未接入。
