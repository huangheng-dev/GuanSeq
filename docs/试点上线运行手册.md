# GuanSeq 试点上线运行手册

> 容器构建、生产 Compose、配置预检、TLS、备份/恢复和升级回退命令见[生产部署与恢复运行手册](./生产部署与恢复运行手册.md)。本文继续负责具体安装实例的身份、权限和业务验收。

本文用于把已经通过工程门禁的 GuanSeq 基线接入客户真实身份、空正式数据库和真实试点数据。它不是“已上线”声明；只有本手册中的外部环境、真实登录和业务验收证据齐全后，试点才可判定为上线。

## 1. 范围与责任

本次上线范围是第一条制造闭环及其基础收付款证据链，以及支撑多岗位试点的当前工作区成员和最小组织治理：销售订单、计划/MRP、采购与备料、生产工单与工序、质量、完工入库、发货、订单利润、成员开通、受控角色分配、当前工作区访问停用/恢复、所在工厂与直属现场维护、当前工作区负责人和成员主要归属。设备、完整总账、外部系统集成、动态角色与组合权限、跨工作区组织治理、岗位，以及未从 Mock Adapter 替换的页面不在本次承诺内。首次初始化只建立首个管理员，后续成员必须通过正式成员管理用例开通，不得复用初始化入口或人工改库；组织归属不产生角色或权限。

上线前指定三名责任人：部署负责人维护应用、数据库和密钥；身份负责人配置 OIDC 客户端并核实令牌声明；业务负责人准备受控试点主数据和验收订单。三者共同确认上线窗口、数据库备份、RPO/RTO、网络回退和故障联系人。

## 2. 上线前置条件

- 正式域名和 HTTPS 已生效，服务器时间同步；浏览器回调固定为 `https://<正式域名>/api/auth/callback`。
- 身份提供者已登记授权码流程、PKCE S256、退出回调，访问令牌包含后端受众以及稳定的用户名声明（默认 `preferred_username`）。
- PostgreSQL 有独立正式账号、备份和恢复演练记录；部署前记录构建版本、Flyway 当前版本和备份标识。
- BFF 到后端的地址只在受控网络可达；后端不直接暴露给非受控公网。初始化窗口再增加来源网络限制。
- 所有密钥由密钥管理系统注入，不写入仓库、镜像、工单正文或命令输出。会话密钥是 Base64 编码的 32 个随机字节；初始化令牌与会话密钥、OIDC 客户端密钥彼此独立。
- 身份负责人已从签名有效的真实访问令牌或 IdP 管理界面确认首个管理员用户名的精确值和大小写。填写错误后不能再次初始化。

## 3. 配置与预检

前端/BFF 必需配置：

```text
GUANSEQ_SECURITY_MODE=oidc
GUANSEQ_API_BASE_URL=<后端内部地址>
GUANSEQ_OIDC_ISSUER_URI=<签发者>
GUANSEQ_OIDC_CLIENT_ID=<保密客户端 ID>
GUANSEQ_OIDC_CLIENT_SECRET=<密钥系统注入>
GUANSEQ_OIDC_CLIENT_AUTH_METHOD=client_secret_basic
GUANSEQ_OIDC_REDIRECT_URI=https://<正式域名>/api/auth/callback
GUANSEQ_OIDC_POST_LOGOUT_REDIRECT_URI=https://<正式域名>/login?signedOut=1
GUANSEQ_OIDC_SCOPE=openid profile
GUANSEQ_OIDC_RESOURCE=<API 资源，按 IdP 要求>
GUANSEQ_SESSION_SECRET=<Base64 32 字节随机密钥>
```

后端必需配置：

```text
SPRING_PROFILES_ACTIVE=oidc
GUANSEQ_DB_URL=<正式 PostgreSQL JDBC 地址>
GUANSEQ_DB_USERNAME=<正式数据库账号>
GUANSEQ_DB_PASSWORD=<密钥系统注入>
GUANSEQ_OIDC_ISSUER_URI=<与前端相同的签发者>
GUANSEQ_OIDC_JWK_SET_URI=<公开 JWK 集地址>
GUANSEQ_OIDC_AUDIENCE=<访问令牌要求的受众>
GUANSEQ_OIDC_USERNAME_CLAIM=preferred_username
```

在与正式环境网络条件等价的受控执行节点加载配置后运行：

```powershell
pnpm pilot:preflight
```

预检会验证必要配置、HTTPS 回调、会话密钥长度、OIDC discovery、授权码/PKCE 能力和公开签名密钥，不打印客户端、会话或初始化密钥。所有 `[FAIL]` 必须清零；每条 `[WARN]` 由责任人记录接受理由。

## 4. 数据库迁移与首次初始化

1. 停止业务写入，完成并核验部署前备份。
2. 启动后端，让 Flyway 执行版本迁移；确认没有校验失败，并访问 `/api/v1/platform/status` 记录构建版本和请求编号。
3. 仅对空正式库临时设置 `GUANSEQ_BOOTSTRAP_ENABLED=true` 和独立的 `GUANSEQ_BOOTSTRAP_TOKEN`，限制入口来源后重启后端。
4. 使用已核实的真实 OIDC 用户名发起一次初始化。请求体中的编码使用大写字母、数字、下划线或连字符；公司编码与工厂编码不得相同。

```powershell
$bootstrapHeaders = @{
  "X-GuanSeq-Bootstrap-Token" = $env:GUANSEQ_BOOTSTRAP_TOKEN
  "X-Request-Id" = "pilot-bootstrap-<变更单号>"
}
$bootstrapBody = @{
  tenantCode = "ACME"
  tenantName = "示例制造有限公司"
  plantCode = "ACME_PLANT_01"
  plantName = "一号工厂"
  workspaceCode = "ACME_MAIN"
  workspaceName = "生产运营工作区"
  externalUsername = "pilot.admin"
  displayName = "试点管理员"
} | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri "$env:GUANSEQ_API_BASE_URL/api/v1/bootstrap/initial-workspace" `
  -Headers $bootstrapHeaders -ContentType "application/json" -Body $bootstrapBody
```

预期只有一个请求返回 `201` 和 `COMPLETED`；无令牌返回 `401`，重复或并发败者返回 `409`。保留请求编号、响应中的事实 ID 和审计查询结果，不保留令牌。

5. 立即设置 `GUANSEQ_BOOTSTRAP_ENABLED=false`、从部署和密钥系统删除初始化令牌并重启。再次 POST 应为 `404`。数据库的完成状态还会阻止重复初始化，但不能替代关闭入口。

若初始化事务失败且返回非 `201`，先根据请求编号排查，确认库中没有部分事实后再重试。若用户名或组织填写错误但事务已经成功，不得修改初始化状态或直接删除数据；停止上线，走受控数据修正和审计流程。

## 5. 真实登录与只读冒烟

1. 首个管理员从 `/login` 发起真实登录，完成授权码 + PKCE 跳转，确认进入正确工作区。
2. 浏览器只检查会话 Cookie 的名称、`HttpOnly`、`Secure`、`SameSite` 和作用域，不复制或记录 Cookie 值。
3. 由身份负责人通过批准的方式取得该管理员的短期访问令牌，在受控终端临时注入以下变量，然后运行只读冒烟：

```powershell
$env:GUANSEQ_PILOT_ACCESS_TOKEN = "<短期令牌，仅当前受控会话>"
$env:GUANSEQ_PILOT_EXPECTED_USERNAME = "pilot.admin"
pnpm pilot:smoke
Remove-Item Env:GUANSEQ_PILOT_ACCESS_TOKEN
```

冒烟覆盖平台状态、工作区、工作区成员、销售订单、独立需求、MRP、采购订单、生产订单、工序任务、完工检验、库存、发货和订单利润。成员接口同时确认首个账号拥有当前工作区管理员授权。每次请求使用唯一请求编号，只接受 HTTP 200、JSON 响应和请求编号贯穿；输出不包含令牌和业务响应体。十三项必须全部通过。

## 6. 多岗位成员开通

1. 身份负责人先在 IdP 中建立或确认试点用户，记录访问令牌中稳定用户名声明的精确值；贯序不会自动创建内部账号，也不读取 IdP 组作为业务角色。
2. 首个管理员进入“系统管理 → 组织与用户 → 用户管理”，逐人填写该外部用户名、显示姓名和一个受控业务角色。用户名创建后不能在此修改。
3. 让新成员完成真实登录，确认只能进入已分配工作区，并按角色验证一个允许动作和一个拒绝动作。前端隐藏按钮不作为授权证据。
4. 抽查一次停用和恢复：必须填写原因；停用后新会话不能进入当前工作区；恢复后重新登录可用。管理员不能在该页面修改自己，工作区必须保留启用管理员。
5. 保留开通、角色变更、停用/恢复的请求编号和审计事件。不要把动态角色、组织架构或 IdP 生命周期同步记录为已完成能力。

## 7. 真实业务验收

业务负责人用专门的低风险试点编码创建真实但受控的数据，逐项保留单据号、操作者、时间、请求编号、状态和关键金额。不得使用本地示例数据作为证据。

验收顺序：

1. 建立客户、物料、有效 BOM、有效工艺路线、仓库/库位、提前期、标准成本和工作中心费率。
2. 创建、提交、审核并下达一张销售订单，确认独立需求自动生成且快照正确。
3. 执行 MRP，核对冻结输入、日期净算与 BOM 展开；人工审核建议并转换采购/生产草稿，不允许自动下达。
4. 完成采购订单、收货与来料检验；生成生产备料单并分批领料，核对不可变库存流水和退料边界。
5. 下达生产订单，逐工序开工、完工并登记/审核实际人工；未完成工序时验证报工被拒绝。
6. 完成生产报工、完工检验和合格品入库，核对不合格数量不能入库、库存和订单完成量一致。
7. 完成销售发货与成品出库，生成应收发票并做部分/全部收款；登记应付发票并付款核销。
8. 结算订单利润，核对收入、材料净用量、审核人工、制造费用、缺成本标记和毛利快照。
9. 对适用动作各抽查一次校验失败、无权限、重复请求或版本冲突，确认无部分写入且审计证据可追踪。

任一核心金额、库存数量、状态流或租户隔离不一致都阻止上线通过，不能以手工改库消除差异。

## 8. 监控、回退与完成标准

上线窗口持续观察应用错误率、认证失败、接口延迟、数据库连接/锁等待、Flyway 状态和基础资源。以 `X-Request-Id` 串联 BFF、后端错误和审计事件；日志不得记录访问令牌、会话、初始化令牌或完整敏感业务体。

回退遵循数据阶段：尚未产生正式业务写入时，可停止新版本并从已验证的部署前备份恢复；Flyway 迁移只向前，禁止手工删除版本记录。已经产生真实业务写入后，不做破坏性数据库回退，立即停止新增写入、保留证据并采用前向修复。身份异常时可先撤销 OIDC 客户端/用户访问并停止应用，但不能重开初始化状态。

只有以下条件全部满足才可标记试点上线：

- 工程版本的前后端完整门禁和真实 PostgreSQL 迁移测试通过；
- OIDC 预检无失败，真实登录成功，初始化入口已关闭且令牌已删除；
- 十三项只读冒烟全部通过，试点成员完成角色允许/拒绝验证；
- 一条受控真实业务闭环和异常边界验收通过；
- 备份/恢复、监控、RPO/RTO、责任人、已知限制和回退决定均有记录。

在客户 IdP、正式网络、正式数据库和业务数据尚未提供时，当前状态只能称为“试点上线工程就绪”，不能称为“生产已上线”。
