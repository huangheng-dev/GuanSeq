# 业务切片：销售退货与质量处置闭环

> 适用阶段：阶段 C 订单到交付反向增强  
> 工程状态：已完成（2026-08-27）  
> 前置事实：销售发货、库存流水、红字发票与反核销、订单利润重算

## 目标与边界

本切片补齐客户退货的实物流事实，使“客户提出退货”不再只靠财务人员手工填写红字数量：

```text
已发货销售订单
→ 销售经理建立退货授权
→ 仓库收货进入待检库存
→ 质量人员判定合格/不合格
→ 合格品回到可用库存，不合格品进入隔离库存
→ 销售订单形成毛发货、累计退货和净发货事实
→ 既有红字发票与订单利润重算读取净发货口径
```

本切片不自动开红字发票或自动退款。财务事实仍由财务人员在既有红字/退款流程中确认，避免实物到库直接触发资金冲销。退货单与红字发票的显式关联属于后续增强。

## 业务对象与所有权

| 对象 | 数据所有者 | 核心事实 |
| --- | --- | --- |
| 销售退货单与退货行 | sales | 客户、原订单、授权退货数量、原因、状态和责任证据 |
| 毛发货/累计退货/净发货 | sales | 订单行保留毛发货，新增累计退货，净发货为二者之差 |
| 待检、合格与隔离库存 | warehouse | 退货收货、检验转移及所有不可变库存流水 |
| 质量判定 | sales | 本切片保留判定人、时间、合格/不合格数量；库存事实仍归 warehouse |
| 红字发票、退款、利润快照 | finance | 继续由既有财务用例维护，不由销售模块直接改表 |

模块协作只通过公开 API 或模块事件：sales 不写 warehouse/finance 表，warehouse 不写 sales 表；退货收货或撤销后发布履约变化事件，finance 据此把已有利润快照标记为待重算。

## 状态机

```text
PENDING_RECEIPT ──收货──> RECEIVED ──质量判定──> COMPLETED
       │                    │
       └──取消──> CANCELLED  └──收货冲回──> REVERSED
```

- `PENDING_RECEIPT`：销售经理已经授权，仓库尚未收到实物。
- `RECEIVED`：全部授权数量已进入 `INSPECTION` 待检库存，订单累计退货已更新。
- `COMPLETED`：质量人员将全部待检数量拆分为 `AVAILABLE` 合格库存与 `BLOCKED` 隔离库存。
- `CANCELLED`：实物收货前取消，释放待收数量，不产生库存或净发货变化。
- `REVERSED`：质量判定前发现收货错误，完整冲回待检库存和订单累计退货；原记录及事件保留。

首版一张退货单一次完整收货；客户分批退回时建立多张退货单。已完成质量判定的退货单不可删除、取消或冲回，后续错误必须通过新的库存调整和责任单据处理。

## 权限与关键不变量

- `SALES_MANAGER`、`ADMIN` 可以建立和取消待收退货单。
- `WAREHOUSE_MANAGER`、`INVENTORY_CONTROLLER`、`ADMIN` 可以收货或在检验前冲回收货。
- `QUALITY_INSPECTOR`、`QUALITY_MANAGER`、`ADMIN` 可以提交质量判定。
- 任何有效退货行数量必须大于零，且“累计已退 + 其他待收退货 + 本次授权”不得超过该订单行毛发货数量。
- 建立退货单和收货时都重新校验数量；同一订单使用事务级业务锁，避免并发超退。
- 收货必须选择活动仓库及其活动库位，全部商品先进入 `INSPECTION`，不得直接成为可用库存。
- 判定时每行 `accepted + rejected = received`；合格与不合格数量均不能为负。
- 收货冲回只允许 `RECEIVED` 状态，且待检库存仍足够；冲回后累计退货减少，状态终结为 `REVERSED`。
- 每个写动作使用 `X-Request-Id` 幂等并校验 `expectedVersion`；事件记录责任人、时间、原因、请求编号和前后状态。
- 订单毛发货量不改写。净发货量 = `delivered_quantity - returned_quantity`，允许退货后重新发替换品，但净发货不得超过订单数量或小于零。

## API 与数据事实

- `GET /api/v1/sales/returns`：分页查询退货单。
- `GET /api/v1/sales/returns/{id}`：读取退货详情、行、库存摘要与责任事件。
- `GET /api/v1/sales/return-reference-data`：读取可退订单、剩余可授权数量、仓库和库位。
- `POST /api/v1/sales/returns`：建立待收退货授权。
- `POST /api/v1/sales/returns/{id}/actions`：取消、收货、质量判定或收货冲回。
- Flyway `V48` 是表结构事实来源，OpenAPI 是 HTTP 契约事实来源。
