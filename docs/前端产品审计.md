## 1. 审计范围与方法

本次审计包括：

- 12 个一级栏目、78 个二级模块、79 个三级页面。
- 全部 169 条产品 URL 可达性检查。
- 经营总览、销售、产品/BOM、计划/MRP、生产、库存、质量、设备、成本、权限等代表性页面。
- 新建表单、弹窗、筛选、分页、移动端布局和移动导航。
- 页面模型、交互实现、自定义下拉、焦点和基础语义检查。

169 条产品 URL 当前均返回 HTTP 200。由于大量页面共享同一页面模型，URL 可达不等同于业务页面已经完整实现。

## 2. 总体结论

### 2.1 已经做好的部分

- 12 个一级栏目覆盖了普通制造企业的主要工作域，不建议继续增加一级菜单。
- 导航层级、独立 URL、展开状态和移动端抽屉结构清晰。
- 圆润视觉体系、颜色、间距、表格、分页、弹窗和自定义下拉保持一致。
- 首页能够表达销售订单到生产交付的跨部门主流程。
- 页面已有加载、Mock 异步提交、错误反馈、分页和空筛选状态的工程基础。
- 计划模块明确标识“规划”，没有完全隐藏未来能力。

### 2.2 主要问题

当前 169 条路径主要由 12 类通用页面模型生成。页面标题和少量态势面板不同，但表格、表单、关注事项、流程和数据结构重复度较高。

这会产生三个直接问题：

1. 页面看起来完整，但不能真实完成对应岗位的专业任务。
2. 部分表头与数据语义不匹配，例如库存“仓库库位”列显示“现存量 · 标准”。
3. 不同领域的状态机、审批、证据和操作被统一成“创建、审核、执行、完成”，失去制造业务差异。

因此当前状态应定义为：

- **视觉设计系统：基本完成。**
- **导航与路由框架：基本完成。**
- **前端工程基线：基本完成。**
- **专业业务页面：需要逐模块深化。**
- **正式上线前端：尚未完成。**

## 4. 一级栏目审计

当前 12 个一级栏目已经足够完整：

1. 经营工作台
2. 销售管理
3. 产品与工艺
4. 计划管理
5. 采购与供应
6. 仓储物流
7. 生产管理
8. 质量管理
9. 设备与资产
10. 成本与结算
11. 数据分析
12. 系统管理

该顺序按“经营入口 → 客户需求 → 产品定义 → 计划 → 供应与备料 → 生产执行 → 质量闭环 → 资产保障 → 成本经营 → 平台治理”组织。仓储放在生产前，突出收货、备料与领料对车间执行的前置支撑；成品入库与销售发货仍在仓储栏目内部按作业顺序呈现。

审计结论：**不建议增加新的一级栏目。** AI、消息、任务、集成、设备数据等能力应进入现有工作台或系统管理，避免侧栏继续膨胀。

## 5. 建议补充的二级/三级栏目

### 5.1 经营工作台

近期补充：

- 消息中心：全部、未读、业务提醒、系统通知。
- 任务中心：我的待办、批量任务、导入导出任务、失败任务。
- 收藏与最近使用：用于移动端和高频岗位快捷访问。
- 工厂/组织切换：不作为一级栏目，放在顶部工作区入口。

### 5.2 销售管理

建议补充：

- 价格与折扣：价目表、客户价格、折扣规则。
- 销售合同：合同、附件、履约与变更。
- 客户需求/预测：客户预测、需求版本。
- 信用与额度：信用额度、占用、逾期和放行记录。

现有销售订单、报价和发货计划保留，但必须形成独立专业页面。

### 5.3 采购与供应

建议补充：

- 询价比价：询价单、供应商报价、比价定标。
- 采购合同：合同、交付条款、价格与变更。
- 采购价格：供应商价格表、阶梯价格和有效期。
- 供应商协同：订单确认、交期回复、送货预约；可以后续作为供应商门户。

### 5.4 产品与工艺

当前栏目基本合理。需要深化：

- 工程变更必须从“规划”进入正式闭环：变更申请、影响分析、评审、生效和切换。
- 增加版本生效关系，而不是只显示版本号。
- 工艺参数、资源、工装、质量控制点和标准工时进入工艺路线详情。

不建议新增独立 PLM 一级入口。

### 5.5 计划管理

建议补充：

- 需求管理：销售需求、预测需求、独立需求和版本。
- 计划参数：提前期、批量规则、安全库存、计划策略。
- 可承诺量：ATP；约束承诺 CTP 可后续建设。
- 计划异常：缺料、延期、超负荷、重复建议和数据完整性。

高级排程继续保持规划状态，先把 MRP 和齐套做实。

### 5.6 生产管理

建议补充或深化：

- 工序执行台：开工、暂停、报工、异常、质检和完工。
- 班组与人员：班组、技能/资质、当班人员。
- 生产资源：工作中心、设备、工装和人员占用。
- 投入产出与消耗：投料、退料、替代料、合格、不良和报废。
- 电子作业指导书与过程参数采集。

这些优先进入已有生产栏目，不新增一级菜单。

### 5.7 仓储物流

建议补充或深化：

- 批次与序列号：批次状态、有效期、序列号和追溯。
- 库存占用与预留：订单、工单、质检和冻结占用。
- 库存策略：上架、拣货、补货、先进先出和有效期。
- 运输交接：承运商、运单、车辆和签收异常；普通制造版本可保持轻量。

### 5.8 质量管理

建议补充：

- 质量计划：产品/物料对应的检验阶段与控制点。
- 抽样方案：AQL、抽样等级和动态转换规则。
- 缺陷代码：缺陷分类、严重度和原因码。
- SPC：控制图、过程能力和超限规则，可作为后续高级能力。
- CAPA：纠正预防措施、验证和关闭；现有“纠正措施”需要深化为闭环。
- 供应商质量：来料质量趋势、供应商整改和索赔。

### 5.9 设备与资产

建议补充：

- 设备状态与停机：运行、待机、故障、停机原因和时长。
- 计量与抄表：运行小时、循环次数、能耗和保养触发值。
- OEE 与停机分析：可用率、性能、质量和损失分类。
- 故障知识：故障代码、原因、措施和维修案例。
- 设备接入配置：网关、协议、点位模板、报警和数据质量。

设备采集仍保持规划，直到 MQTT/EMQX、网关和真实数据链路建立。

### 5.10 成本与结算

建议补充或深化：

- 成本期间：开期、关期、重算和结转状态。
- 标准成本：材料、人工、制造费用和委外费率。
- 实际成本：领料、报工、费用分摊和质量损失。
- 成本差异：价格、用量、效率和制造费用差异。
- 订单利润：收入、各类成本、差异、毛利和利润率下钻。

总账税务继续保持规划；如果首批客户已有财务软件，可先做凭证接口而不是自建完整总账。

## 8. 可访问性审计

### 8.1 已确认的优点

- 导航、按钮、表单和弹窗多数具有可读标签。
- 页面使用标题、区域、导航、Tab、Dialog、Listbox 等基础语义。
- 自定义下拉具备键盘操作和选择状态。
- 图标按钮普遍配置 `aria-label`。

### 8.2 已确认或高度可能的问题

1. 弹窗和抽屉已补初始焦点、焦点圈定、Escape 关闭、背景 `inert` 与关闭后焦点恢复；仍需以屏幕阅读器组合做回归验证。
2. 数据列表已改用原生表格语义，页签具备 `tablist`、`tab` 与 `tabpanel` 关系；复杂 Grid 键盘导航仍属于后续增强。
3. 小字号与浅灰文字仍存在对比风险，需要用真实色值和自动化工具逐项测量，截图不能证明达到 WCAG。
4. 移动端、200% 缩放、系统大字体与高对比模式仍需形成固定回归矩阵。

本审计不能仅凭截图宣称符合 WCAG。仍需使用键盘、屏幕阅读器、对比度工具和自动化可访问性测试进一步验证。

## 9. 整改优先级

### P0：先让第一条业务闭环能够真实操作

1. 产品与工艺：物料、BOM、工艺路线专用详情与表单已接入真实 API；版本比较、替代料和受控文档仍待后续切片。
2. 销售订单：订单头、明细、交期、价格、审核和变更。
3. MRP：参数向导、运行记录、异常与供需建议。
4. 采购与库存：采购订单、收货、批次库位、领料和库存流水。
5. 生产执行：工单、工序、派工、开工、报工、异常和完工。
6. 质量：检验记录、不合格评审、处置和纠正措施。
7. 成品入库、发货和订单利润下钻。

### P1：补足平台和岗位效率

- 角色权限矩阵、数据范围和字段权限。
- 工厂/组织切换、消息中心、任务中心和最近使用。
- 高级筛选条件组、跨页面共享视图和导入任务中心。
- 附件正文服务、关联单据图谱和不可篡改证据服务。
- 完成屏幕阅读器、200% 缩放、高对比模式和移动端回归矩阵。

### P2：设备、AI 与高级能力

- 设备采集、网关、点位、报警、OEE 和停机分析。
- AI 助手真实模型接入、企业知识库、工具授权、风险解释和日报生成。
- 高级排程、工程变更、自定义报表和开放接口。

## 10. 最终审计意见

GuanSeq 不缺大的一级栏目，当前最需要的是把已有栏目做深。

正确路线不是继续增加 169 条以上的页面，而是停止通用模板横向复制，围绕第一条主业务闭环，为每个关键对象建立：

```text
专业列表
→ 专业详情
→ 受控表单
→ 业务状态机
→ 审批与权限
→ 关联单据
→ 操作证据
→ 异常与恢复
```

完成 P0 后，GuanSeq 才能从“视觉完整的制造系统原型”进入“可与后端联调的专业产品前端”。
