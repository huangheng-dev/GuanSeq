# 设备采集无硬件快速开始

> 适用范围：开源贡献者、产品演示和没有真实 PLC 的开发环境  
> 真实边界：该流程使用生产 Modbus TCP 或 MQTT 3.1.1 客户端适配器和外部协议仿真端点，但不构成厂商、真实 Broker、网络、安全、容量或现场验收证据

## 1. 选择并启动仿真端点

### Modbus TCP

在仓库根目录执行：

```powershell
pnpm telemetry:simulator
```

默认监听 `127.0.0.1:1502`，单元标识为 `1`。可通过以下环境变量调整：

- `GUANSEQ_MODBUS_SIM_HOST`
- `GUANSEQ_MODBUS_SIM_PORT`
- `GUANSEQ_MODBUS_SIM_UNIT_ID`

仿真器只使用 Node.js 标准库，不是 GuanSeq Server 的生产依赖，也不会自动写入任何业务数据。

### MQTT 3.1.1

在另一个终端执行：

```powershell
pnpm telemetry:mqtt-simulator
```

默认监听 `127.0.0.1:1883`，发布精确 Topic `factory/cnc/telemetry`。可通过以下环境变量调整：

- `GUANSEQ_MQTT_SIM_HOST`
- `GUANSEQ_MQTT_SIM_PORT`
- `GUANSEQ_MQTT_SIM_TOPIC`
- `GUANSEQ_MQTT_SIM_INTERVAL_MS`

这个工具是仅供开发的最小 MQTT 3.1.1 协议 Broker，不是生产 Broker，也不会成为 GuanSeq Server 的部署依赖。生产部署应使用用户自行选择和运维的兼容 Broker。

## 2. 启动 GuanSeq

按项目现有开发说明启动 PostgreSQL、`guanseq-server` 和前端。如需启用后台周期轮询，在启动服务端前设置：

```powershell
$env:GUANSEQ_TELEMETRY_POLLING_ENABLED = "true"
```

不启用该变量时，仍可在页面执行连接测试和“立即采集”，便于开发调试；生产部署是否启用轮询必须由运行责任人确认。

如需验证原始样本自动保留任务，还必须显式启用独立运行开关：

```powershell
$env:GUANSEQ_TELEMETRY_RETENTION_SCHEDULER_ENABLED = "true"
```

该开关默认关闭。启用应用开关后，仍需由当前工作区 `ADMIN` 或 `MAINTENANCE_MANAGER` 在页面显式启用自动清理并设置间隔；首次计划从“保存时间 + 间隔”开始，不会立即删除样本。关闭应用开关时仍可查询历史和执行既有人工清理，但后端会拒绝启用工作区自动策略。

## 3. 在页面建立连接

### Modbus TCP 示例

打开“设备与资产 → 设备采集”，选择“接入设备”，使用：

| 字段 | 示例值 |
|---|---|
| 关联设备 | `EQ-CNC-001` |
| 端点类型 | 仿真端点 |
| 主机 | `127.0.0.1` |
| 端口 | `1502` |
| 单元标识 | `1` |
| 采集周期 | `5` 秒 |

默认表单提供运行状态、主轴负载和防护门三个点位，可继续增加工作簿中的其他点位。页面地址是 Modbus 协议零基偏移：`HR40001` 对应地址 `0`，`C00001` 对应地址 `0`。

### MQTT 3.1.1 示例

在“采集协议”选择 `MQTT 3.1.1`，开发验证使用：

| 字段 | 示例值 |
|---|---|
| 端点类型 | 开发仿真端点 |
| 主机 / 端口 | `127.0.0.1` / `1883` |
| 传输 / QoS | `TCP` / `0` |
| 客户端标识 | `guanseq-dev-mqtt` |
| 凭据别名 | 留空（匿名仿真） |
| 消息编号 / 设备时间 | `/messageId` / `/deviceTime` |
| Topic | `factory/cnc/telemetry` |
| 点位 Pointer | `/values/runState`、`/values/spindleLoad`、`/values/doorClosed` |

生产连接可以选择“外部 Broker”并替换主机、TLS、QoS、客户端标识、Topic 和 Pointer。凭据别名不是用户名或密码；例如别名 `SHOPFLOOR_A` 对应服务端环境变量：

```powershell
$env:GUANSEQ_MQTT_CREDENTIAL_SHOPFLOOR_A_USERNAME = "broker-user"
$env:GUANSEQ_MQTT_CREDENTIAL_SHOPFLOOR_A_PASSWORD = "replace-with-secret"
```

用户名和密码不进入数据库、API、浏览器或连接事件。首期只接受精确 Topic，不接受 `+`、`#` 通配符。

## 4. 完成闭环

依次执行：

```text
建立待测试连接
→ 测试连接
→ 启用采集
→ 立即采集或开启周期轮询
→ 查看当前值与质量
→ 暂停采集
```

Modbus 仿真器返回固定工程值；MQTT 仿真器每 2 秒发布带稳定消息编号和设备时间的 JSON，页面会把运行状态、主轴负载和防护门归一化到同一当前值与有限历史模型。重复消息编号不会产生重复样本。

## 5. 切换到真实设备

真实设备到位后，新建端点类型为“物理设备”的连接，并替换主机、端口、单元标识、点位地址、类型、比例和值域。生产代码、样本模型、API 和页面不需要更换。

必须重新执行连接、值域、异常响应、断连、恢复、权限、TLS/ACL 和容量验收。Modbus TCP 只允许读取；MQTT 只订阅用户已有的外部 Broker 并进入同一统一样本模型，不要求所有用户部署内置 Broker，也不绑定 EMQX。
