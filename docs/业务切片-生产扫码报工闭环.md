# 业务切片：生产扫码报工闭环

> 状态：已完成（2026-08-27）

## 目标

让普通键盘式扫码枪或人工输入成为生产执行的受控入口，但不建立第二套移动业务事实。操作人员扫描工序任务与本人身份后，继续调用既有工序开工、工序完工、生产报工和完工检验用例；只有后端返回正式事件、报工单和检验单后，业务事实才生效。

## 对象、所有权与权限

| 对象 | 事实所有者 | 本切片责任 |
|---|---|---|
| 工序任务、工序事件 | production | 校验任务顺序、状态、版本、数量、操作人和请求幂等 |
| 生产报工 | production | 校验订单剩余可报数量，并关联触发报工的最后工序 |
| 完工检验 | quality | 报工后生成独立的待检事实；检验前不增加成品库存 |
| 离线草稿 | 浏览器本地 | 只保存待扫描输入和稳定请求编号，不属于服务端业务事实 |

- 人员标签格式为 `EMP:<username>`，后端要求标签账号与当前认证账号完全一致，不能由前端代填他人身份。
- 工序标签格式为 `OT:<taskNumber>`；移动报工必须精确绑定所属生产订单的最后一道已完成工序。
- 后端权限仍是唯一可信边界，页面隐藏或禁用按钮不替代授权。

## 状态闭环

```text
扫描工序任务 + 扫描本人
  → PENDING 工序：正式开工
  → IN_PROGRESS 工序：登记完工
  → 等待同订单其他工序全部完成
  → 扫描最后工序：提交生产报工
  → 自动生成 PENDING 完工检验
```

- 每次成功动作后更换请求编号；接口失败或离线时保留原请求编号，重试不会重复形成事实。
- 离线状态只保留本地草稿，不后台静默同步，也不写生产、质量或库存表。
- 工序事件和生产报工记录 `DESKTOP_FORM` 或 `MOBILE_SCAN` 来源；系统生成任务事件记录为 `SYSTEM`。
- 移动链路显式传入工序版本和生产订单版本，过期页面、数量越界、状态变化和并发写入均由后端拒绝。
- 既有桌面表单默认仍使用 `DESKTOP_FORM`，本切片不改变桌面执行语义。

## 数据、契约与入口

- Flyway：`V53__add_mobile_production_reporting_evidence.sql`
- OpenAPI：工序动作增加 `source`、`operatorBadge`；生产报工增加 `source`、`operationTaskId`、`operatorBadge`，响应返回任务与来源证据。
- 正式页面：`/production/mobile-operations/reporting-scan`
- BFF：`GET/POST /api/production/mobile-reporting`
- 页面数据统一经 `src/services` 访问，不直连数据库、Broker 或设备。

## 未纳入范围

- 不包含自动设备报工、专用 PDA SDK、摄像头扫码、后台离线同步或独立移动服务。
- 不包含工序检验、返工返修、报废、不合格评审，以及移动端的完工检验和成品入库。
- 不把标签补打页视为已完成；条码身份、模板版本、打印责任和补打审计应由后续独立切片闭环。
