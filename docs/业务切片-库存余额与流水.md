# 业务切片：库存余额与不可变流水

## 目标与业务所有权

本切片由 `warehouse` 模块拥有库存事实，为仓库人员提供库存余额查询和受控事务过账，并通过公开的 `StockPositionProvider` 向计划模块提供物料库存位置。计划模块只能读取并冻结供给快照，不能直接修改库存表。

库存余额的唯一维度为：租户、仓库、库位、物料、批次和质量状态。当前数量拆分为现存量、已分配量、冻结量与可用量；只有 `AVAILABLE`（合格）库存形成可用量，`INSPECTION`（待检）和 `BLOCKED`（冻结）库存的可用量为零。

## 已实现范围

- 仓库、库位、库存余额和库存流水的 PostgreSQL/Flyway 模型。
- 库存余额分页、搜索、质量状态与仓库筛选、详情和参考数据 API。
- 入库、出库、分配、取消分配、冻结和解冻六类库存事务。
- 每笔事务保存责任人、工作区、请求编号、原因、发生时间和三类数量的变动前后值。
- `X-Request-Id` 幂等、乐观版本检查、租户隔离、角色门禁和数量边界校验。
- 前端真实 API Adapter、同源 BFF、列表选择/导出/排序/完整分页、余额详情、流水证据和事务弹窗。
- MRP 运算准备按物料冻结现存、分配、冻结、可用数量及余额数，不再把库存位置整体标为缺失。

## 状态与规则

- 库存余额不提供直接覆盖接口，所有数量变化必须经过不可变流水。
- 错误流水不得删除或改写，使用对应的反向事务更正，并填写原因。
- 出库与分配只允许作用于合格库存。
- 现存量、已分配量、冻结量不得为负，已分配量与冻结量之和不得超过现存量。
- 客户端必须提交预期版本；版本落后时返回冲突并要求刷新。
- 相同租户内相同请求编号只过账一次；请求编号复用于其他余额时返回冲突。
- 当前本地开发用户以 `ADMIN` 成员身份验证跨模块纵向切片；正式角色配置仍由后续身份权限切片收口，不把前端按钮隐藏当作授权边界。

MRP 计划接收、提前期、完整净需求展开和建议转单已由后续切片完成；本文件继续作为 V10 库存事实模型与不可变流水边界的设计依据。
