# 业务切片：暂估应付（GR/IR）

> 文档状态：已实现并通过测试
> 适用阶段：C 阶段财务闭环增强
> 模块归属：finance（应付子域）
> 迁移：V31
> 前置切片：采购收货与来料检验、采购应付发票与付款核销、会计期间与关账

## 0. 设计立场

面向普通制造企业，解决最常见的"货到票未到"账务问题：月末采购已入库但供应商发票未到，需要按采购订单单价暂估入账，下一次月末结账时统一冲回并重提。本切片采用中小企业最常用的**月初冲回法（月度滚调）**，不做逐笔收货匹配、不做部分冲回、不引入总账凭证模块，保持操作三步以内：

1. 月末运行暂估 → 系统自动冲回上期暂估，按当前已收货未开票余额生成新暂估单。
2. 发票到达 → 在现有应付发票模块正常登记，不与暂估单逐笔关联。
3. 暂估单有误 → 在关账前手动全额冲回。

不做审批流、不做税务发票核验、不生成会计凭证（总账凭证模块为后续规划）。暂估金额为**不含税净额**，进项税以实际发票认证时为准。

## 1. 业务对象与事实所有权

| 对象 | 所有者模块 | 说明 |
|---|---|---|
| 采购收货合格数量 | procurement | 已存在，`PurchaseOrderLineEntity.receivedQuantity` |
| 采购订单单价 | procurement | 已存在，`PurchaseOrderLineEntity.unitPrice` |
| 应付发票及开票数量 | finance | 已存在，按 `purchase_order_line_id` 聚合 |
| 暂估单（GR/IR Accrual） | finance | 本切片新增，月末暂估事实 |
| 会计期间 | finance | 已存在，期间守卫复用 |

暂估单金额 = Σ（订单行累计合格收货数量 − 该订单行累计已开票数量）× 订单行单价，不含税。数量取 4 位小数，金额取 2 位小数 HALF_UP。

## 2. 状态机

```
POSTED ──(被下期暂估运行自动冲回)──→ REVERSED
POSTED ──(手动冲回)──→ REVERSED
```

- `POSTED`：暂估单已生成，代表期末暂估应付余额。
- `REVERSED`：暂估单已被全额冲回（自动或手动），不可再修改。

不设 DRAFT：暂估运行是原子操作，预览与提交分离；一旦提交即 POSTED。

## 3. 关键流程

### 3.1 月末暂估运行

1. 财务人员选择会计年/月（默认当前月），系统预览将生成的暂估明细。
2. 提交后：
   - 期间守卫校验目标月份为 OPEN。
   - 幂等校验：同一租户同一年月若已有 POSTED 暂估单，直接返回已有单（不重复生成）。
   - 若存在上期 POSTED 暂估单，在**同一事务**内将其标记为 REVERSED（冲回日期记为本次运行日期），并写入 `REVERSE_PRIOR` 事件。
   - 遍历所有有合格收货的采购订单，对每个订单行计算 `未开票数量 = receivedQuantity − Σ invoiceQuantity`，若 > 0 则生成暂估行。
   - 写入暂估单头（状态 POSTED）、暂估行、`ACCRUE` 审计事件。
3. 若本期所有订单行均已票完，新暂估单总额为 0：仍生成一张 POSTED 的暂估单（金额为 0），作为"本月无暂估余额"的审计证据，同时冲回上期。

### 3.2 发票到达

- 不修改现有应付发票流程。发票登记后，该订单行的"已开票数量"增加，下一次月末暂估运行时自然减少暂估余额。
- 不做发票与暂估单的逐笔勾稽（SMB 场景下月度滚调已足够，逐笔匹配属于大型企业 GR/IR 清算功能）。

### 3.3 手动冲回

- 对 POSTED 状态的暂估单，可手动全额冲回（录错、重复运行等场景）。
- 冲回日期必须在 OPEN 期间，冲回原因至少 4 个字符。
- 冲回后状态 REVERSED，不可撤销；如需重新暂估，再次运行月末暂估即可（会重新生成新单）。

## 4. 权限

- 写入操作（运行暂估、手动冲回）需要 `ADMIN` 或 `FINANCE_MANAGER` 角色，与应付发票保持一致。
- 查询对所有已登录用户开放（数据范围按租户边界）。
- 后端 `@CurrentWorkspaceAccess` 注入权限，前端按钮不做角色隐藏（后端 403 是唯一可信边界）。

## 5. 幂等与并发

- 月末暂估运行通过 `X-Request-Id` 幂等：重复提交同一请求 ID 返回已生成的暂估单。
- 同租户同期暂估通过 `pg_advisory_xact_lock(hashtextextended('grir-accrual:' + tenant + ':' + year + '-' + period, 0))` 加事务级业务锁，防止并发运行。
- 暂估单头带 `@Version` 乐观锁。
- 数据库唯一约束 `(tenant_organization_id, fiscal_year, fiscal_period)` 保证同期只有一张暂估单。

## 7. OpenAPI 契约

- `GET /api/v1/finance/grir-accruals?page=&size=&year=&status=` — 分页列表
- `GET /api/v1/finance/grir-accruals/{id}` — 详情（含行）
- `GET /api/v1/finance/grir-accruals/preview?year=&period=` — 预览本次将暂估的明细（不落库）
- `POST /api/v1/finance/grir-accruals/run` — 运行暂估（body: `{fiscalYear, fiscalPeriod, accrualDate?, note?}`）
- `POST /api/v1/finance/grir-accruals/{id}/reverse` — 手动冲回（body: `{reversalDate, reason}`）

错误码：403 无权限、404 不存在、409 PERIOD_CLOSED（期间已关账）、422 业务校验失败。

## 8. 验收条件

1. 月末运行暂估：有收货未开票的订单行出现在暂估单中，金额 = 未开票数量 × 订单单价。
2. 再次运行同一月：返回已存在的暂估单，不生成重复数据（幂等）。
3. 下月运行暂估：上期暂估单自动变为 REVERSED，新单按当前余额生成。
4. 全部开票后运行：生成 0 元暂估单，上期被冲回。
5. 手动冲回：POSTED → REVERSED，原因与日期记录在案；重复冲回被拒。
6. 关账期间：运行暂估或冲回返回 409 PERIOD_CLOSED。
7. 无权限角色：写入操作返回 403。
8. 前端工作台可查看暂估列表、详情、预览、运行、冲回，覆盖加载/空数据/失败/无权限/提交中状态。
9. 后端集成测试覆盖以上场景，前端 tsc/eslint/vitest/build 通过。
