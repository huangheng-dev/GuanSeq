# GuanSeq 整体项目进度重基线

> 审计日期：2026-08-28  
> 审计口径：完整产品地图、真实业务闭环、工程质量、开源发行运维、现场与高级能力  
> 结论：A—D 已选核心里程碑为 100%；R0 开源预览发行基线已经闭环，完整 GuanSeq 项目综合进度约为 **57%（合理波动范围 53%—62%）**，尚余约 **43%**。

## 1. 为什么此前是 100%，现在整体是 57%

此前的 100% 只回答“已经承诺的 A—D 核心纵向切片是否闭环”，其分母是业务底座、第一条制造主闭环、反向实物流、关键移动作业和设备开源工程切片。这些范围已经完成，因此该里程碑仍保持 100%。

本次重新把分母扩展为整个仓库声明的产品目标，包括 236 条产品路径的真实化、正式开源发行、生产部署和运维、不同安装实例的现场验收、AI 与按规模演进能力。两个比例回答的问题不同，不能相互替代。

## 2. 可核验事实

- 产品地图由 `src/lib/product-navigation.ts` 统一生成，共 12 个一级区域、123 个二级模块、101 个三级页面，合计 236 条独立路径。
- 正式页面注册表 `src/lib/backend-page-registry.ts` 当前包含 51 条真实后端路径，占 236 条路径的 **21.6%**；新增计入的是已经具备数据库、OpenAPI、后端授权、审计与前端服务接入的“系统管理 → 用户管理”，不是新增页面数量冒充完成度。
- 12 条路径因所属模块明确标记为“已规划”，占 **5.1%**。
- 其余 173 条路径仍使用前端 Mock、通用业务页或目录视图，占 **73.3%**；这些路径具备产品原型和 Mock 异步语义，但不具备真实业务事实、后端授权和数据库审计能力。
- 51 条正式路径在后端不可用时由页面注册表进入失败态，不静默回退为 Mock。
- OpenAPI 当前有 178 个 `/api/v1` 路径、223 个 HTTP 操作；Flyway 有 V1—V56 迁移。接口数量不能等同于产品路径完成度，因为一条页面可能组合多个接口，同一接口也可能服务多个页面。
- 最近一次完整交付验证为：前端 49 个测试文件、140 项测试通过，lint、类型检查和生产构建通过；后端 Maven verify 的 143/143 项测试通过、0 跳过，V1—V56 在 PostgreSQL 18.4 空库执行通过。
- 已构建同版本前后端 OCI 镜像，并用最小生产 Compose 真实启动 `guanseq-web → guanseq-server → PostgreSQL`；三服务均 Healthy，只有 Web 绑定宿主回环端口，两个应用容器以非 root、只读根文件系统和降权能力运行。
- 已实际生成带 SHA-256/版本/Flyway 清单的 PostgreSQL 备份，并在随机隔离数据库恢复、核对 56 条成功迁移后清理；原数据库未被覆盖。
- GitHub 托管环境的 Verify 与 Release security 已在提交 `a2a6e01` 上通过：前端完整检查、后端 143/143 测试、浏览器生产闭环、源码/依赖/密钥/配置扫描、双镜像构建、双 SBOM 和双镜像 HIGH/CRITICAL 阻断均为成功；验证记录分别为 [Verify #33152773238](https://github.com/huangheng-dev/GuanSeq/actions/runs/33152773238) 和 [Release security #33152773233](https://github.com/huangheng-dev/GuanSeq/actions/runs/33152773233)。
- 根目录已补齐 Apache-2.0 LICENSE、NOTICE、CONTRIBUTING、SECURITY、SUPPORT、CODE_OF_CONDUCT 和 CHANGELOG，并建立版本/发布策略及 Issue/PR 模板；公开仓库已发布 [`v0.1.0-alpha.1`](https://github.com/huangheng-dev/GuanSeq/releases/tag/v0.1.0-alpha.1) 非稳定预览版，不冒充生产稳定发行版。
- 标签发布流水线 [Publish preview release #33153140642](https://github.com/huangheng-dev/GuanSeq/actions/runs/33153140642) 再次通过全部功能与安全门禁，已发布可匿名拉取的 Web/Server GHCR 镜像、两份 SPDX SBOM 和不可变发布清单；镜像分别固定为 `ghcr.io/huangheng-dev/guanseq-web:0.1.0-alpha.1@sha256:d42febd7ac9bcff9fb071f9e75303c8d42834693a56821ae841fb180ef3241ac` 与 `ghcr.io/huangheng-dev/guanseq-server:0.1.0-alpha.1@sha256:1f760dca906fa2acf5adabcd0f82bedc6dc22b6f3a155298603a6013e1ff1845`。

- 已提交 Playwright 浏览器发行冒烟：测试专用 Compose 从 PostgreSQL 18.4 tmpfs 空库执行 V1—V56 和本地种子，真实启动生产前后端镜像，以单 worker 串行覆盖开发身份登录、采购收货/IQC/采购退货、生产开工/报工/完检/入库、销售发货/销售退货，以及一次接口失败后的无重复写入恢复；本地首跑 1/1 通过，失败证据和三容器清理均已实测。

已完成：提交式 Playwright 浏览器 E2E/冒烟套件，覆盖空库初始化、开发身份登录、销售到交付、采购收货、生产报工、销售/采购退货和关键接口失败恢复；生产 OIDC/TLS 仍由具体实例验收。

仍需完成：

1. 按生产责任补齐指标、追踪、集中告警、性能基线和容量阈值，不能用健康端点替代完整可观测性。
2. 在具体安装实例完成真实 TLS、OIDC、异机备份、升级回退和业务验收；在没有实例证据前不把 Alpha 宣称为稳定生产版。

### 6.2 业务完整性缺口

- 系统管理：当前工作区用户、受控单角色和成员访问状态已形成正式页面闭环；组织层级维护、动态角色/组合权限、审批流程、系统参数、编号、审计查询、归档和集成管理尚未形成正式页面闭环。
- 质量：当前正式能力集中在来料和完工检验；过程检验、不合格处置、CAPA、追溯、量具和 SPC 仍未完成。
- 生产：在制品、派工、异常、返工返修、报废、完整批次追溯、资源与人员能力仍主要是 Mock。
- 仓储：成品入库专页、拣货/装箱/交接/POD、批次序列号、占用、冻结调整、整仓盘点和策略化作业仍未完成。
- 计划与产品：ATP、MPS、齐套、产能、高级排程、工程变更、受控文档和更完整的替代料/版本能力尚未完成。
- 财务：标准成本、材料成本、制造成本、实际成本、成本差异、成本对账和总账仍未形成完整正式闭环。
- 经营工作台与数据分析：目前没有正式后端路径，真实指标、风险、任务、通知和 BI 仍待建设。

### 6.3 明确按需、不应强行提前建设

- 每个客户真实设备或已有 MQTT Broker 的现场接入验收。
- OPC UA、自动 OEE、边缘断网缓存、远程控制和高级报警策略。
- AI 助手、知识检索、预测建议和工具调用。
- 微服务拆分、独立消息/缓存/时序平台、多区域高可用。

这些能力只有在真实现场、容量、法规或业务收益证明必要后才进入实施，不计为当前核心闭环缺陷，但属于完整长期产品尚未完成的范围。

## 7. 下一条主线

R0 **“正式开源发行基线与能力真实性治理”** 已完成预览发行闭环。下一条主线定为 **“R1 系统管理/IAM 正式化”**，先解决后续业务扩展共同依赖的组织、角色、权限、审计和系统配置，不新增误导性的 Mock 页面，也不引入未经业务证明的中间件。R1 第一项已完成：把既有工作区用户管理纳入正式页面注册表和统一失败关闭门禁。

交付顺序建议：

1. 已盘点并确认现有工作区、成员、OIDC/开发身份、租户所有权、受控角色、双版本并发和后端授权边界；既有成员管理页面已从误标 Mock 切换为正式后端并统一失败关闭。
2. **当前下一项：**以当前已执行的角色编码为输入，建立可审计的“角色权限矩阵查询”只读事实，让管理员和审计人员能够回答每个角色可执行哪些正式 API/业务动作；在没有组合权限客户证据前不开放自定义角色写入。
3. 再根据矩阵与真实客户职责分离需求决定是否进入动态角色/组合权限 ADR；若证据不足，优先实现组织层级与成员归属，不建设空壳权限引擎。
4. 后续按业务价值推进质量不合格与 CAPA、生产追溯与异常、仓储销售出库，再建设真实经营工作台和分析。
5. 真机验收由具体安装实例推进；AI 和阶段 F 继续按证据门禁立项。

当前项目已经从“工程功能完整的开发版”进入“可公开获取、可重复安装、可持续验证的开源 Alpha 预览版”；进入稳定版仍取决于横向业务真实化、生产实例验收、性能容量和可观测性证据。
