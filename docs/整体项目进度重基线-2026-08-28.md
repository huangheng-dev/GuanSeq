# GuanSeq 整体项目进度重基线

> 审计日期：2026-08-28  
> 审计口径：完整产品地图、真实业务闭环、工程质量、开源发行运维、现场与高级能力  
> 结论：A—D 已选核心里程碑为 100%；完成浏览器发行门禁后，完整 GuanSeq 项目综合进度约为 **55%（合理波动范围 51%—60%）**，尚余约 **45%**。

## 1. 为什么此前是 100%，现在整体是 54%

此前的 100% 只回答“已经承诺的 A—D 核心纵向切片是否闭环”，其分母是业务底座、第一条制造主闭环、反向实物流、关键移动作业和设备开源工程切片。这些范围已经完成，因此该里程碑仍保持 100%。

本次重新把分母扩展为整个仓库声明的产品目标，包括 236 条产品路径的真实化、正式开源发行、生产部署和运维、不同安装实例的现场验收、AI 与按规模演进能力。两个比例回答的问题不同，不能相互替代。

## 2. 可核验事实

- 产品地图由 `src/lib/product-navigation.ts` 统一生成，共 12 个一级区域、123 个二级模块、101 个三级页面，合计 236 条独立路径。
- 正式页面注册表 `src/lib/backend-page-registry.ts` 当前包含 50 条真实后端路径，占 236 条路径的 **21.2%**。
- 12 条路径因所属模块明确标记为“已规划”，占 **5.1%**。
- 其余 174 条路径仍使用前端 Mock、通用业务页或目录视图，占 **73.7%**；这些路径具备产品原型和 Mock 异步语义，但不具备真实业务事实、后端授权和数据库审计能力。
- 50 条正式路径在后端不可用时由页面注册表进入失败态，不静默回退为 Mock。
- OpenAPI 当前有 178 个 `/api/v1` 路径、223 个 HTTP 操作；Flyway 有 V1—V56 迁移。接口数量不能等同于产品路径完成度，因为一条页面可能组合多个接口，同一接口也可能服务多个页面。
- 最近一次完整交付验证为：前端 49 个测试文件、140 项测试通过，lint、类型检查和生产构建通过；后端 Maven verify 的 143/143 项测试通过、0 跳过，V1—V56 在 PostgreSQL 18.4 空库执行通过。
- 已构建同版本前后端 OCI 镜像，并用最小生产 Compose 真实启动 `guanseq-web → guanseq-server → PostgreSQL`；三服务均 Healthy，只有 Web 绑定宿主回环端口，两个应用容器以非 root、只读根文件系统和降权能力运行。
- 已实际生成带 SHA-256/版本/Flyway 清单的 PostgreSQL 备份，并在随机隔离数据库恢复、核对 56 条成功迁移后清理；原数据库未被覆盖。
- GitHub Actions 已有前后端验证；新增源码/依赖/密钥/配置扫描、双镜像构建、双 SBOM 和双镜像 HIGH/CRITICAL 阻断工作流，但本地闭环不能冒充该新工作流已在 GitHub 托管环境执行。
- 根目录已补齐 Apache-2.0 LICENSE、NOTICE、CONTRIBUTING、SECURITY、SUPPORT、CODE_OF_CONDUCT 和 CHANGELOG，并建立版本/发布策略及 Issue/PR 模板；当前仍是 `0.1.0` 开发快照，不冒充稳定生产发行版。
- 全部 236 条路径现在由统一规则唯一分类，并在导航与页面首屏显示“正式后端、Mock、规划”；对应数量为 50/174/12。
- 浏览器已通过本地真实 BFF/API/数据库链路验收正式、Mock、规划三类代表页面；首屏事实说明准确，控制台 0 错误、0 警告。
- 已提交 Playwright 浏览器发行冒烟：测试专用 Compose 从 PostgreSQL 18.4 tmpfs 空库执行 V1—V56 和本地种子，真实启动生产前后端镜像，以单 worker 串行覆盖开发身份登录、采购收货/IQC/采购退货、生产开工/报工/完检/入库、销售发货/销售退货，以及一次接口失败后的无重复写入恢复；本地首跑 1/1 通过，失败证据和三容器清理均已实测。
- AI 仍是正式规划，未接入代码；阶段 F 未启动。Modbus/MQTT 的可替换只读采集和现场验收状态机已经完成，但每个真实安装实例仍需用自己的设备或 Broker 证据完成验收。

## 4. 综合进度模型

为避免用页面数掩盖核心闭环价值，也避免用核心闭环掩盖大量 Mock，本次采用五维加权模型。它是项目管理基线，不是财务工时结算；比例保留约 5 个百分点的不确定性。

| 维度 | 权重 | 当前得分 | 加权贡献 | 依据 |
|---|---:|---:|---:|---|
| 完整产品地图真实化 | 40% | 21.2% | 8.5% | 50/236 条路径进入正式页面注册表 |
| 第一条核心业务闭环深度 | 25% | 100% | 25.0% | A—D 已承诺核心切片、正反向实物流、收付款、利润、关键移动作业已闭环 |
| 工程架构与质量基线 | 10% | 90% | 9.0% | Modulith、OpenAPI、Flyway、CI、自动测试、生产构建和提交式浏览器 E2E 较完整；仍缺性能基线与托管持续验证 |
| 开源发行与生产运维 | 15% | 70% | 10.5% | 已有治理、版本边界、生产镜像/编排、配置预检、真实健康、升级回退、备份恢复演练、浏览器发行门禁与 SBOM/扫描工作流；仍缺托管门禁首跑、完整可观测平台、正式发行和实例验收 |
| 现场、AI 与高级能力 | 10% | 20% | 2.0% | 设备工程适配和验收模型已完成；真实实例验收、AI、自动 OEE、高级分析和阶段 F 未完成 |
| **整体项目** | **100%** |  | **55.0%（约 55%）** | 尚余约 45% |

## 6. 尚未完成的主要工作

### 6.1 公开发布前必须补齐

已完成：开源许可证、贡献指南、安全与支持策略、行为准则、变更日志、版本边界，以及 236 条路径的“正式后端、Mock、规划”三态真实性标识。

已完成：前后端生产镜像、最小生产 Compose、配置预检、真实 readiness、外部 TLS 边界说明、数据库升级/回退规则、备份/隔离恢复脚本与一次真实演练，以及源码/依赖/密钥/配置、SBOM 和镜像扫描工作流。

已完成：提交式 Playwright 浏览器 E2E/冒烟套件，覆盖空库初始化、开发身份登录、销售到交付、采购收货、生产报工、销售/采购退货和关键接口失败恢复；生产 OIDC/TLS 仍由具体实例验收。

仍需完成：

1. 让新增发行安全工作流在 GitHub 托管环境完成首跑并处理实际发现；按生产责任补齐指标、追踪、集中告警和容量阈值，不能用健康端点替代完整可观测性。
2. 形成明确版本的首个公开预览发行物、发布说明和安装实例验收记录；真实 TLS、OIDC、异机备份和业务验收仍由具体实例完成。

### 6.2 业务完整性缺口

- 系统管理：组织层级维护、动态角色/组合权限、审批流程、系统参数、编号、审计、归档和集成管理尚未形成正式页面闭环。
- 质量：当前正式能力集中在来料和完工检验；过程检验、不合格处置、CAPA、追溯、量具和 SPC 仍未完成。
- 生产：在制品、派工、异常、返工返修、报废、完整批次追溯、资源与人员能力仍主要是 Mock。
- 仓储：成品入库专页、拣货/装箱/交接/POD、批次序列号、占用、冻结调整、整仓盘点和策略化作业仍未完成。
- 计划与产品：ATP、MPS、齐套、产能、高级排程、工程变更、受控文档和更完整的替代料/版本能力尚未完成。
- 财务：标准成本、材料成本、制造成本、实际成本、成本差异、成本对账和总账仍未形成完整正式闭环。
- 经营工作台与数据分析：目前没有正式后端路径，真实指标、风险、任务、通知和 BI 仍待建设。

### 6.3 明确按需、不应强行提前建设

- 每个客户真实设备或已有 MQTT Broker 的现场接入验收。
- OPC UA、自动 OEE、边缘断网缓存、远程控制和高级报警策略。
- AI 助手、知识检索、预测建议和工具调用。
- 微服务拆分、独立消息/缓存/时序平台、多区域高可用。

这些能力只有在真实现场、容量、法规或业务收益证明必要后才进入实施，不计为当前核心闭环缺陷，但属于完整长期产品尚未完成的范围。

## 7. 推荐下一条主线

下一条主线应定为 **“R0 正式开源发行基线与能力真实性治理”**，而不是立刻再扩一批 Mock 页面或引入新中间件。

交付顺序建议：

1. 已先完成正式页面契约稳定性第一项：修复 V48 销售退货状态扩展未同步到 OpenAPI、销售订单和应收前端契约的问题，并用前后端契约测试、完整门禁及真实页面回归固化。
2. 已完成开源治理文件和版本/发布边界，并让全部 236 条路径在界面上准确显示“正式后端、Mock、规划”三态。
3. 已建立可重复的生产容器部署、升级/回退、备份恢复、健康/请求日志基线和安全扫描工作流；完整指标、追踪与集中告警仍按实例责任补齐。
4. 已提交浏览器 E2E 冒烟套件，把第一条主闭环、反向实物流和关键失败恢复固化为发行门禁。
5. **当前下一项：**在 GitHub 托管环境触发验证与发行安全工作流首跑，处理真实发现并准备首个公开预览发行物；该托管首跑不能由本地结果冒充。
6. 再按业务价值替换下一批 Mock：优先系统管理/IAM、质量不合格与 CAPA、生产追溯与异常、仓储销售出库，随后建设真实经营工作台和分析。
7. 真机验收由具体安装实例推进；AI 和阶段 F 继续按证据门禁立项。

完成 R0 后，项目才适合从“工程功能完整的开发版”进入“可公开发布、可重复安装、可持续升级的开源预览版”。
