# 业务切片：工艺路线版本

> 状态：已实现并通过自动化验证  
> 领域归属：产品与工艺（`product` 模块）  
> 对应页面：`/product/routings/list`

## 业务目标

产品工程师以受控版本维护自制物料的制造顺序、工作中心、标准工时、质量控制点与简要作业要求。计划和生产只能引用在需求日期已经生效的已发布版本，历史单据后续应固定引用当时版本。

本切片不包含完整工作中心主数据、人员与设备能力、工装台账、电子作业指导书附件、工程审批流或高级排程。这些能力必须在有真实业务需求后独立建设，不能以文本快照冒充完整资源模型。

## 业务对象与状态

- 工艺路线表头：路线编号、适用自制物料、用途、版本、基准数量、生效窗口、负责人和变更原因。
- 工序明细：顺序号、工序编码/名称、工作中心编码/名称、准备工时、单件工时、排队时间、质量控制点和作业摘要。
- 审计事件：创建、修改、发布、停用，记录操作者、工作区、请求编号、前后状态和关键详情。
- 状态机：`DRAFT → PUBLISHED → INACTIVE`；只有草稿可编辑，停用不可逆，需新建版本恢复供后续引用。

## 权限与数据边界

- `PRODUCT_ENGINEER`、`PLANNING_MANAGER`、`ADMIN` 可以维护、发布和停用工艺路线。
- 后端按当前用户的租户组织过滤查询和写入，不信任前端传入的数据范围。
- 物料必须属于当前租户、处于启用状态且获取方式为 `MAKE`。

## 核心不变量

- 同一租户、物料、用途与版本编码唯一。
- 同一租户、物料与用途最多存在一个已发布版本；发布新版本前必须停用旧版本。
- 路线至少包含一道工序，工序顺序由服务端按 10 递增生成。
- 同一路线内工序编码不得重复。
- 工时不得为负；每道工序的准备工时或单件工时至少一项大于零。
- 发布和停用使用乐观版本检查，冲突时拒绝静默覆盖。

## 下游使用

- 产品模块通过公开 `RoutingReferenceProvider` 提供按租户、物料和日期查询有效路线的能力。
- MRP 准备检查对自制物料增加 `ROUTING_UNAVAILABLE` 阻断证据。
- 后续生产订单生成时应固定路线版本和工序快照，不直接读取会变化的当前路线。

## 验收证据

- Flyway `V9__create_product_routing_model.sql` 是数据库事实来源。
- OpenAPI 已声明列表、详情、创建、更新、发布/停用和引用数据契约。
- PostgreSQL 集成测试覆盖租户隔离、创建、审计请求号、并发冲突、编辑、发布、发布后禁止编辑、非自制物料、重复工序、重复已发布版本和越权。
- 前端通过 `src/services` 与 BFF Route Handler 接入真实业务 API，不使用页面内 Mock。
