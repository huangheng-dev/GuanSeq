# 业务切片：库内调拨与盘点闭环

## 状态

- 状态：已完成（2026-08-28）
- 所属主线：仓储上架 → 库内调拨 → 盘点核实 → 库存事实纠偏
- 业务事实所有者：`warehouse`
- 契约事实来源：`guanseq-server/src/main/resources/openapi/guanseq-api-v1.yaml`
- 数据库事实来源：Flyway 迁移

## 目标

为仓储经理和库存控制员提供同一仓库正式库位之间的受控调拨，以及单库存余额的账面快照、实盘录入、差异审批和补偿冲回。库存余额与不可变库存流水继续是唯一库存事实，任务只保存作业状态、责任和关联证据。

## 业务边界

- 调拨只允许 `AVAILABLE`、位于活动 `STORAGE` 库位且可用量大于零的库存；目标必须是同仓库、不同的活动 `STORAGE` 库位。
- 调拨创建只占用可调拨额度，完成时才在同一事务中产生源库位 `ISSUE` 和目标库位 `RECEIPT` 两条流水，来源为 `TRANSFER_TASK`。
- 盘点以一个库存余额为最小对象，创建时冻结账面数量、已分配量、冻结量和余额版本的业务快照，不锁死数据库或阻止正常业务。
- 实盘录入和差异审批都要求余额版本仍与快照一致；期间发生任何库存变动时明确返回冲突，用户必须取消旧任务并重新盘点。
- 盘盈产生 `RECEIPT`，盘亏产生 `ISSUE`，零差异不产生库存流水；差异审批不能让现存量低于已分配量与冻结量之和。
- 错误调拨和错误盘点调整不得删除原流水，只能用方向相反的补偿流水冲回。
- 不实现跨仓运输在途、整仓盘点计划、盲盘、复盘抽样、容器/LPN、批次拆并、序列号或 PDA 离线数据库。

## 状态机

### 调拨任务

```text
OPEN ──完成调拨──> COMPLETED ──冲回──> REVERSED
  └──取消──> CANCELLED
```

### 盘点任务

```text
OPEN ──录入实盘──> COUNTED ──差异审批──> APPROVED ──冲回调整──> REVERSED
  └──────────────取消──────────────> CANCELLED
COUNTED ─────────取消──────────────> CANCELLED
```

## 权限、责任与并发

- 调拨与盘点执行角色：`WAREHOUSE_MANAGER`、`INVENTORY_CONTROLLER`、`ADMIN`。
- 后端授权是唯一可信边界；前端隐藏按钮不构成授权。
- 每个创建、录入、审批、取消和冲回动作记录租户、工作区、操作者、时间、请求编号、前后状态和原因。
- 所有高风险命令使用 `X-Request-Id` 幂等；任务使用乐观版本，过账时以固定顺序锁定相关库存余额。
- 同一源余额的开放调拨总量不得超过可用量；存在开放调拨时不能创建盘点，存在开放或已录入盘点时不能创建或完成该余额的调拨。

## 正式页面

- `/warehouse/inventory-operations/transfers`：调拨任务创建、完成、取消、冲回与流水证据。
- `/warehouse/counts`：盘点快照、实盘录入、差异审批、取消、冲回与责任证据。
- 两个页面均通过 `src/services` 和同源 BFF 访问正式业务 API，覆盖加载、空数据、无权限、校验失败、接口失败、提交中、离线和并发冲突状态。

## 验收条件

1. 合法库存与同仓目标库位可创建调拨，开放任务占用额度，完成后数量守恒并形成两条流水。
2. 重复请求不重复建单或过账；超量、跨仓、同库位、质量状态错误、陈旧版本和无权限请求被后端拒绝。
3. 盘点任务保存不可变账面快照，实盘数量可录入，差异只能审批后形成一条调整流水。
4. 盘点期间余额改变时，录入或审批明确冲突，不静默覆盖。
5. 开放/已录入任务可取消；已过账任务只能以补偿流水冲回。
6. 自动化测试、真实 PostgreSQL 迁移、生产构建和桌面浏览器主路径全部通过后才将状态改为“已完成”。
