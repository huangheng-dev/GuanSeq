# 业务切片：只读角色—权限矩阵

> 状态：已实现并完成本地自动化验证  
> 日期：2026-08-28  
> 决策依据：[ADR-0005 工作区成员与角色管理](./adr/0005-工作区成员与角色管理.md)

## 1. 业务目标

当前工作区管理员需要回答“每个受控内置角色可以执行哪些已经接入后端的业务动作”，不能继续依赖散落代码、Mock 复选框或外部身份提供者角色。本切片由 `identity` 模块提供只读目录，把现有 13 个受控角色和 52 个后端显式角色门禁按 11 个业务分组呈现。

矩阵是授权透明度能力，不是动态权限引擎。业务 API 的后端校验仍是唯一可信边界。

## 2. 对象与数据所有权

- `WorkspaceRoleCatalog`：13 个可分配的工作区内置角色，与成员管理复用同一目录。
- `WorkspacePermission`：后端显式角色门禁的动作编码、业务分组、说明、风险和允许角色。
- `WorkspaceRolePermissionPage`：当前工作区上下文下的只读目录 DTO。
- 数据所有者是 `identity` 模块；目录由代码和 OpenAPI 管理，不新增数据库表或 Flyway 迁移。
- 48 个业务权限角色集合通过自动化测试与各应用服务实际使用的私有角色集合逐项比对；其余 4 项是身份治理和会计期间的专门规则。

## 3. 权限与范围

- `GET /api/v1/identity/role-permissions` 仅允许当前工作区 `ADMIN`。
- 未认证返回 401，非管理员返回 403；前端在服务不可用或无权限时失败关闭，不回退到 Mock。
- 矩阵只表达显式角色门禁。租户、工作区、对象状态、本人范围、仓库/工厂范围、并发版本、幂等和字段校验仍由具体业务用例执行。
- 外部 OIDC 组或角色不会写入或覆盖贯序目录。
- 读取目录不修改业务事实，因此不建立状态机、乐观锁或审计写事件。

## 4. 页面与失败恢复

`/settings/roles` 使用专用只读工作台和同源 BFF：

- 展示角色数、受控动作数、业务分组数和关键动作数；
- 支持按角色、业务分组和动作关键字筛选；
- 展示目录版本、权限编码、风险和允许角色；
- 支持人工刷新；失败保留后端消息和请求编号，可重试；
- 不提供新建角色、勾选授权、保存、删除或成员分配入口。

## 5. 非目标

- 自定义角色、组合角色、岗位继承和职责分离审批；
- 组织、工厂、车间、仓库等动态数据范围；
- 字段级权限和敏感字段脱敏策略配置；
- IdP 角色同步或自动用户生命周期；
- 把只读矩阵宣称为完整 IAM。

当真实客户提出组合角色、字段权限、数据范围或职责分离的可验证需求时，再按 ADR-0005 的退出条件创建新的权限模型 ADR。

## 6. 验收证据

- OpenAPI 明确定义只读端点、响应结构和 401/403。
- 目录测试锁定 13 个角色、52 个动作、管理员覆盖和 48 个业务服务角色集合一致性。
- PostgreSQL/Testcontainers 集成测试覆盖管理员成功、未认证、普通角色拒绝，并回归成员并发与审计治理。
- 前端 Zod 契约、正式页面登记、能力成熟度和失效关闭测试通过。
- 浏览器发行冒烟进入 `/settings/roles`，核对正式后端成熟度、系统管理员、52 项动作和无授权写入口。
