# ADR-0002：统一前端 UI 基础库

- 状态：接受
- 日期：2026-08-20
- 决策人：GuanSeq 产品负责人、Codex
- 关联需求/问题：全站表单、下拉、表格、分页、弹窗和反馈控件长期由页面自行实现，视觉与交互状态持续漂移
- 取代：无
- 被取代：无

## 背景与问题证据

GuanSeq 已使用 Next.js、React 与 TypeScript 建立应用框架，但尚未采用统一的 UI 组件基础库。当前公共样式集中在 `src/app/globals.css`，文件约 185 KB、1945 行；下拉选择、复选框、弹窗、抽屉、分页、按钮和表单控件主要由项目自行实现，独立业务页面还存在重复结构。

这导致以下可复现问题：

- 同类控件在不同页面具有不同的尺寸、圆角、悬停、焦点和禁用反馈；
- 修复一个交互状态需要同时修改多个页面选择器；
- 自制下拉和覆盖层需要重复维护定位、键盘、焦点、门户和无障碍行为；
- 新页面容易复制旧样式并继续扩大差异；
- 全局 CSS 已难以清晰区分基础控件、业务组件和页面布局。

## 决策驱动因素

- 制造业 ERP/MES 页面需要完整的表格、表单、选择、日期、分页、弹窗、抽屉、树和状态反馈能力；
- 简体中文桌面工作台需要较高信息密度，同时保留 GuanSeq 圆润、克制的品牌风格；
- 必须支持 Next.js App Router、React 与 TypeScript；
- 页面开发应优先组合稳定组件，不继续重复实现通用交互；
- 迁移必须保留现有路由、业务逻辑、服务契约和可访问性基线。

## 候选方案

### 方案 A：继续维护自制控件

不增加依赖，但需要持续承担控件状态、无障碍、浏览器兼容和视觉一致性的全部维护成本，无法解决当前重复实现问题。

### 方案 B：采用 shadcn/ui 与 Tailwind CSS

组件源码归项目所有，定制自由度高，但仍要求团队自行维护组件源码和大量样式组合，与“减少自行编写和维护通用 UI”的目标不一致；同时会新增一套样式体系并扩大迁移面。

### 方案 C：采用 Ant Design，并建立 GuanSeq 封装层

提供覆盖企业管理系统主要场景的成熟控件、主题令牌和 Next.js App Router 接入方式。页面不直接散用库组件，而是通过 GuanSeq 主题和 `src/components/ui` 封装层使用，以控制品牌、升级边界和统一默认行为。

## 决策

选择方案 C：

- Ant Design 作为唯一通用 UI 组件基础库；
- 通过根级 Provider 配置简体中文、主题令牌、控件尺寸、圆角、颜色、悬停、焦点与弹层容器；
- 在 `src/components/ui` 建立 GuanSeq 基础组件出口，业务页面优先依赖该层；
- 保留现有导航、页面布局、品牌资产、业务组件、服务层和领域契约；
- 按“建立底座 → 迁移公共页面 → 迁移独立页面 → 验证 → 删除对应旧实现”的顺序渐进迁移；
- 同一种通用控件迁移完成后，不长期保留自制实现和 Ant Design 实现两套路径；
- 页面专属 CSS 只负责业务布局与特殊可视化，不重新定义通用控件状态。

本决策不引入新的业务状态管理、数据访问方案、后端组件或部署服务。

## 后果

### 正面

- 表单、下拉、复选框、表格、分页、弹窗和抽屉获得统一行为与无障碍基础；
- 品牌视觉通过主题令牌集中调整，不再逐页覆盖；
- 新页面能够复用统一组件，减少 CSS 继续膨胀；
- 通用控件问题可在封装层一次修复并覆盖全部页面。

### 代价与风险

- 增加前端包体积和第三方升级维护成本；
- 迁移期间新旧结构会短暂共存，必须按组件清单及时收缩；
- 直接在页面中任意覆盖 Ant Design 样式会重新造成漂移，因此必须保持封装层边界；
- CSS-in-JS 与服务端渲染需要使用官方 Next.js Registry 接入并通过生产构建验证。

## 验证方式

- 成功指标：主要业务页面不再新增自制通用控件；相同控件的高度、圆角、颜色和状态一致；旧通用 CSS 随迁移持续减少。
- 监控证据：ESLint、TypeScript、Vitest、Next.js 生产构建全部通过；桌面与移动端浏览器检查无首屏样式闪烁；下拉、表单、弹窗、抽屉和分页完成键盘与焦点验收。
- 验收时间：每个迁移批次完成时验收，全部独立业务页面迁移后复核本 ADR。

## 退出条件与替换路径

若 Ant Design 无法稳定支持当前 Next.js/React 版本、关键制造业务控件必须大量绕过其 API、或经过两个迁移批次仍无法降低样式重复，则停止扩大使用范围。替换时保持 `src/components/ui` 的 GuanSeq 公共接口，先更换封装层实现，再逐步移除 Ant Design 依赖，避免再次改写全部业务页面。
