# ADR-0005：工作区成员与角色管理

- 状态：接受
- 日期：2026-08-24
- 决策人：GuanSeq 产品负责人、Codex
- 关联需求/问题：首次初始化只能建立一个管理员，真实试点缺少受认证的后续用户开通、角色维护和访问停用能力
- 取代：无
- 被取代：无

## 背景与问题证据

ADR-0003 明确外部身份提供者只证明来访者身份，贯序内部账号、工作区成员关系和业务角色仍是授权事实。ADR-0004 只解决空正式库的首个管理员，且明确不能复用初始化入口开通普通用户。当前系统因此无法形成多用户试点的职责分工，也只能依赖人工 SQL，绕过租户边界、并发控制和审计。

现有 `identity.user_accounts` 是全局用户名事实，缺少明确租户所有权；`workspace_memberships` 只有状态和单一角色，缺少并发版本。各业务模块已经使用一组受控角色编码执行后端授权，本切片应复用这些事实，而不是新建尚无业务规则的动态权限引擎。

## 决策驱动因素

- 只有当前工作区管理员可以维护当前工作区成员；
- 用户账号必须明确归属租户，查询不能泄漏其他租户用户名或成员事实；
- 外部用户名继续精确映射内部账号，外部组和角色不自动写入；
- 成员停用必须立即阻止其进入当前工作区，但不能误停其在同租户其他工作区的合法访问；
- 角色只能来自当前后端已经执行授权的受控目录；
- 创建、编辑、停用和恢复必须具备责任人、请求编号、前后状态、原因和审计证据；
- 并发编辑不能静默覆盖，管理员不能通过当前用例修改自己的权限或停用自己。

## 候选方案

### 方案 A：把 IdP 组和角色直接映射为贯序角色

开通速度快，但会让外部目录绕过贯序的工作区、业务职责和审计边界；不同客户的组命名也无法稳定对应制造业务权限，因此不接受。

### 方案 B：立即建设动态 RBAC、岗位、权限点和数据范围引擎

长期表达力更强，但当前业务模块只识别稳定角色编码，立即建设完整权限引擎会扩大数据库、页面和迁移范围，且缺少岗位与职责分离的客户规则证据，因此不接受。

### 方案 C：当前工作区成员管理与受控角色目录

由 `ADMIN` 在当前工作区创建租户内部账号、维护显示名和一个受控角色，并停用或恢复该工作区成员关系。用户和成员各自使用乐观锁，所有动作进入审计。该方案足以支持多岗位试点，并为后续动态权限模型保留清晰替换边界。

## 决策

选择方案 C：

- 为 `identity.user_accounts` 增加不可为空的 `tenant_organization_id` 和乐观锁版本；历史数据从已有工作区成员关系回填，若同一账号已跨租户关联则迁移明确失败并要求先治理，不做任意归属；
- 为 `identity.workspace_memberships` 增加 `updated_at` 和乐观锁版本；
- 新增 `/api/v1/identity/workspace-users` 查询、创建、更新和成员状态动作，只作用于当前工作区；
- 只有当前工作区角色为 `ADMIN` 的用户可以访问这些 API；前端隐藏入口不替代后端校验；
- 新建账号时用户名在全系统唯一，并固定到当前租户。已有同名账号不由当前接口自动关联，避免跨租户账号枚举和误授权；
- 当前角色目录固定为已经由业务模块执行授权的编码：管理员、销售、计划、采购、产品、生产、质量、仓储、库存和财务岗位；本切片不创建自定义角色或权限点；
- 编辑同时校验用户版本和成员版本；停用/恢复校验成员版本并要求原因；冲突返回 409；
- 管理员不能修改自己的显示名、角色或成员状态，避免当前会话自锁；个人资料由独立用例负责；
- 停用只改变当前工作区成员关系，不改变全局认证账号状态，也不影响同租户其他工作区成员关系；
- 动作分别记录 `USER_PROVISIONED`、`WORKSPACE_MEMBER_UPDATED`、`WORKSPACE_MEMBER_DEACTIVATED` 和 `WORKSPACE_MEMBER_ACTIVATED` 审计事件。

本决策不提供公司、工厂和工作区层级的创建、移动或停用，不提供密码管理，不自动发送邀请邮件，也不建设动态权限点、岗位或审批流。

## 后果

### 正面

- 首个管理员可以在不执行 SQL 的情况下建立真实试点岗位账号；
- 租户、工作区和角色授权事实继续由后端独立控制；
- 停用成员不会误伤其在其他工作区的合法访问；
- 双版本与审计能证明谁在何时以何原因改变了显示名、角色或访问状态。

### 代价与风险

- 每个成员当前只有一个基础角色，不能表达组合权限和字段级权限；
- 用户名仍是全系统唯一，跨租户复用同一个自然人账号需要后续受控平台用例；
- 不自动通知 IdP 或发送邀请，身份负责人仍需在外部目录建立同名主体；
- 组织结构和自定义角色页面仍保持规划/Mock 状态，不能宣称完整 IAM 已完成。

## 验证方式

- 真实 PostgreSQL 验证迁移回填、租户非空约束、唯一约束和乐观锁；
- 集成测试覆盖管理员成功、无认证、非管理员、跨工作区不可见、重复用户名、非法角色、自我修改、停用/恢复、过期版本和审计；
- 前端覆盖加载、空数据、无权限、接口失败、校验失败、提交中和并发冲突；
- OpenAPI、lint、类型检查、自动化测试和生产构建全部通过。

## 退出条件与替换路径

当真实客户需要组合角色、岗位继承、字段权限、数据范围或职责分离审批时，以新的权限模型 ADR 取代受控单角色目录。迁移时保留现有角色编码兼容映射、成员状态、用户租户归属和全部审计证据，不让外部 IdP 角色成为业务事实来源。
