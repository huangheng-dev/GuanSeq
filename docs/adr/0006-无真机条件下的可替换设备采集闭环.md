# ADR-0006：无真机条件下的可替换设备采集闭环

- 状态：接受
- 日期：2026-08-26
- 决策人：GuanSeq 产品与工程团队
- 关联需求/问题：开源用户应能在没有真实设备时完成开发验证，取得设备后无需重写采集链路即可直接接入
- 取代：无
- 被取代：无

## 背景与问题证据

GuanSeq 已完成设备台账和维护业务闭环，但当前没有可供开发联调的真实机器。此前的设备采集门禁把真实厂商资料同时作为“开始开发”和“现场启用”的前置条件，这能避免伪集成，却会让开源贡献者和没有硬件的用户无法验证协议、数据质量、权限及页面链路。

设备采集现场需求包已经给出一台设备、Modbus TCP 和 8 个只读点位的工程假设。容量评审显示首机平均约 1.21 样本/秒，不足以证明需要新增 Broker、时序数据库、独立服务或边缘部署单元。

## 决策驱动因素

- 无硬件开发环境必须和真实设备使用同一协议链路，不能维护两套实现。
- 用户取得真实设备后应只替换连接与点位配置，不修改核心代码和数据模型。
- 仿真数据必须可识别、可隔离，不能冒充现场运行证据。
- 当前规模应继续复用模块化单体与 PostgreSQL。
- 首个切片只读，不开放远程控制或安全联锁写入。

## 候选方案

### 方案 A：等待真实设备后再开发

风险最低，但开源用户无法复现，协议和数据模型问题会延后暴露，也无法建立持续集成门禁。

### 方案 B：前后端返回静态 Mock 数据

开发成本低，但不会经过真实 Modbus TCP 帧、超时、异常响应和网络断连，未来接入真机时需要重写，且容易误导用户。

### 方案 C：生产适配器连接外部协议仿真端点

仿真器只扮演设备，生产和仿真使用同一个连接配置、协议适配器、归一化、存储、API 和页面。真实设备到位后只替换端点与点位映射。

## 决策

选择方案 C。

第一阶段在现有 `equipment` 模块中实现协议无关的连接、点位、运行状态和样本模型，以及一个只读 Modbus TCP 适配器。开发/测试仿真器位于业务系统之外，只使用标准协议响应，不进入生产依赖或生产数据。

当前不增加 EMQX、TimescaleDB、独立设备接入服务或强制边缘代理。直接连接模式是首期默认；现场网络隔离、串口/专有驱动或可靠离线缓存得到真实证据后，再评估可选边缘连接器。

这不是排除 MQTT。对于原生发布 MQTT 的真实设备或现场网关，后续适配器应连接用户已有的外部 Broker，把消息归一化到同一连接、点位、质量和样本模型；只有连接规模、离线会话或运维责任证明必要时，GuanSeq 才提供或推荐可选 Broker 部署，不把 EMQX 变成所有开源安装的强制依赖。

## 后果

### 正面

- 没有硬件也能验证真实协议帧和端到端链路。
- 真机接入与仿真验证共享同一实现，降低替换风险。
- 开源贡献者可以复现成功、断连、坏质量和恢复场景。
- 保持现有部署单元最少。

### 代价与风险

- 仿真器无法证明厂商寄存器表、现场网络、安全审批和真实负载正确。
- 首版轮询器只承诺当前单实例部署；多实例并发采集需增加租约或独立执行单元后再批准。
- Modbus TCP 缺少原生鉴权，必须依赖网络隔离、只读功能码、后端权限和审计。

## 验证方式

- 成功指标：同一 Modbus TCP 适配器可以读取外部仿真端点，并通过连接、点位、样本、API 和页面形成闭环。
- 异常指标：超时、异常响应、越界、断连和恢复拥有稳定状态与自动化测试。
- 安全指标：跨租户/工作区访问被拒绝，普通岗位不能创建、启停或测试连接，浏览器不直连设备。
- 替换指标：从仿真器切换到真机只需要更新端点和点位配置。

## 退出条件与替换路径

当真实现场证明需要串口/厂商驱动、网络隔离、长时间离线缓存、多网关会话，或持续写入和保留规模超过现有 PostgreSQL 的实测能力时，创建新 ADR，评估可选边缘连接器、Broker、时序存储或独立接入服务。现有统一样本和业务 API 保持兼容，协议执行部分通过适配接口替换。
