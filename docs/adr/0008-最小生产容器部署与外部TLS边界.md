# ADR-0008：最小生产容器部署与外部 TLS 边界

- 状态：接受
- 日期：2026-08-28
- 决策人：GuanSeq 维护者
- 关联需求/问题：开源安装缺少可重复生产打包、健康依赖、备份恢复和发行安全门禁
- 取代：无
- 被取代：无

## 背景与问题证据

仓库此前只有 PostgreSQL 本地开发 Compose，没有前后端生产镜像、最小生产编排或自动镜像安全门禁。安装者必须自行猜测 Node/Java 运行方式、端口暴露、密钥注入、健康顺序和数据恢复流程，无法重复验证同一发行物。与此同时，当前批准架构只有 Next.js、Spring Boot 模块化单体和 PostgreSQL；为部署方便提前加入缓存、消息、Broker、Kubernetes 或独立可观测平台会扩大运行成本并违反技术门禁。

## 决策驱动因素

- 单工厂和开源安装需要可重复、可审计且最小的运行单元。
- 浏览器只能访问 Web/BFF，后端和数据库不能直接暴露公网。
- 正式配置必须使用 OIDC，密钥不能进入仓库或镜像。
- Flyway 只向前，恢复不能自动破坏正式数据库。
- 构建产物需要 SBOM、依赖/密钥/配置和镜像漏洞门禁。

## 候选方案

### 方案 A：引入 Kubernetes、统一网关和完整观测栈

具备较强编排和扩展能力，但当前没有多副本、服务拆分或容量证据，部署与维护成本远超单工厂需要，并会一次引入多个未经批准组件。

### 方案 B：OCI 镜像 + Docker Compose + 外部 TLS 入口

复用现有 Docker/PostgreSQL 基线，固定 `guanseq-web → guanseq-server → PostgreSQL` 三单元。Compose 默认只把 Web 绑定到宿主回环地址，安装者使用已有 Nginx、负载均衡器或云入口完成 TLS；不把具体代理产品变成 GuanSeq 强制依赖。

### 方案 C：继续发布源码和手工启动命令

初始成本低，但不能形成可重复发行物、健康顺序、安全默认值或恢复证据，不满足开源正式版要求。

## 决策

采用方案 B：前后端使用非 root OCI 镜像，生产 Compose 只编排 Web、模块化后端与 PostgreSQL。数据库和后端只在内部网络暴露；Web 默认绑定 `127.0.0.1`，由安装环境已有的 TLS 入口反向代理。生产预检拒绝开发身份、占位密钥、非 HTTPS 公开来源、错误回调和未确认的 TLS 边界。

备份使用 PostgreSQL custom format 并生成 SHA-256、应用版本与 Flyway 数量清单；自动恢复只允许进入随机命名的隔离演练数据库，验证后删除。正式故障恢复采用“恢复到新数据库 → 验证 → 切换连接”的前向方式，不提供自动覆盖原库或伪造 Flyway 回滚。

发行 CI 生成两个镜像的 SPDX JSON SBOM，并以 Trivy 对源码、依赖、密钥、配置和镜像执行 HIGH/CRITICAL 门禁。完整指标、链路和集中日志平台仍按安装环境与容量证据接入，本决策不批准新运行时中间件。

## 后果

### 正面

- 同一镜像可在不同环境通过运行时密钥和 OIDC 配置提升。
- 默认网络和非 root/只读文件系统减少误暴露与容器越权面。
- Web readiness 真实依赖后端公开状态，Compose 可以阻止错误启动顺序。
- 备份与恢复演练形成机器可核验清单，同时保护原数据库。

### 代价与风险

- 安装者必须已有受控 Docker 主机、TLS 入口、OIDC 和备份外部存储。
- 单机 Compose 不是高可用方案；宿主、卷或单数据库故障仍需外部容灾。
- 容器基础镜像和扫描数据库会持续变化，发行门禁需要维护版本和例外记录。
- 多副本 Next.js 缓存协调、完整指标/追踪和 WAL 连续归档不在本轮范围。

## 验证方式

- 成功指标：两个镜像可构建；生产 Compose 可解析并达到健康；Web 健康端点能验证后端；备份和隔离恢复演练通过；安全工作流配置进入仓库。
- 监控证据：容器健康、平台状态、请求编号日志、备份清单、恢复演练记录和 CI SBOM/扫描结果。
- 验收时间：2026-08-28 工程基线；客户级 RPO/RTO、TLS、OIDC 和异机备份仍由每个安装实例验收。

## 退出条件与替换路径

当多副本、持续可用、独立扩缩容、法规隔离或平台运维证据证明单机 Compose 不足时，创建新 ADR 迁移到客户已有编排平台。迁移继续使用相同 OCI 镜像、外部化配置、内部网络和 PostgreSQL 恢复清单；不得因更换编排平台改变业务 API 或数据所有权。
