# ADR-0007：外部 MQTT Broker 只读接入

- 状态：接受
- 日期：2026-08-26
- 决策人：GuanSeq 产品与工程团队
- 关联需求/问题：开源用户应能连接自己选择的 MQTT Broker，且不把 EMQX 或任何 Broker 变成 GuanSeq 的强制部署依赖
- 取代：无
- 被取代：无

## 背景与问题证据

ADR-0006 已建立协议无关的连接、点位、运行状态和样本模型，并完成 Modbus TCP 生产适配器与外部仿真端点闭环。当前没有真实机器，但产品边界已经明确：原生发布 MQTT 的设备或现场网关应能通过用户已有 Broker 接入同一工作台，用户可以自行选择 Broker，GuanSeq 不强制部署内置 EMQX。

现有 Java 代码没有 MQTT 协议实现。自行用 Socket 实现 MQTT 会重新承担连接、会话、QoS、TLS、重连和协议兼容成本，无法以合理成本满足可直接替换真实 Broker 的目标。增加一个模块内客户端库是当前业务需求所需；增加 Broker、独立接入服务或消息总线则没有容量和运维证据支持。

## 决策驱动因素

- 用户可以使用 Mosquitto、EMQX、HiveMQ、云 MQTT 或其他兼容 Broker，不绑定服务端品牌。
- 浏览器只访问 GuanSeq 业务 API，不直连 Broker，也不获得用户名、密码或证书私钥。
- MQTT 与 Modbus 进入相同连接、点位、质量、当前值、有限历史和保留模型，不复制设备台账。
- 没有真实硬件时仍能用外部标准协议仿真端点验证；仿真结果不能冒充现场验收。
- 当前继续保持 Next.js、Spring Boot 模块化单体和 PostgreSQL 三个默认运行单元。

## 候选方案

### 方案 A：内置或强制部署 EMQX

能快速提供 Broker，但会增加独立部署、账号、证书、监控、备份、升级和高可用责任，也会限制开源用户已有 Broker 的选择。当前容量与离线会话证据不足以证明必要。

### 方案 B：自行实现 MQTT 协议客户端

不增加第三方依赖，但需要自行正确实现 MQTT 帧、QoS、TLS、会话、重连和边界错误，安全与维护成本不可接受。

### 方案 C：模块内使用标准 MQTT 客户端连接用户外部 Broker

只增加进程内协议客户端依赖，不增加部署单元。适配器订阅受控 Topic，把 JSON Payload 归一化到现有样本事实；Broker 品牌和部署继续由用户决定。

## 决策

选择方案 C。

`equipment` 模块增加 HiveMQ MQTT Client `1.3.17`，仅使用其公开 API 连接 MQTT 3.1.1 Broker。该库是 Apache-2.0 许可的客户端，不包含或启动 HiveMQ Broker。首个切片支持 TCP 或基于 JVM 信任库的 TLS、QoS 0/1、精确 Topic、JSON Pointer 映射、消息编号去重和可选设备时间。

Broker 凭据不写入数据库。连接只保存受控凭据引用，例如 `SHOPFLOOR_A`；服务端运行环境通过 `GUANSEQ_MQTT_CREDENTIAL_<引用>_USERNAME` 和 `GUANSEQ_MQTT_CREDENTIAL_<引用>_PASSWORD` 注入真实值。API 只返回是否配置及有管理权限时的引用名，绝不返回密码。

连接继续使用 `DRAFT → ACTIVE ↔ PAUSED` 状态机。测试必须收到每个配置 Topic 的一条有效消息；启用后复用现有受控采集调度，把消息归一化为当前值和原始样本。暂停连接时关闭本进程会话。当前采集调度仍遵守 ADR-0006 的单实例限制；多实例共享订阅或采集租约必须由部署证据另行决策。

开发工具可以提供最小标准 MQTT 仿真端点，但它不是生产 Broker 依赖，也不能用于现场运行。

## 后果

### 正面

- 开源用户可以自行选择 Broker，现有 EMQX/Mosquitto/HiveMQ/云服务均可按标准协议接入。
- MQTT 和 Modbus 共享业务模型、权限、审计、历史与保留能力。
- 密钥不进入浏览器、数据库、仓库、审计详情或截图。
- 不新增 Broker、消息总线、时序库或独立服务。

### 代价与风险

- 应用包增加 MQTT 客户端及其网络依赖，需要持续跟踪安全更新。
- 首切片只支持 JSON Payload、精确 Topic、QoS 0/1 和 JVM 默认信任库；二进制 Payload、Topic 通配、多证书租户和双向 TLS 不在范围。
- 用户 Broker 的账号、ACL、证书、保留消息和离线会话仍由部署方运维。
- 当前单实例采集限制不因增加 MQTT 而消失。

## 验证方式

- 成功指标：同一页面可建立外部 Broker 连接，完成测试、启用、采集、当前值、有限历史和暂停闭环。
- 协议指标：自动化测试经过真实 MQTT 3.1.1 CONNECT/SUBSCRIBE/PUBLISH 帧，覆盖正常消息、重复编号、无效 JSON、缺少字段、超时和断连。
- 安全指标：无权限和跨工作区访问被拒绝；密码不落库、不回传、不写日志；TLS 使用 JVM 信任库校验服务端。
- 替换指标：从仿真端点切换到用户 Broker 只更改连接、Topic、JSON Pointer 和凭据引用，不修改核心代码。

## 退出条件与替换路径

当真实现场证明需要多实例共享订阅、边缘离线缓存、二进制工业 Payload、mTLS 多租户证书、持续超过当前 PostgreSQL 能力的写入或独立扩缩容时，创建新 ADR 评估采集租约、可选边缘连接器或独立接入服务。退出时保留统一样本与业务 API，只替换协议执行和部署适配层。
