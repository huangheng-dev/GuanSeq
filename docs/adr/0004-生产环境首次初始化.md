# ADR-0004：生产环境首次初始化

- 状态：接受
- 日期：2026-08-24
- 决策人：GuanSeq 产品负责人、Codex
- 关联需求/问题：正式数据库不写入示例身份事实，而 OIDC 登录要求外部用户名先映射到贯序内部启用用户，形成首个管理员无法建立的循环依赖
- 取代：无
- 被取代：无

## 背景与问题证据

贯序只在 `local` Profile 的可重复迁移中写入示例组织、工作区和用户。正式环境正确地不包含这些数据。根据 ADR-0003，外部身份提供者只证明来访者身份，JWT 用户名必须精确映射到 `identity.user_accounts` 中的启用用户；工作区和 `ADMIN` 角色也必须是贯序内部事实。

当前受保护 API 都要求已有内部用户，因此新生产库没有任何身份能够调用用户或组织维护能力。人工执行客户专属 SQL 会绕过业务校验、请求编号和审计边界，也难以保证并发、可重复执行和运维证据。

## 决策驱动因素

- 初始化只能在明确开启时存在，默认部署必须拒绝；
- 只允许成功一次，并在数据库事实层永久关闭，不能依赖单实例内存状态；
- 两个并发初始化请求最多一个成功；
- 初始化凭据不得进入 URL、日志、响应、代码或数据库；
- 创建的公司、工厂、工作区、用户、成员关系、当前工作区和审计事件必须在同一事务内提交；
- 初始化之后仍由 OIDC 和贯序内部权限承担日常认证授权，不形成第二套账号系统。

## 候选方案

### 方案 A：由运维人员直接执行 SQL

实现成本最低，但会绕过业务 API、输入校验和审计，容易在客户编码、外部用户名或并发操作上产生不可追踪差异，因此不接受。

### 方案 B：应用启动时根据环境变量自动写入首个管理员

不需要匿名端点，但只要环境变量未及时移除，每次启动都可能触发高权限写入；失败反馈和操作证据也不清晰，不适合滚动部署和多副本。

### 方案 C：显式开启的一次性初始化 API

部署人员临时注入高熵初始化令牌，通过受控 API 提交首个组织与管理员。服务在事务中锁定数据库单例状态，成功后永久标记完成；后续请求即使持有原令牌也被拒绝。该方式可以自动化、审计和并发验证，但初始化窗口内必须保护网络入口和令牌。

## 决策

选择方案 C：

- 新增 `POST /api/v1/bootstrap/initial-workspace`，只在 `GUANSEQ_BOOTSTRAP_ENABLED=true` 时注册；默认不注册；
- 请求必须在 `X-GuanSeq-Bootstrap-Token` Header 中携带至少 32 字符的高熵令牌；服务使用常量时间比较，不记录或回显令牌；
- 安全过滤器允许该路径匿名到达控制器，但初始化服务仍独立验证令牌。无效令牌返回 401；功能未开启时返回 404；
- `identity.system_bootstrap` 保存单例状态。应用事务使用悲观写锁串行化竞争请求，状态不是 `PENDING`、或库中已有身份/组织事实时返回 409；
- 成功事务创建租户公司、下属工厂、工作区、与 OIDC 声明精确匹配的启用用户、`ADMIN` 成员关系、当前工作区偏好和 `SYSTEM_BOOTSTRAPPED` 审计事件，最后将单例状态改为 `COMPLETED`；
- 初始化响应只返回新事实 ID、用户名和状态。令牌不入库；初始化完成后立即从部署密钥和环境中删除令牌，并关闭开关；
- 普通用户、后续工厂和角色维护不复用该端点，必须走后续受认证的身份管理用例。

本决策不自动从身份提供者同步组织或角色，不写入示例客户、物料、库存或业务单据，也不提供重置初始化状态的 API。

## 后果

### 正面

- 新生产库可以在不执行客户专属 SQL 的情况下建立第一组可信身份事实；
- 初始化事务具备输入校验、并发互斥、请求编号和审计证据；
- 成功后由数据库状态永久关闭，令牌泄漏不会重新初始化已有系统；
- 外部身份与内部权限边界保持不变。

### 代价与风险

- 初始化窗口存在一个以高熵令牌保护的匿名入口，部署人员必须限制网络来源并尽快关闭；
- 首个外部用户名填写错误时不能通过重复初始化修正，需要在上线前验证 IdP 声明，并通过受控运维变更处理；
- 初始化只解决首个管理员和工作区，后续用户与组织管理仍需正式业务能力；
- 数据库已经存在身份或组织事实但没有初始化完成标志时会安全拒绝，需要人工审计现状而不是自动合并。

## 验证方式

- 成功指标：空正式库中一个有效请求完整创建全部事实；无令牌、错误令牌和非法输入被拒绝；并发请求仅一个返回 201；重复请求返回 409；创建后 OIDC 同名用户可以读取工作区。
- 监控证据：Flyway 真实 PostgreSQL 迁移测试、初始化并发集成测试、OpenAPI 契约测试、安全模式测试和审计记录检查通过；日志不含初始化令牌。
- 验收时间：首个试点环境首次初始化时保留请求编号、响应摘要和关闭开关的变更记录。

## 退出条件与替换路径

当贯序具备经过正式身份认证的租户开通控制面，或部署平台提供更安全的离线一次性作业机制时，创建新 ADR 取代本决策。替换时保留 `identity.system_bootstrap` 的完成事实和已有审计，不重新开放已初始化环境，也不迁移或重写首个管理员业务事实。
