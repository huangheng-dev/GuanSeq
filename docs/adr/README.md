# GuanSeq 架构决策记录（ADR）

ADR 用来记录会长期影响系统结构、开发方式、数据边界或运维成本的决策。它不是技术调研笔记，也不是为了给已经写好的代码补理由。

## 何时必须创建 ADR

- 引入或替换框架、中间件、数据库、消息系统、存储或部署平台。
- 新增独立部署服务或拆分现有模块。
- 改变模块数据所有权、事务边界、权限模型或集成方式。
- 采用会影响大量页面或接口的公共模式。
- 接受明显技术债、兼容性限制或供应商锁定。

普通缺陷修复、局部重构、样式调整和不改变公共契约的小功能不需要 ADR。

## 状态

- `提议`：正在讨论，不能作为实施依据。
- `接受`：已经批准，后续开发必须遵守。
- `取代`：被新的 ADR 替换，保留历史原因。
- `废弃`：不再适用，但没有直接替代方案。

## 编号与文件名

使用四位连续编号：

```text
0001-模块化单体架构.md
0002-示例决策.md
```

复制 [0000-template.md](./0000-template.md) 创建新记录。已接受 ADR 不应改写历史结论；决策变化时创建新 ADR，并在新旧记录中互相引用。
