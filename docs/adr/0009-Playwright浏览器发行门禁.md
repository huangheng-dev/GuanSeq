# ADR-0009：Playwright 浏览器发行门禁

- 状态：接受
- 日期：2026-08-28
- 决策人：GuanSeq 维护者
- 关联需求/问题：R0 正式开源发行基线缺少可提交、可重复的浏览器 E2E 证据
- 取代：无
- 被取代：无

## 背景与问题证据

仓库已有前端单元测试、后端集成测试、生产构建、容器启动和人工浏览器验收，但尚无提交到仓库并在拉取请求中自动运行的浏览器测试。人工验收不能稳定发现 Web、BFF、正式 API、Flyway 空库迁移和浏览器交互之间的回归，也不能作为公开预览发行的重复证据。

第一条制造主闭环包含跨模块状态和库存事实。只检查页面可打开不足以证明采购收货、检验、生产报工、成品入库、销售发货和退货仍能通过真实产品入口协同工作。

## 决策驱动因素

- 测试必须从一次性空 PostgreSQL 数据库开始，执行全部 Flyway 迁移和受控开发种子。
- 浏览器只通过 Web/BFF/正式 API 改变业务事实，不允许测试直接写业务表。
- 写入型场景必须串行，避免共享业务状态造成伪并发和不稳定结果。
- 失败证据应保留 trace、截图、视频和 HTML 报告，成功运行不长期保留大体积产物。
- 开发身份只能验证工程链路，不能冒充生产 OIDC、TLS 或具体安装实例验收。

## 候选方案

### 方案 A：继续人工浏览器验收

零新增依赖，但不可重复、不可作为提交门禁，也无法稳定验证失败恢复和跨模块状态。

### 方案 B：只增加 API 集成测试

执行速度较快，但无法覆盖 Next.js 服务端取数、BFF 适配、浏览器表单、可访问名称和用户可见状态。

### 方案 C：Playwright Test + 一次性容器环境

增加一个开发测试框架和浏览器运行成本，以真实生产镜像、local 身份配置和 tmpfs PostgreSQL 组成隔离环境，由 Playwright 串行执行核心业务动作，并在 CI 失败时上传证据。

## 决策

采用方案 C。`compose.e2e.yaml` 是测试专用编排，启动一次性 PostgreSQL、GuanSeq Server 和 Web；数据库不挂载持久卷，测试结束后删除容器。`scripts/e2e-run.mjs` 统一负责启动、执行和清理，`playwright.config.ts` 固定 Chromium、单 worker 和失败证据目录。

首个发行冒烟用例覆盖：空库迁移后的健康状态、开发身份登录、采购收货与 IQC、采购退货出库、生产开工与报工、完工检验与入库、销售发货、销售退货处置，以及一次浏览器接口失败后保持表单并成功重试。测试数据所有权始终属于后端模块。

本决策不引入第二套业务后端，不把开发种子当生产初始化数据，也不声称覆盖真实 OIDC、TLS、外部 Broker、真机或具体客户数据。

## 后果

### 正面

- 拉取请求能够发现跨 Web、BFF、API、迁移和浏览器交互的主闭环回归。
- 每次运行从相同空库状态开始，失败不会污染开发数据库或生产卷。
- 失败产物可直接定位到页面动作、网络请求和视觉状态。

### 代价与风险

- CI 需要安装 Chromium 并构建前后端镜像，耗时高于单元测试。
- 本地完整 E2E 需要 Docker；只调试测试时可显式使用已有隔离服务。
- 单套开发身份不能替代生产身份提供方的实例验收，必须继续在运行手册中保留该边界。
- 测试依赖受控种子对象；种子或业务状态变化时需要同步更新测试意图，而不是用宽松断言掩盖变化。

## 验证方式

- 成功指标：`pnpm e2e` 在空库上完成全部迁移并通过发行冒烟；测试结束后 `guanseq-e2e` 容器全部清理。
- 监控证据：GitHub Actions `browser-e2e` 状态；失败时上传 `output/playwright/report` 和 `output/playwright/test-results`。
- 验收时间：每次拉取请求和 `main` 分支推送。

## 退出条件与替换路径

当浏览器门禁持续超过可接受的发布等待时间、Playwright 不再维护当前浏览器，或测试规模需要分片时，先用实际运行时长和失败率创建新 ADR。可将只读检查拆为并行项目、将写入闭环按独立数据库分片，或迁移到等价的受维护浏览器框架；业务断言、空库迁移和失败证据要求必须保留。
