# 业务切片：OEE 与停机证据闭环

## 1. 目标与事实边界

本切片把设备综合效率从规划页推进为可核实、可审批、可追溯的业务事实。在没有真实机器、班次排程与工序设备绑定的当前阶段，首版采用 `MANUAL_VERIFIED`（人工核实）来源：用户填写核实过的计划生产时间、理想节拍、产量和停机事件，系统统一计算可用率、性能率、质量率与 OEE，并通过提交、审核和不可变事件保留责任证据。

这不是仿真遥测推导的“漂亮数字”，也不代表现场自动采集已经完成。以后接入生产、质量、设备采集或用户已有 Broker 时，自动来源写入同一 OEE 记录模型，页面和审批证据链不需要推翻。

## 2. 业务对象与数据所有权

| 对象 | 所有模块 | 事实内容 |
| --- | --- | --- |
| OEE 记录 | equipment | 设备快照、统计窗口、计划生产分钟、理想节拍、总产量、合格产量、来源、状态和冻结指标 |
| 停机事件 | equipment | OEE 记录窗口内的开始/结束时间、原因分类、责任方、说明和持续分钟 |
| OEE 事件 | equipment | 创建、编辑、停机新增/修改/移除、提交、审核、驳回的责任人、时间、原因、请求编号和变更摘要 |
| 设备台账 | equipment | OEE 记录引用设备并冻结编码、名称、工作中心和位置快照 |

首版不直接读取或修改 `production`、`quality` 的表。生产工序任务和完工检验虽已是真实事实，但当前没有可信的设备、班次和统计窗口绑定；未来只能通过这些模块公开 API 或已批准的模块事件提供来源，不得跨模块查表拼接。

## 3. 指标口径

- 统计窗口必须结束晚于开始；计划生产分钟必须大于 0，且不得超过窗口总分钟。
- 计划生产分钟是已经扣除不纳入生产计划的休息、节假日等时间后的净计划时间。
- 停机事件必须完全位于统计窗口内，同一 OEE 记录内不得重叠；记录中的停机都发生在计划生产时间内，因此都会扣减运行时间。
- 运行分钟 = 计划生产分钟 − 停机分钟合计。
- 可用率 = 运行分钟 ÷ 计划生产分钟。
- 性能率 = 理想节拍秒 × 总产量 ÷（运行分钟 × 60）。
- 质量率 = 合格产量 ÷ 总产量；总产量为 0 时质量率为 0。
- OEE = 可用率 × 性能率 × 质量率。
- 草稿允许暂时不完整，但提交时运行分钟不得为负、总产量不得小于合格产量、性能率不得超过 100%。超过 100% 通常说明理想节拍、产量或时间口径错误，必须修正后提交。
- 同一设备已经提交或审核通过的统计窗口不得重叠，避免重复计算。

服务端使用高精度小数计算并返回百分比；数据库保存指标快照，审核通过后记录不可编辑。

## 4. 停机原因分类

首版使用稳定分类而不是自由文本冒充主数据：

- `EQUIPMENT_FAILURE`：设备故障。
- `SETUP_CHANGEOVER`：换型、换线、调机。
- `MATERIAL_WAIT`：缺料或等待配送。
- `QUALITY_HOLD`：质量等待或异常处置。
- `PERSONNEL_WAIT`：人员等待。
- `PLANNED_MAINTENANCE`：计划内保养占用净计划生产时间。
- `OTHER`：其他，必须用说明补充事实。

每条停机还记录责任方和事实说明，原因分类用于汇总，责任方用于后续改善闭环；首版不自动创建维修工单或质量处置单。

## 5. 状态与动作

状态流为：

`DRAFT → SUBMITTED → APPROVED`

审核人可以将 `SUBMITTED` 驳回为 `REJECTED`；`REJECTED` 可修改并重新提交。`DRAFT` 和 `REJECTED` 可以编辑主数据、增加/修改/移除停机事件；`SUBMITTED` 与 `APPROVED` 冻结。所有写动作要求期望版本并使用请求编号保证幂等，版本冲突返回 `409`。

## 6. 权限

- 所有当前工作区有效成员可以查看 OEE 记录。
- `MAINTENANCE_MANAGER`、`PRODUCTION_MANAGER`、`ADMIN` 可以创建、编辑、维护停机和提交记录。
- `PRODUCTION_MANAGER`、`ADMIN` 可以审核通过或驳回。
- 前端只根据服务端返回的 `canMaintain`、`canApprove` 和 `availableActions` 呈现动作；后端授权是唯一可信边界。

小型企业可能只有管理员，因此首版不强制提交人与审核人分离；责任人和请求证据仍完整记录。需要强制复核分离时，应作为可配置治理策略另立切片。

## 7. API 与界面

- `GET /api/v1/equipment/oee-records`：分页、状态和关键字查询，返回汇总指标与权限。
- `GET /api/v1/equipment/oee-records/{id}`：返回主记录、停机明细和审计事件。
- `POST /api/v1/equipment/oee-records`：建立人工核实草稿。
- `POST /api/v1/equipment/oee-records/{id}/actions`：执行 `UPDATE`、`ADD_DOWNTIME`、`UPDATE_DOWNTIME`、`REMOVE_DOWNTIME`、`SUBMIT`、`APPROVE`、`REJECT`。

`/equipment/oee` 展示来源边界、审核通过指标、记录列表、状态筛选、详情证据、草稿维护、停机登记和状态动作。空数据、无权限、加载、接口失败、校验失败和并发冲突都必须有明确状态。

## 8. 非目标与后续兼容

本切片不实现：

- 从仿真样本或稀疏遥测自动推断开停机。
- 班次日历、排班、设备与工序任务自动绑定。
- 生产/质量数量自动回填、OPC UA、边缘网关或强制部署 EMQX。
- 微停、速度损失的高频自动归因、停机原因主数据维护、OEE 趋势仓库。
- 自动创建维修/质量工单、预测维护、远程控制。

后续来源类型可增加 `PRODUCTION_CONFIRMED`、`TELEMETRY_CONFIRMED` 或 `MIXED_VERIFIED`，但必须保留原始来源引用、质量状态与人工核实责任，不允许无证据覆盖已经审核的 OEE 事实。

## 9. 验收条件

- 建立一条人工核实记录，登记两条不重叠停机，系统计算四项指标且详情与列表一致。
- 修改草稿后版本递增；重复请求幂等，旧版本写入返回冲突。
- 越界、重叠、负运行时间、合格数大于总数和提交时性能率超过 100% 均由后端拒绝。
- 提交后主数据与停机冻结；生产经理或管理员可审核或驳回，驳回后可修正并重新提交。
- 同一设备的已提交/已审核统计窗口不能重叠。
- 非维护角色只能查看；非审核角色不能审核。
- 页面明确显示“人工核实”而不是“自动采集”，且后端不可用时不回退静态 JSON。
- Flyway、OpenAPI、后端集成测试、前端契约测试、lint、类型检查、生产构建和桌面/窄屏浏览器验收全部通过。
