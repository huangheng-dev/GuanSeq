# GuanSeq 版本与发布策略

## 1. 当前状态

仓库当前版本是 `0.1.0-alpha.1` 开源预览版。它用于公开评审、持续开发和受控试点准备，不是稳定生产发行版。页面上的“正式后端”只表示该 URL 已接入受控业务 API，不代表整套产品、部署环境或工厂现场已经达到生产就绪。

## 2. 版本规则

版本号采用 `主版本.次版本.修订版本`：

- `0.x`：开发期。允许发生不兼容调整，但必须在更新日志、迁移和发布说明中明确。
- `1.x`：首个稳定系列。主闭环、部署、升级、备份恢复、安全基线和开源治理全部通过发布门禁后才能进入。
- 主版本：稳定期的不兼容 API、配置、数据或扩展点变更。
- 次版本：向后兼容的新能力。
- 修订版本：向后兼容的缺陷和安全修复。

预发布版本使用 `-alpha.N`、`-beta.N` 或 `-rc.N`。正式标签、前端 `package.json` 和后端 Maven 版本必须一致；未完成同步时不得对外宣称发布。

## 3. 发布门禁

每个候选版本至少满足：

1. 能力清单逐项标记“正式后端、Mock、规划”，没有把原型冒充完成项。
2. 前端 lint、类型检查、自动化测试和生产构建通过；后端单元/集成测试、模块边界、OpenAPI 和打包通过；浏览器发行冒烟在一次性空库和生产镜像上通过。
3. Flyway 迁移只向前演进，并验证全新安装和受支持版本升级。
4. 发布说明列出功能、修复、已知问题、配置变化、迁移步骤、回退边界和安全影响。
5. 稳定版还必须验证生产部署、监控、备份恢复、身份接入、最小权限和至少一条端到端试点主闭环。

生产候选的配置、健康、TLS 边界、备份恢复与升级回退以[生产部署与恢复运行手册](./生产部署与恢复运行手册.md)为执行清单；工作流存在不等于门禁已经通过，必须保留对应版本的实际运行结果和例外记录。

## 4. 兼容与支持

`0.x` 不承诺长期兼容或维护窗口。只有更新日志明确标记的稳定版本才进入支持范围；在第一个稳定版本发布时，项目会同时公布具体的支持周期和升级跨度。数据库迁移不做自动向下回滚，部署者必须在升级前完成经过验证的备份，并按发布说明执行应用回退与数据恢复。

第三方扩展不得绕过 GuanSeq 业务 API 修改核心事实。外部 Broker、身份提供者、硬件和边缘组件的兼容范围以对应版本发布说明与现场验收证据为准。
