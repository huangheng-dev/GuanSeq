## 0. 设计立场（面向普通制造企业）

1. **月度期间，不做日历和季度**：普通制造企业按月记账和报税，月度粒度足够。不引入 4-4-5 周历、季度调整或自定义期间。
2. **关账只做写保护，不做结账计算**：关账后禁止把业务单据日期记入已关月份，但不生成损益结转、资产负债表或总账凭证——这些属于后续"总账凭证"切片。
3. **允许 ADMIN 重开**：关账不是不可逆的。发现错误时 ADMIN 可重开期间并补录，重开必须填写原因并留下完整审计。普通财务经理只能关账，不能重开。
4. **期间自动预生成**：迁移时预生成 2024–2027 共 48 个月度期间；之后系统自动在每年 12 月为下一年生成期间，不需要人工初始化。
5. **校验在后端服务层**：所有财务写操作在 `requireWriteRole()` 之后、业务逻辑之前检查单据日期所属期间是否为 `OPEN`。前端不做期间状态判断。

## 1. 业务目标

为已经过账的财务事实提供按月写保护，防止已关账月份被随意修改：

```text
财务单据（发票/收付款/红字/退款/反核销/成本结算）
→ 按单据业务日期确定所属年月
→ 查询该月期间状态
├─ OPEN   → 正常过账
└─ CLOSED → 拒绝，返回 409 PERIOD_CLOSED
```

关账操作本身：

```text
选择一个 OPEN 期间
→ 校验不存在未完成的在途操作
→ 标记为 CLOSED，记录关闭人和时间
→ 该月所有财务写入被阻止
```

重开操作：

```text
选择一个 CLOSED 期间
→ 仅 ADMIN 角色
→ 必须填写重开原因（≥4 字符）
→ 标记为 OPEN，记录重开人、时间和原因
→ 可再次写入该月
```

## 2. 事实所有权与模块协作

- `finance` 拥有会计期间记录、期间状态变更审计。
- 会计期间按 `tenant_organization_id` 隔离；每个组织独立维护自己的期间状态。
- 所有财务写操作（应收开票/收款/红字/退款/反核销、应付开票/付款/红字/退款/反核销、订单成本结算）在过账前检查期间状态。
- 销售、采购、生产、质量、仓储模块的业务操作（创建订单、发货、收货、报工等）**不受期间关账限制**——关账只冻结财务过账，不冻结业务操作。
- 工作中心成本费率变更和工时录入属于业务操作，不受期间关账限制（它们影响未来成本，不改动已过账财务事实）。

## 3. 期间对象

### 3.1 数据结构

每个会计期间包含：

- `fiscal_year`（INTEGER）：年份，如 2026
- `fiscal_period`（INTEGER）：月份 1–12
- `status`（VARCHAR）：`OPEN` 或 `CLOSED`
- `closed_at` / `closed_by`：关账时间和操作人
- `reopened_at` / `reopened_by` / `reopen_reason`：最近一次重开审计（可空）
- 标准字段：`id`、`tenant_organization_id`、`workspace_id`、`version`、`created_at`、`updated_at`

唯一约束：`(tenant_organization_id, fiscal_year, fiscal_period)`。

### 3.2 状态机

```text
OPEN ──close──→ CLOSED
  ↑                │
  └────reopen──────┘
```

- `OPEN`：允许该月的财务写入。
- `CLOSED`：拒绝该月的所有财务写入。
- 期间创建后默认为 `OPEN`，不需要"草稿"状态。
- 重开后状态回到 `OPEN`，数据库约束要求 `closed_at`/`closed_by` 为空（OPEN 期间无关闭审计）；`reopened_at`/`reopened_by`/`reopen_reason` 记录最近一次重开，历次关账与重开痕迹通过审计事件表保留（`finance_finance_events`）。

### 3.3 核心规则

- 期间按年月唯一标识，不允许同一组织存在重复年月。
- 关账前检查该月是否有 `status = 'DRAFT'` 的红字发票（当前红字发票直接 POSTED，无 DRAFT，因此此检查预留）。
- 关账操作本身不校验余额是否平衡（没有总账就没有余额概念）。
- 不强制必须按月顺序关账——可以先关 8 月再关 7 月（虽然实务上不推荐，但系统不阻止）。
- 日期早于 2024-01-01 或晚于 2027-12-31 的财务操作返回 422，提示"会计期间未初始化"。

## 4. 权限

| 操作 | ADMIN | FINANCE_MANAGER | 其他角色 |
|------|:-----:|:---------------:|:--------:|
| 查看期间列表/状态 | ✅ | ✅ | ✅ |
| 关账 | ✅ | ✅ | ❌ 403 |
| 重开期间 | ✅ | ❌ 403 | ❌ 403 |

重开权限比关账更严格，因为重开已关账月份意味着修改已经"定稿"的财务数据。

## 5. 受影响的写操作

```json

  "status": 409,
  "error": "PERIOD_CLOSED",

```

## 6. API 与数据事实

### 6.1 OpenAPI（新增路径）

- `GET /api/v1/finance/accounting-periods?year=2026`：列出指定年份的 12 个期间（不传 year 默认当前年）。
- `GET /api/v1/finance/accounting-periods/{id}`：期间详情。
- `POST /api/v1/finance/accounting-periods`：手动创建期间（正常情况自动生成，仅用于补录历史期间）。
- `POST /api/v1/finance/accounting-periods/{id}/close`：关账。
- `POST /api/v1/finance/accounting-periods/{id}/reopen`：重开，请求体含 `reason`。

写接口接受 `X-Request-Id`；`409` 幂等/期间冲突，`422` 日期超出范围或重复期间，`403` 无权限，`404` 不存在。

### 6.2 Flyway V29 摘要

新增表 `finance.accounting_periods`：

- `id UUID PRIMARY KEY`
- `tenant_organization_id UUID NOT NULL`
- `workspace_id UUID NOT NULL`
- `fiscal_year INTEGER NOT NULL`（CHECK 2020–2099）
- `fiscal_period INTEGER NOT NULL`（CHECK 1–12）
- `status VARCHAR(16) NOT NULL DEFAULT 'OPEN'`（CHECK OPEN/CLOSED）
- `closed_at TIMESTAMPTZ`、`closed_by UUID`
- `reopened_at TIMESTAMPTZ`、`reopened_by UUID`、`reopen_reason VARCHAR(500)`
- `request_id VARCHAR(200)`、`version BIGINT NOT NULL DEFAULT 0`
- `created_at`、`created_by`、`updated_at`、`updated_by`
- `UNIQUE (tenant_organization_id, fiscal_year, fiscal_period)`

种子数据：为开发租户（`00000000-0000-4000-8000-000000000001`）生成 2024–2027 共 48 条 OPEN 期间。

### 6.3 前端入口

- `/finance/accounting-periods`：会计期间管理页面。
- 按年分组展示 12 个月，每月显示状态标签（开放/已关账）、关账时间、操作按钮。
- 关账按钮：FINANCE_MANAGER 和 ADMIN 可见，点击后二次确认。
- 重开按钮：仅 ADMIN 可见，点击后必须填写原因。
- 当用户在应收/应付台账提交单据遇 409 PERIOD_CLOSED 时，弹窗提示"该单据日期所在期间已关账，请联系管理员重开或修改日期"。

## 7. 自动生成下一年期间

采用最简方案：在 `AccountingPeriodApplicationService` 中增加 `ensureNextYearPeriods(tenantId, workspaceId)` 方法，在每年第一次查询期间列表时检查下一年是否已生成，若无则批量插入 12 条 OPEN 期间。此方法是幂等的。

不使用定时任务或调度器——普通制造企业不需要在精确时间点自动切换期间，由用户第一次访问时触发即可。

## 8. 失败与并发语义

- 无权限：`403`。
- 期间已关账：`409 PERIOD_CLOSED`，响应体含期间标识。
- 重复期间（同年月已存在）：`422`。
- 日期超出预生成范围：`422`，提示"会计期间未初始化"。
- 乐观锁冲突（并发关账/重开）：`409`。
- 重开原因缺失或少于 4 字符：`422`。
- 幂等：关账和重开使用 `X-Request-Id`，重复请求返回当前状态而非报错。
- 期间查询本身不受关账影响。

## 9. 明确不在本切片

- 总账凭证、科目余额、试算平衡、损益结转、资产负债表。
- 年度关账（12 月关账不自动结转本年利润）。
- 多账簿（税务账、管理账）、多准则。
- 预算控制、费用报销。
- 工作中心成本费率和工时录入的期间冻结（它们是业务事实，不是财务过账）。
- 关账前的校验工作流（如折旧计提、暂估冲回、汇兑损益）——这些在相关切片交付后再加入关账检查清单。
