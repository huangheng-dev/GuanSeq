# 业务切片：采购收货与来料检验

> 状态：已实现并通过自动化验证  
> 范围日期：2026-08-20

## 1. 业务目标

把已下达采购订单接入第一条主闭环：仓库登记到货后，需要检验的物料自动进入 IQC 待检；检验合格数量进入合格库存，不合格数量进入不合格/隔离库存，并回写采购订单行已收数量。库存可继续被生产备料领用。

## 2. 模块所有权

- 采购模块拥有采购收货单、收货行、收货事件，以及采购订单行 `received_quantity` 的回写。
- 质量模块拥有检验任务、检验判定和检验事件。采购模块不能直接写质量表。
- 仓储模块拥有库存余额、库存流水和入库/转状态事务。采购模块不能直接写库存表。
- 主数据模块提供物料“是否需要来料检验”属性。

## 3. 对象与状态

### 采购收货单

- 编号：`PR-yyyyMMdd-xxxxxx`
- 状态：
  - `PENDING_INSPECTION`：至少一行仍在待检。
  - `PARTIALLY_RECEIVED`：无待检，但存在合格与不合格混合结果。
  - `RECEIVED`：所有收货行均已合格入库或免检入库。
  - `REJECTED_CLOSED`：所有收货行均不合格关闭。

### 采购收货行

- 状态：
  - `PENDING_INSPECTION`：已到货，已入待检库存，等待 IQC。
  - `RECEIVED`：免检直接入合格库存，或 IQC 全部合格。
  - `PARTIALLY_RECEIVED`：IQC 部分合格、部分不合格。
  - `REJECTED_CLOSED`：IQC 全部不合格。
- 采购订单行 `received_quantity` 只累计合格入库数量。

### 来料检验

- 复用 `quality.inspections`，扩展 `inspection_type = INCOMING`、`source_type = PURCHASE_RECEIPT_LINE`。
- `order_id/order_number` 表示采购订单，供应商字段随检验任务快照保存。
- 判定结果仍为 `PASSED`、`PARTIALLY_PASSED`、`FAILED`。

## 4. 权限与审计

- 登记采购收货允许角色：`WAREHOUSE_MANAGER`、`INVENTORY_CONTROLLER`、`PROCUREMENT_MANAGER`、`ADMIN`。
- 提交 IQC 结论允许角色：`QUALITY_INSPECTOR`、`QUALITY_MANAGER`、`ADMIN`。
- 所有创建与判定动作必须带 `X-Request-Id`，并记录操作者、请求编号、前后状态和数量证据。

## 5. 关键不变量

- 只有 `RELEASED` 采购订单可登记收货。
- 单行收货数量必须大于 0，且累计合格入库数量不能超过采购订单未收数量。
- 同一请求编号重复提交返回同一收货单/判定结果，不重复入库。
- 待检库存不能被生产备料领用；合格数量才进入 `AVAILABLE`。
- IQC 合格与不合格数量之和必须等于送检数量；存在不合格时必须填写缺陷说明。
- 乐观锁版本不匹配返回 409。

## 6. 异常与恢复

- 无权限返回 403。
- 采购订单、订单行、仓库、库位、物料不可见或状态不合法返回 404/422。
- 超量收货、重复行、数量合计不等于送检数量返回 422。
- 重复请求按幂等返回已有结果。
- 库存流水不可修改；若后续判定错误，通过反向事务/退货单处理，不在本切片内实现。

## 7. 非目标

- 不实现供应商退货单、采购发票/应付、复杂抽样方案、批号自动生成、跨收货单拼批/拆批。
- 不改变采购订单头状态；订单收齐程度通过行数量表达。
- 不把前端按钮作为权限边界，所有授权均在后端校验。
