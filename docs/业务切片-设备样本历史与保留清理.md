# 业务切片：设备样本历史与保留清理

> 状态：工程闭环完成；自动运行化待后续  
> 领域所有者：`equipment`  
> 前置切片：[可替换 Modbus TCP 只读采集](./业务切片-可替换Modbus只读采集.md)

## 业务目标

设备经理需要查看一条采集连接在有限时间窗口内的原始归一化样本，按点位和质量筛选；同时以工作区为边界设置原始样本保留天数，并在确认影响后人工清理已过期数据。维修、生产等当前工作区成员可以只读查看历史，但不能修改策略或删除证据。

## 业务对象与不变量

- 历史样本：继续由 `equipment.telemetry_samples` 持有，只允许当前工作区按连接、时间、点位和质量查询。
- 保留策略：每个工作区最多一条，范围为 7—3650 天，使用乐观版本避免静默覆盖；未显式配置时使用 30 天默认值。
- 保留事件：`POLICY_UPDATED` 和 `CLEANUP_COMPLETED` 为不可变事实，记录责任人、原因、请求编号、策略前后值、截止时间和删除数量。
- 清理动作：只删除当前租户/工作区中 `received_at < cutoff` 的样本；不会删除连接、点位、当前运行状态或连接事件，也不会修改人工设备状态。
- 请求幂等：相同工作区和请求编号的清理重试返回第一次结果，不重复产生删除副作用。

## 权限与恢复

- 当前工作区成员可以读取历史样本与当前保留策略。
- `ADMIN`、`MAINTENANCE_MANAGER` 可以修改策略和人工清理。
- 越权修改返回 403，版本冲突返回 409，跨工作区连接返回 404。
- 清理在单个数据库事务中执行；失败整体回滚，操作者可使用新请求编号重试。

## 验收条件

1. V42 是保留策略和不可变保留事件的数据库事实来源。
2. OpenAPI 固化历史分页、筛选、策略读取/修改和人工清理契约。
3. 原始历史查询时间窗口最大 31 天，默认最近 24 小时，避免无界扫描。
4. 清理严格遵守当前策略截止时间，并通过真实 PostgreSQL 测试工作区隔离、权限、并发与幂等。
5. 页面覆盖加载、空数据、筛选失败、无权限、版本冲突、操作中和成功结果。

## 非目标

- 不实现自动清理调度、多实例租约、失败通知或后台补偿任务。
- 不实现趋势聚合、报表导出、长期归档或时序数据库。
- 不改变协议适配、MQTT Broker 选择、报警、OEE 或远程控制边界。
