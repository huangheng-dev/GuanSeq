# 业务切片：预收预付（Advance Receipts & Payments）

> 文档状态：已实现并通过测试
> 适用阶段：C 阶段财务闭环增强
> 模块归属：finance（预收预付子域）
> 迁移：V32
> 前置切片：销售应收与收款核销、采购应付与付款核销、会计期间与关账

## 0. 设计立场

面向普通制造企业，解决两类常见场景：

1. **预收（Advance Receipt）**：客户先付款、后发货开票。款项到账时形成预收负债，后续应收开票时用预收余额冲抵应收款。
2. **预付（Advance Payment）**：企业先付款给供应商、后收货收票。款项付出时形成预付资产，后续应付开票时用预付余额冲抵应付款。

本切片采用**余额池模式**：预收/预付按客户/供应商维度维护余额池，开票时可从池中抵扣，不做逐笔订单绑定。这与现有应收应付核销模式一致，操作三步以内：

1. 登记预收/预付 → 选择客户/供应商，录入金额和日期。
2. 开票时抵扣 → 在现有应收/应付开票流程中自动提示可用预收/预付余额，可选择抵扣金额。
3. 退还预收/预付 → 客户取消订单或供应商无法供货时，将余额退回。

不做审批流、不做票据管理、不生成会计凭证（总账模块为后续规划）。预收/预付金额为**含税总额**（因为款项收付是含税的），与现有收款/付款表一致。

## 2. 状态机

### 预收单 / 预付单

```
OPEN（有余额）
  ├── PARTIALLY_USED（部分已抵扣或部分已退）
  └── CLOSED（余额为 0：全部抵扣完毕，或全部退还，或混合）
```

状态由实体根据已用金额自动重算，不允许手动设置。

### 核销记录（抵扣）

```
POSTED（已过账，不可变）
```

### 退款记录

```
POSTED（已过账，不可变）
```

## 3. 业务流程

### 3.1 登记预收

1. 选择客户（必须），录入金额（>0）、收款日期、备注。
2. 系统校验会计期间开放、角色（FINANCE_MANAGER/ADMIN）。
3. 幂等：同一 X-Request-Id 不重复创建。
4. 生成预收单号 `ADR-YYYYMMDD-NNN`。
5. 初始状态 OPEN，已用金额 0。

### 3.2 登记预付

1. 选择供应商（必须），录入金额（>0）、付款日期、备注。
2. 同预收校验流程。
3. 生成预付单号 `ADP-YYYYMMDD-NNN`。

### 3.3 开票时抵扣预收/预付

在应收/应付开票时（复用现有开票接口），传入可选的 `advanceApplication` 参数：

```json
{
  "advanceId": "uuid",
  "appliedAmount": 100.00
}
```

系统校验：
- 预收/预付单状态为 OPEN 或 PARTIALLY_USED
- 抵扣金额 ≤ 可用余额
- 抵扣金额 ≤ 发票总额
- 会计期间开放（用发票日期校验）

抵扣后：
- 预收/预付单的已用金额增加，状态重算
- 发票的已收/已付金额增加（与正常收款效果一致）
- 写一条核销记录（APPLICATION）
- 写事件

### 3.4 退还预收/预付

1. 选择预收/预付单，录入退款金额（>0 且 ≤ 可用余额）、退款日期、退款原因。
2. 系统校验期间开放。
3. 退款后预收/预付单余额减少，状态重算。
4. 写一条退款记录（REFUND），写事件。

### 3.5 查询

- 按类型（RECEIVABLE/PAYABLE）、客户/供应商、状态筛选，分页列表。
- 详情页显示基本信息 + 核销记录列表 + 退款记录列表。

## 4. 权限

| 操作 | 允许角色 |
|---|---|
| 查询预收预付 | 已认证用户 |
| 登记预收/预付 | ADMIN, FINANCE_MANAGER |

| 退还预收/预付 | ADMIN, FINANCE_MANAGER |

## 5. 幂等与并发

- 登记预收/预付：`X-Request-Id` → `request_id` 唯一约束 + 先查重后加锁。
- 业务锁：`pg_advisory_xact_lock(hashtextextended(key, 0))`，键格式 `advance:<tenant>:<type>:<customer/supplierId>`，防止同一客户/供应商并发操作余额。
- 抵扣和退款在同一事务内更新余额，乐观锁 `@Version` 防止丢失更新。
- 核销记录和退款记录不可变，不设 `@Version`。

## 8. 验收条件

1. 登记预收后，列表可见，状态 OPEN，可用余额 = 登记金额。
2. 应收开票时使用预收抵扣，发票已收金额增加，预收已用金额增加、状态变为 PARTIALLY_USED。
3. 预收余额全部抵扣后状态自动变为 CLOSED。
4. 退还预收后余额减少，状态正确重算。
5. 抵扣金额超过可用余额时返回 400。
6. 退还金额超过可用余额时返回 400。
7. 关账期间登记/抵扣/退还返回 409 PERIOD_CLOSED。
8. 同一 X-Request-Id 重复登记幂等返回已有单据。
9. 预付流程与预收对称（供应商开票时抵扣）。
10. 详情页显示完整的核销和退款历史。
