# 业务切片：设备现场接入验收闭环

> 适用阶段：设备与智能能力（阶段 D 最终收口切片）  
> 工程状态：已实现；部署现场状态必须由真实设备或用户真实 Broker 单独验收

## 目标与边界

本切片把“技术预检通过”与“现场正式接入完成”拆成两个事实。技术预检继续证明协议适配器能够只读连接、解析点位并返回结构化检查；现场验收单负责证明真实网络、安全边界、只读权限、断连恢复、容量和点位映射已经由责任人核实并获得审批。

仿真端点永远不能创建现场验收单。没有真实机器时，开源项目仍可完成可部署、可验证的工程闭环，但任何具体部署实例都保持“待现场验收”，不得以模拟数据、自动化测试或开发者勾选冒充真实上线。

## 业务对象与所有权

| 对象 | 数据所有者 | 核心事实 |
| --- | --- | --- |
| 采集连接 | equipment | 设备、协议、端点类型、只读点位和运行状态 |
| 技术预检事件 | equipment | 最新一次测试结果、证据层级、点位覆盖与安全提示 |
| 现场验收单 | equipment | 真实端点、六项核验、责任人、测试窗口、证据引用、状态和版本 |
| 现场验收事件 | equipment | 创建、修改、提交、批准、驳回的责任人、时间、请求编号和变更摘要 |

## 状态与权限

```text
DRAFT ──提交──> SUBMITTED ──批准──> APPROVED
  ▲                  │
  └────修改──── REJECTED <──驳回──┘
```

- 当前工作区有效成员可以查看验收上下文。
- `MAINTENANCE_MANAGER`、`ADMIN` 可以建立、修改和提交验收单。
- `PRODUCTION_MANAGER`、`ADMIN` 可以批准或驳回已经提交的验收单。
- 所有写操作使用请求编号幂等；修改和审批要求预期版本，冲突返回 `409`。
- 已批准验收单冻结；重新验收必须由后续明确变更流程触发，不允许覆盖历史批准事实。

## 提交与批准门禁

提交必须同时满足：

1. 端点类型是 `PHYSICAL_DEVICE` 或 `EXTERNAL_BROKER`，不是 `SIMULATOR`。
2. 最新一次结构化技术预检为 `FIELD_CANDIDATE_PRECHECK` 且成功。
3. 现场网络审批、安全边界验证、只读权限确认、断连恢复验证、容量验证、点位映射确认六项全部有真实证据。
4. 已填写现场责任人、有效测试窗口和证据引用。
5. 审批时最新技术预检仍然成功；若期间出现新的失败预检，必须先重新验证再批准。

草稿允许不完整，用于提前安排责任人与测试窗口；不完整草稿不能提交。界面明确提醒用户只在取得真实证据后勾选，不提供“一键全选”或默认通过。

## API 与数据事实

- `GET /api/v1/equipment/telemetry-field-acceptances/{connectionId}`：读取连接、最新技术预检和验收单上下文。
- `PUT /api/v1/equipment/telemetry-field-acceptances/{connectionId}`：创建或修改草稿。
- `POST /api/v1/equipment/telemetry-field-acceptances/{connectionId}/actions`：提交、批准或驳回。
- Flyway `V47` 是表结构事实来源；OpenAPI 是接口事实来源。
- 验收事件不可变，保留动作前后状态、原因、请求编号和检查摘要。

## 完成定义

- 数据迁移、领域状态机、权限、幂等、并发冲突、业务校验和不可变事件通过集成测试。
- 前端覆盖加载、空数据、仿真不适用、无权限、校验失败、接口失败、驳回返工和已批准冻结状态。
- 全量 lint、类型检查、自动化测试、后端打包和前端生产构建通过。
- 浏览器验证真实页面的草稿与受阻提交路径；没有真实机器时不制造 `APPROVED` 数据。
- 阶段 D 可标记为“工程闭环完成”；部署现场的真实设备验收仍是每个安装实例的上线前置条件，不计作开源代码缺陷。

## 不在本切片范围

- 远程写入或设备控制。
- 强制部署 EMQX 或任何指定 Broker。
- 用遥测自动生成 OEE、预测维护或跨厂时序分析；这些属于取得真实数据映射和容量证据后的可选增强，不是阶段 D 工程完成门槛。
