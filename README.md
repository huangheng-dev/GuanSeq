# GuanSeq（贯序）

贯序是面向普通制造企业的专业级一体化制造运营管理平台。产品统一规划 ERP、MES、WMS、QMS、PLM/PDM、APS、EAM、成本财务与数据分析能力。

> **发行状态：** 当前 `0.1.0-alpha.1` 是首个开源预览版，不是稳定生产发行版。仓库中的“正式后端”仅表示对应页面已接入受控业务 API，不等于整套系统或任何工厂实例已经生产就绪。发布范围、安装方式和已知限制见[预览版说明](./docs/releases/0.1.0-alpha.1.md)。

当前前端产品基线已经收口，后端工程位于 `guanseq-server`。组织与工作区、当前工作区成员与受控角色、客户和物料主数据、受控 BOM 与工艺路线版本、销售订单与独立需求、采购和生产订单、库存余额与不可变流水、物料提前期、MRP 净需求、MRP 建议审核转单，“生产报工 → 完工检验 → 合格品入库”，“生产备料/领料单生成 → 按 BOM 组件发料 → 库存扣减 → 已领组件退料 → 库存回补”，“生产订单下达 → 工序任务快照 → 开工/完工 → 实际人工登记审核 → 全部工序完成后报工”，采购收货与来料检验、采购移动扫码收货、生产移动扫码领料与报工、工序/本人/库存受控标签生成补打、仓储收货上架与库内扫码、库内调拨与单余额盘点、销售发货与成品出库、销售退货授权/待检收货/质量处置、采购退货授权/原批次出库/应付复核、销售应收开票与收款核销、采购应付发票与付款核销，订单收入、直接材料、实际人工、制造费用和毛利快照，以及设备台账、人工受控运行状态、点检/保养/维修、备件领退、运维成本、周期任务与人工核实 OEE/停机审核已经通过正式服务层接入真实 API；第一条制造与基础收付款主闭环已贯通，销售与采购反向实物流也已闭环，三个现场移动扫码切片、受控标签、仓储上架以及调拨盘点切片已落地。设备阶段已完成可替换的 Modbus TCP 与外部 MQTT 3.1.1 Broker 只读适配、统一点位/质量/样本/当前值、有限历史、受控保留清理、结构化技术预检、现场验收状态机，以及基础报警责任和人工核实 OEE 闭环。仿真端点不能生成现场验收；每个安装实例只有在真实端点预检和网络、安全、只读、恢复、容量、映射六项证据通过独立审批后才显示“现场已验收”。阶段 D 已完成开源工程闭环，但这不冒充任何工厂已经上线。其余业务页面仍通过统一数据服务访问 Mock 数据，后端将继续按制造业务优先级逐项替换 Mock Adapter。GuanSeq 不内置或强制 EMQX；自动 OEE 来源、OPC UA、可选边缘网关、远程控制和高级报警策略属于按需增强。

V52 已在既有生产领料和仓库库存事实之上完成生产领料移动扫码；V53 进一步完成“扫描工序/本人 → 开工 → 工序完工 → 最后工序报工 → 自动送检”，并固化精确任务、认证操作人和 `MOBILE_SCAN` 来源证据；V54 完成工序、本人和库存三类 Code 128B 标签的首次生成、受控补打、模板版本、稳定请求幂等和不可变责任证据；V55 完成“扫描待上架库存/目标库位 → 创建任务 → 完成/取消 → 补偿冲回”；V56 完成同仓正式库位调拨、账面快照、实盘录入、差异审批与补偿冲回，库存余额和不可变流水继续是唯一库存事实。`PREPARED` 只表示打印凭证已准备，不等于打印机成功出纸；库内扫码不依赖专用 PDA、相机 SDK、离线数据库或 Broker。

MRP 当前会冻结需求、库存、采购/生产计划接收与提前期快照，执行按日期净算、BOM 展开并形成采购、生产或委外建议；建议通过审核后可转为带来源追溯的采购或生产草稿单，不会自动下达。生产订单完工不允许直接改状态，工序任务未全部完成时不能报工，订单完工必须经过报工、质量判定和合格品入库形成审计证据。

## 当前范围

全部 236 条产品路径现在采用唯一成熟度分类，并在导航和页面首屏显示：

- **正式后端（50 条）**：通过 `src/services`/同源 BFF 接入 GuanSeq Server，后端权限、状态与审计事实生效。
- **Mock（174 条）**：保留异步、错误和状态语义的产品原型，只用于评审，不能作为正式业务记录。
- **规划（12 条）**：只表达边界、依赖和验收条件，尚未接入正式业务服务。

- 制造业一级、二级及按需三级左侧树形工作台
- 12 个一级栏目、123 个二级模块、101 个三级页面和 236 条独立产品路径
- 全路由专业页面目录、统一圆润表单/弹窗、分页、筛选、详情与业务状态
- 工作区切换、收藏与最近访问、全局搜索、通知中心和首页业务下钻
- 表单、刷新、查询、导出和规划反馈五类主操作语义
- 销售订单到生产交付的主流程总览
- 生产订单、产能负荷、质量异常和交付风险视图
- 加载、失败与数据适配边界的工程基线

## 本地运行

```bash
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

打开 `http://localhost:3000`。

## 后端运行

```powershell
cd guanseq-server
docker compose up -d --wait postgres
$env:SPRING_PROFILES_ACTIVE = "local"
.\mvnw.cmd spring-boot:run
```

后端运行在 `http://localhost:8080`，当前真实接口覆盖平台状态、工作区、当前工作区成员与受控角色、主数据、BOM 与工艺路线、销售订单、独立需求、采购/生产订单、库存余额与流水、MRP 净需求、采购收货与来料检验、生产备料与领退料、车间工序执行、实际人工工时、生产报工和完工检验、销售发货与成品出库、销售退货与质量处置、销售应收开票与收款核销、采购应付发票与付款核销、订单利润结算，以及设备台账、人工状态流转、点检、预防性保养、维修验收、维修备件领退、运维成本、周期维护模板、人工到期生成、逾期证据、Modbus/MQTT 只读采集、有限样本历史、保留策略、人工/受控自动清理、技术预检、现场接入验收、报警处置和人工核实 OEE/停机审批。前端通过同源 BFF 路由代理访问后端；本地开发凭据和正式访问令牌都不会进入浏览器代码。`local` Profile 默认使用互斥的开发身份；正式环境使用 `oidc` Profile，Next.js 通过授权码 + PKCE 建立加密 HttpOnly 会话，Spring Boot 独立验证 Bearer JWT 并映射贯序内部启用账号。缺少正式配置时受保护能力会关闭，不会退回开发账号。首次运行 Maven Wrapper 和 PostgreSQL 容器会下载对应的官方发行包。

## 浏览器发行门禁

完整 E2E 需要 Docker，并使用测试专用的 tmpfs PostgreSQL、开发身份和前后端生产镜像；不会连接或修改开发/生产数据库。首次在本机安装 Chromium 后执行：

```bash
pnpm e2e:install
pnpm e2e
```

门禁从空库执行 Flyway 与受控种子，串行验证登录、采购收货/IQC/采购退货、生产报工/完检/入库、销售发货/销售退货，以及浏览器接口失败后的无重复写入恢复。失败证据位于 `output/playwright/`；开发身份 E2E 不替代生产 OIDC、TLS 或具体安装实例验收。决策边界见 [ADR-0009](./docs/adr/0009-Playwright浏览器发行门禁.md)。

## 正式身份配置

正式部署需要在身份提供者注册保密客户端和回调地址，并让访问令牌包含后端配置的受众，以及可映射到贯序内部用户名的声明（默认 `preferred_username`）。前端设置 `GUANSEQ_SECURITY_MODE=oidc`，后端激活 `oidc` Profile；完整变量见 [.env.example](./.env.example) 和 [后端配置说明](./guanseq-server/README.md)。会话密钥必须由密钥管理系统提供，可用以下 PowerShell 命令生成初始值：

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

外部账号不会自动创建贯序用户，也不会把外部组或角色直接当作业务权限。空正式库通过默认关闭、只允许成功一次的初始化 API 建立首个公司、工厂、工作区和内部管理员；此后由当前工作区 `ADMIN` 在“系统管理 → 组织与用户 → 用户管理”开通内部账号、分配受控角色并停用或恢复成员关系。动态角色、组合权限、组织层级维护和 IdP 生命周期同步仍未接入。上线前可运行 `pnpm pilot:preflight` 检查 OIDC 配置与公开签名密钥，上线后可运行 `pnpm pilot:smoke` 对十三个只读主链路接口做带请求编号的验收。完整步骤、证据和回退边界见 [试点上线运行手册](./docs/试点上线运行手册.md)。

后端完整说明见 [guanseq-server/README.md](./guanseq-server/README.md)。

## 生产容器基线

生产环境使用根目录 [compose.production.yaml](./compose.production.yaml) 编排 `guanseq-web → guanseq-server → PostgreSQL`。两个应用镜像均以非 root 和只读根文件系统运行；数据库、后端不暴露宿主端口，Web 默认只绑定 `127.0.0.1:3000`，由安装环境已有的 HTTPS 入口代理。

```bash
pnpm production:preflight -- --env-file /etc/guanseq/production.env
docker compose --env-file /etc/guanseq/production.env -f compose.production.yaml build --pull
docker compose --env-file /etc/guanseq/production.env -f compose.production.yaml up -d --wait
```

配置、TLS、健康、升级回退、备份和隔离恢复演练见[生产部署与恢复运行手册](./docs/生产部署与恢复运行手册.md)。这套基线不等于高可用，也不代表任何具体工厂已经上线。
